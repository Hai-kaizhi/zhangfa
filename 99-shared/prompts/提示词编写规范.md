# 提示词编写规范

> 本文件是本仓库**所有提示词的编写宪法**。任何提示词的新建、修改、重构，都必须先对照本规范自检通过。
>
> 本规范以**六要素**为骨架——这是提示词最基本的组成单元，缺一不可。在六要素内部，保留了一些验证过有效的机制（边界声明单一可信源、质量检查表、去重铁律），作为约束的落地方式。

---

## 一、为什么以六要素为纲

一个优秀的提示词必须包含六个要素，缺一不可：

| 要素 | 作用 | 说明 |
|------|------|------|
| **任务（Task）** | 明确目标 | ⭐ 最核心。一句话说明要做什么，并贯穿全文驱动其余要素 |
| **角色（Role）** | 设定身份 | 让模型"成为"某个专家，影响知识调用范围和表达风格 |
| **上下文（Context）** | 提供背景 | 给出做决策所需的信息（上游输入、下游产出、承接原则） |
| **约束（Constraints）** | 划定边界 | 明确不能做什么、必须遵循什么；含核心原则、边界声明、思考过程 |
| **格式（Format）** | 规定输出 | 期望的输出结构（章节大纲、表格、Mermaid 等） |
| **示例（Examples）** | 对齐标准（可选） | 通过样例展示"好"的样子，比纯描述更有效。**可选手段**：如需参考范本，在上下文章一句话点明范本位置（学结构不学业务），不复制正文、不逐节贴占位符 |

**六要素之间的关系：任务贯穿全文，其余五要素围绕任务展开。**

```
        任务（Task）← 核心，贯穿全文
       /    |    \      \
    角色  上下文  约束   格式   示例
   (为谁) (背景) (边界) (产出) (对齐)
```

> 历史教训：早期提示词采用"八部分骨架"（角色/上下文/原则/边界/思考/输出/检查/输入），结构合规但"任务"被边缘化、"示例"被范本库冒充，导致"骨架合规、要素不全"。本规范以六要素纠正这一偏差。

---

## 二、标准结构：六要素（强制）

每个提示词**必须**包含以下六个部分，顺序固定，缺一不可。

```
# 提示词：{编号}-{名称}

> **层级**：项目级 / 大版本级 / 小版本级
> **位置**：{本文件相对路径}
> **产出文档**：《{产出文档名}》→ {产出存放路径}

---
## 任务
## 一、角色
## 二、上下文
## 三、约束（含核心原则、边界声明、思考过程、质量检查表）
## 四、格式（输出结构）
## 五、输入
```

### 各要素的职责

| 要素 | 职责 | 写法要求 |
|------|------|---------|
| **任务** | ⭐ 最核心，贯穿全文 | 一句话说清"要做什么、做到什么程度"。不只开头有，**在角色、约束、格式中都要呼应任务目标** |
| **角色** | 复合专家设定 | 2-4 行，配合任务——"为了完成X任务，你需要是Y专家" |
| **上下文** | 上游/下游/承接 | 上游输入来自哪、下游产出给谁、承接原则一句话 |
| **约束** | 边界 + 原则 + 思考 + 自检 | 四件套：1.边界声明(单一可信源) 2.核心原则 3.思考过程（推理链）4.质量检查表。这是约束的落地载体。**质量检查表作为约束章最后一个子章节，不独立成章** |
| **格式** | 输出结构 | 章节大纲 + 一句话说明（输出结构本身要写清楚）。如需范本参考，集中在上下文章一处提及，**不逐节贴占位符** |
| **输入** | 占位区 | `{在这里粘贴...}` |

> 注：要素编号"一、二、三..."体现展开顺序，但**任务**作为最核心要素，单独提在最前，不和其余要素混编号。

## 三、五条去重铁律（保留）

历史诊断发现提示词的结构崩坏，根源都是"重复"。以下五条铁律强制去重：

### 铁律 1：边界声明是单一可信源

**所有"本文档写什么 / 不写什么"的约束，只在约束章的"边界声明"里定义一次。** 他处只引用编号（如"见 B3"），禁止重抄约束内容。

### 铁律 2：质量检查表合并标准与检查

**删除独立的"输出质量要求"章节。** 质量标准与自检清单合并为一张表，一行 = 一条标准 = 一项检查。**同一检查项不在文件里出现两次。**

### 铁律 3：核心原则不重叠

灵魂原则（标 ⭐）排第一，次级原则不得是灵魂原则的缩写/细化。

判断：删除某条次级原则，灵魂原则仍完整成立 → 该次级原则冗余，删除。

### 铁律 4：示例不复制进正文

**示例内容不复制进提示词正文**（避免提示词臃肿、避免示例污染逻辑）。如需参考范本，在上下文章一句话点明位置即可，**不要在正文逐节贴占位符**。

### 铁律 5：格式只列大纲

格式章只列章节标题 + 一句话说明（输出结构本身要写清楚）。**不展开表格列头模板、不写填空示例**——让 AI 根据说明自行产出。

## 四、示例占位符规范（可选工具）

> ⚠️ **定位**：占位符是**可选的范本引用工具，不是强制机制**。范本参考应集中在一处（如上下文章一句话点明位置），**不要在格式章每节都贴占位符**——那会让提示词与范本强绑定，范本一动（改章节标题/路径）提示词就牵连大改，难维护。

### 语法（如需使用）

```
{{示例：[相对路径]#[章节锚点]}}
```

- **相对路径**：从本提示词文件出发，指向范本库中的文档
- **章节锚点**：精确定位到该文档的某个章节

### 锚点规则

锚点由章节标题生成：去掉 `##`/`###` 标记和编号前缀 → 空格转 `-` → 全小写 → 去标点。

| 章节标题 | 锚点 |
|---------|------|
| `## 2. 要解决的问题` | `#要解决的问题` |
| `## 5. 功能概览（按端 / 角色）` | `#功能概览` |

### 推荐用法

范本参考**集中在上下文章一句话**提及即可（参见各提示词的"二、上下文"），格式章只写纯输出结构。范本库的结构与挑选见 [`references/README.md`](./references/README.md)。

## 五、思考过程规范（推理链，非步骤清单）

约束章里的"思考过程"是**推理链**，不是工作清单。两者的区别：

| 步骤清单（错误） | 推理链（正确） |
|---------------|--------------|
| "先做 A，再做 B" | "从 A 推导出 B，因为..." |
| 讲"做什么" | 讲"怎么推" |
| 模型按部就班填空 | 模型真正在思考 |

每个提示词的思考过程必须：
1. **动笔前先做**（先推理后落笔）
2. **讲清推理逻辑**（每步如何从前一步推导）
3. **不写进最终文档**（内部推理）

> 思考过程的具体步数由各提示词按任务复杂度自定，不强制统一步数。

## 六、命名与符号约定

### 命名

- 子文件夹使用稳定的英文名称和层级编号，例如 `01-project`、`02-requirement-pool`、`03-versions/major`、`03-versions/minor`、`04-workspace`、`99-tools`
- 项目文档子目录按节点编号命名，与产出文件前缀一致：`00-inputs`（原始输入）、`01-project-docs/01-concept`、`02-prd`、`03-tech-doc`、`04A-dev-standards`、`04B-ui`、`04C-module-design`、`05-roadmap`；同阶段并行分支目录沿用 A/B/C 后缀
- 阶段型提示词统一使用 `<阶段编号>-提示词-<任务>.md`，例如 `02-提示词-PRD（项目）.md`、`01-提示词-PRD（大版本）.md`、`01-提示词-PRD（小版本）.md`
- 数字表示所在层级内的阶段；同一数字后的 `A/B/C/D` 表示同阶段分支。默认同号字母分支可以并行，明确写成 `03B1 → 03B2` 时按箭头串行
- 小版本开发阶段是特殊分支：`03A` 与 `03B1 → 03B2` 互斥，只选择一条开发策略；不能把相邻文件名误解为必须全部执行
- 产出文件按其**存放层级**的阅读顺序编号，不机械复制提示词编号。例如需求池 `01` 导入提示词生成的大版本快照为 `03-需求清单（大版本）.md`
- `README.md`、`需求池.md`、`版本注册表.md`、`变更台账.md`、`发布日志.md`、`术语表.md` 等长期入口和持续台账保持稳定名称，不加阶段编号
- 项目级端文档统一为 `02-功能详情-<端>.md`；开发规范统一为单文件 `04A-开发规范（项目）.md`（按栈分节），某栈规则超过一页时才拆分为 `04A-开发规范（<技术栈>）.md`；模块设计主文档为 `04C-00-模块总览.md`（拆分论证、总架构图、模块清单），各模块文档统一使用 `04C-<模块名>.md`
- 小版本工作区文档统一为 `01-PRD（小版本）.md`、`02-UI（小版本）.md`；发布时的完成需求记录统一为 `05-已完成需求.md`；测试不设独立文档节点，验收按小版本 PRD 验收锚执行
- `执行-` / `测试-` 表示特殊类型
- 配套规范文件加「配套-」前缀
- 本文件「提示词编写规范.md」是规范类文件，不加前缀，放 `prompts/` 根目录

### 业务命名承接纪律（所有提示词通用）

业务命名（主体、角色、端、业务对象、称谓、状态枚举、编码、落库名）以项目文档目录下的《术语表》为**单一可信源**。任何提示词凡生成或引用上述命名，必须遵守：

1. **输入包含术语表**：下游生成提示词的"输入"章须列《术语表》；执行时先读它再动笔。
2. **沿用不另起**：已登记命名一律逐字沿用，禁止同义改写（如把"管理端账号"写成"内部账号／员工账号"）；未登记但上游文档已在用的名称，沿用上游原文。
3. **定名即登记**：本层首次引入的新对象、新编码、新落库名、新字段名，定名即登记术语表（新增行），并在产出文档标注来源状态。
4. **命名推导纪律**：功能名是能力（动词短语），对象名是事物（名词）——对象命名不得从功能名截取拼凑；账号类对象按所属端命名（如管理端账号、顾客账号）。
5. **改名走变更**：确需改名时在术语表变更记录登记，并同步全部受影响文档，不得只改一处。

### 符号（允许 / 禁止）

| 允许 | 用途 |
|------|------|
| `⭐` | 标注灵魂原则 |
| `✅` / `❌` | 正反例表格 |
| `⚠️` `ℹ️` `💡` | 提示性标注 |
| `├` `└` `──` `│` | 树状图（限代码块内） |
| `→` | 箭头/流程 |
| `{{示例：...}}` | 示例占位符 |
| `- [ ]` | 复选框 |

| 禁止 | 替换为 |
|------|--------|
| `§`（分节符） | 纯文字"第X章" |
| `☐`（几何复选符） | `- [ ]` |
| `▶`（几何箭头） | `→` |

### Mermaid 图表语法规范（所有提示词通用）

提示词中凡要求产出 Mermaid 图表的，必须遵守以下语法约束，否则渲染报错：

| 图类型 | 语法约束 | 错误示范 → 正确 |
|--------|---------|---------------|
| **erDiagram** | ⭐ **中文实体名和关系说明必须用双引号包裹**（Mermaid 官方语法支持，未加引号的中文会报错）。英文实体名可不加引号 | `"会员" \|\|--o{ "订单" : "下单"` ✅；`会员 \|\|--o{ 订单 : 下单` ❌（报错） |
| **flowchart 边标签** | ⭐ **统一用 `|标签|` 写法**，兼容性最好，支持中文和任意标点 | `E -- 否,重试 --> D`（报错）→ `E -.->｜否，重试｜D`（正确） |
| **flowchart/stateDiagram 节点标签** | `A[标签]` 可中文、可 `<br/>` 换行，但避免未转义特殊字符 | 正常使用即可，复杂内容用 `<br/>` 分行 |

**erDiagram 中文实体名的正确写法**：

```
erDiagram
    "会员" ||--o{ "订单" : "下单"
    "订单" ||--|{ "订单项" : "包含"
    "会员" }o--o{ "角色" : "分配"
```

> 实体名和关系说明（冒号后的文字）都支持中文，只要用双引号包裹即可。这样比"英文实体名+对照表"更直观可读。

**flowchart 边标签的三种正确写法**（按官方推荐度排序）：

```
实线带文字：A -->|文字| B        ⭐ 推荐，支持中文+标点
虚线带文字：A -.->|文字| B       ⭐ 推荐，支持中文+标点
虚线不带文字：A -.-> B
```

> ⚠️ **避免用 `A -- 文字 --> B` 写法**——这种写法的标签不能含逗号、句号等标点（含中文逗号"，"），易报错。统一用 `|标签|` 写法可彻底避免此类问题，且支持任意中文和标点。

## 七、结构健康度检查（每次改完提示词，先过这个）

- [ ] **六要素齐全**？任务/角色/上下文/约束/格式/输入，一个不缺（示例不复制进正文，质量检查表作为约束子章节，两者都不独立成章）？
- [ ] **任务贯穿全文**？任务不只开头有，在角色、约束、格式中都呼应了任务目标？
- [ ] **示例未污染正文**？没有把示例内容复制进正文，也没有让示例独立成章？（范本参考集中在上下文章一句话提及即可）
- [ ] **质量检查表归位**？作为约束章最后一个子章节，没有独立成章？
- [ ] **边界声明是单一可信源**？每条约束只定义一次，他处只引用编号？
- [ ] **质量检查表无镜像重复**？同一条检查不出现两次？
- [ ] **核心原则无重叠**？删任何一条次级原则，灵魂原则仍完整？
- [ ] **格式只列大纲**？没有展开表格列头/填空模板？
- [ ] **思考过程是推理链**？讲"怎么推"不是"做什么"？
- [ ] **命名承接到位**？输入含术语表（或上游命名出处）、约束含"沿用不另起"、涉及新命名时有"定名即登记"要求（业务命名承接纪律）？
- [ ] **无禁止符号**？无 `§` `☐` `▶`？
