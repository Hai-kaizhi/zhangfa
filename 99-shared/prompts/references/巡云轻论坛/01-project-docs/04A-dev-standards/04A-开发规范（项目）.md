# 开发规范（项目）：巡云轻论坛

> 定位：本文把技术文档确定的工程基线沉淀为"代码怎么写"的通用工程约定——写机制不写业务、只写增量、单文件、底部增量区持续完善，对所有模块、所有人工与 AI 产出的代码同样适用，code review 有逐条依据。上游为模拟案例材料，模拟性质予以保留。

### 1.2 四类增量声明

本文只写四类内容：项目工程约定；与通识不同的取舍；技术决策的机制落地；无成文手册的业内共识。通识条目一律以上表引用，正文不复述；业务规则与业务实例不在本文出现。

### 1.3 等级与检验

规则默认强制（违反即 review 不通过）；〔建议〕为唯一例外等级；〔惯例默认〕表示按通行做法拍板、团队可调，一律行内标注、不设汇总章节。每条规则必须通过业务替换检验：把规则中出现的具体业务对象换成任何其他业务对象，规则仍然成立。

## 2. 通用工程约定

### 2.1 仓库与模块

- 后端单体应用一个仓库，按模块分包；模块划分以技术文档为准，本文不重列清单。
- 模块之间只允许通过对方暴露的接口调用，禁止跨模块直接读写对方的表。
- 模块依赖必须单向、不成环；新增跨模块调用前先确认方向。
- 前台页面工程与管理后台工程各自独立，不共享全局样式与全局变量。

### 2.2 全局数据共识

- 主键使用自增整数；对外编号独立成字段，由持久层统一生成、终身不变，禁止在业务代码中拼装编号。
- 时间以数据库时间类型存储，程序内部与对外输出使用同一时区口径；跨时区展示在展示层转换。〔惯例默认〕
- 需要回溯的实体采用软删除并保留删除时间；删除为业务终态的实体不物理删除。
- 统计类计数字段允许冗余存储，作为查询加速的缓存值，以事实记录为准并可校正。
- 可重复触发的写操作必须保证幂等（唯一约束或条件更新），重复请求不得产生重复数据或重复副作用。
- 状态与枚举取值一律使用《术语表》登记的枚举字面值，禁止自造近义词。

### 2.3 接口与错误

- 接口统一使用固定结构的返回包体，字段命名与分页参数全站一致。
- 错误码按模块分配号段、段内唯一；错误信息面向终端用户可读。
- 入参校验在接入层统一完成，业务层假定入参已校验。
- 异常在接入层兜底转换，不向前端暴露堆栈、SQL 与内部标识。
- 出参与日志中涉及个人信息的内容必须脱敏。

### 2.4 事务与一致性

- 涉及价值凭证或状态结算的多次写入必须在同一事务内完成，不允许出现半完成状态。
- 事务内不做外部调用；先提交落库，再执行外部动作，外部动作必须可重试。
- 并发更新使用条件更新（带原状态或版本号），更新影响行数为零时视为冲突并显式处理。
- 变动类数据必须留下流水记录；余额与流水同事务写入，余额可由流水重算。

### 2.5 协作

- 主分支保持可发布；功能在短分支开发后合并回主分支。〔惯例默认〕
- 提交信息按 Conventional Commits 书写，一次提交只做一件事。
- 任何变更必须经 review 通过后合并，review 逐条对照本规范。
- 版本号按语义化版本递增，发布记录与版本号一一对应。

## 3. 后端

- 分层职责：接入层负责鉴权与参数校验，应用层负责编排与事务边界，领域层承载规则，数据访问层负责持久化；上层不得绕过下层直连数据库。
- 模块分包：模块内按层组织，模块外只暴露接口与传输对象，实体不出模块边界。
- 鉴权与身份上下文：登录态由统一鉴权组件解析为身份上下文，业务代码只从上下文取当前身份，禁止从请求参数推断身份。〔惯例默认〕
- 能力点判定集中在一个判定组件，页面入口与接口校验使用同一套能力点。
- 留痕机制：审核、处置、结算类动作必须写入留痕记录（操作者、时间、结论、原因），并与业务变更处于同一事务。
- 定时任务与应用同进程部署；任务必须可重入，重复执行不产生重复副作用。
- 第三方对接统一经适配层调用，业务层不直接依赖具体服务商；密钥与地址从配置注入。
- 测试要求：核心规则的单元测试与关键闭环的集成测试随功能一并提交；测试不依赖真实外部服务。

## 4. 数据库

- 表名与字段名以《术语表》的落库命名契约为准：单数 snake_case，不另加模块前缀。
- 每张表必备审计字段：创建时间与更新时间。
- 类型原则：整数用整型、时间用日期时间类型、布尔用布尔类型；禁止用字符串承载结构化数据。
- 业务上唯一的组合必须建唯一索引；应用层的先查后写不能替代唯一索引。
- 结构变更一律通过版本化迁移脚本执行，脚本可重复执行，禁止直连环境手改结构。
- 列表查询必须分页并限制单页上限；请求链路内禁止无上限的全量统计。
- 索引按实际查询条件建立；写多读少的表控制索引数量，避免凭猜测加索引。

## 5. 前端

- 多工程机制：前台页面与管理后台分属不同工程，各自的构建、依赖与发布互不影响。
- 接口层收口：所有请求经统一接口层封装，业务代码不直接发起原始请求。
- 配置注入：接口地址、上传地址等环境相关配置由构建或部署注入，不硬编码在代码中。
- 权限点驱动：管理后台的菜单与按钮由能力点驱动，无权限时不渲染，接口侧仍二次校验。
- 数值处理：整数值在前端保持整数语义，不引入浮点参与计算与展示。
- 外部资源地址：图片等资源地址统一经地址拼接函数产出，不散落拼接字符串。
- 状态管理：跨页面共享状态集中管理，禁止用全局变量在页面之间传递。
- 前台脚本渐进增强：脚本不可用时页面仍可阅读与导航。〔惯例默认〕
- 模板输出默认转义；需渲染富文本的字段先经白名单净化再输出。

## 6. 部署与安全

- 反向代理作为唯一对外入口，静态资源与上传文件由代理直接服务。
- 对外一律 HTTPS，证书与代理配置纳入部署脚本管理。
- 数据库与内部服务不暴露公网端口，仅应用进程可访问。
- 密钥与敏感配置不入代码库、不入数据库，经环境变量或部署配置注入。
- 文件上传校验类型与大小白名单；上传文件存放在 Web 根之外，按不可执行内容处理。
- 数据库定期备份并验证可恢复；上传文件随同数据库一并备份。
- 与"明确不采用"清单联动：不引入清单中的技术；确需引入时先修订技术文档，再更新本规范。

## 7. 维护说明

- 增量流程：新约定先追加到"补充规范"区，一句一行并在句末括注来源与版本；同一主题积累成熟后整体并入对应章节，原追加条目移除。
- 追加条目同样执行本文的业务替换检验与双问检验，不通过的不入本文。
- 参照表链接失效或规范升版时，随维护一并更新。
- 本规范与技术文档冲突时以技术文档为准，并即时修订本规范。
