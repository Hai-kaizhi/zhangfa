# 巡云轻论坛 · UI 生图脚本

> 定位：生图提示词由 GPT 在对话中撰写，本文档只给资料清单、分步话术与风格锚定；主流程＝在同一 GPT 对话中使用 GPT-image（资料一次给足 → 产主页提示词 → 生成迭代 → 规划其余 → 批量生成 → 回填）。

| 资料 | 位置 | 必给或可选 |
|---|---|---|
| 概念文档（项目） | `01-project-docs/01-concept/01-概念文档（项目）.md` | 必给（调性来源） |

## 1. 第一步话术：让 GPT 产出主页（第一张图）的生图提示词

```text
你是资深 UI 设计师。我已提供《概念文档（项目）》《PRD（项目）》《术语表（项目）》三份资料（如另附技术文档一并参考）。

请先只分析、只输出一段生图提示词，不要生成图片。

一、产品与主端
- 产品：自建自营的社区论坛，包含「论坛讨论」与「悬赏问答」两个模块；前台为同一站点的电脑端网页与手机端网页（响应式），另有面向站内经营方与版主的管理后台。
- 第一张图＝主端主页：电脑端网页（画布 1440×900）的「板块与话题列表首页」。
- 气质：内容优先、简洁克制、可信可治理；界面文字全部为简体中文。

二、主页必须出现的元素（缺一不可）
- 顶部：站点名「巡云轻论坛」、板块导航、站内搜索入口、未登录状态下的「登录／注册」入口。
- 主体：板块列表（每个板块显示名称、简介、话题数）；板块下的话题列表（标题、作者昵称、评论数、点赞数、发布时间、标签胶囊）。
- 侧栏或次级区块：悬赏问答入口（显示「悬赏问答」与问题数）、待解决的高悬赏问题摘要（含悬赏积分标识）。
- 运营位：一条站长或运营人员发布的引导性内容位。
- 主页为未登录访客视角：列表中只出现已公开内容，不出现「待审核」「已驳回」等未公开状态标识（先审后发机制在作者「我的内容」视图与管理后台待审队列中体现，见第三步覆盖要求）。
- 不出现任何支付、红包、现金、会员卡类元素。

三、风格锚定（必须严格遵守）
- 主色（品牌蓝）#2A6CBE：顶部导航与主按钮、链接、选中态；按下态 #1F5497；浅底选中 #E8F1FB。
- 副色（激励琥珀）#C97A16：悬赏、积分、等级标识专用；浅底 #FAF1E3。
- 语义色：成功 #15803D（已通过、已采纳、已结算）、警示 #B45309（待审核、待处理）、危险 #B91C1C（驳回、删除、封号）、信息 #2A6CBE。
- 中性色：页面底 #F5F7FA、卡片 #FFFFFF、分割线 #E5E8EB、次级文字 #5B6570、正文 #1F2328、禁用 #9AA4AF。
- 字体：中文系统字体栈（苹方／思源黑体／微软雅黑），正文 14px、标题 16px～20px，行高 1.6。
- 形态：卡片圆角 8px、按钮与输入框圆角 6px、列表行高 44px、头像圆形、标签与状态用胶囊；状态一律「色块＋文字」双表达，不靠颜色单独承载语义。
- 通用禁止：不出现英文界面文字；不出现应用商店、手机 App 图标、小程序外壳；不出现真人照片、第三方品牌标识与真实机构名；不使用大面积渐变、霓虹色、玻璃拟态与 3D 元素；不使用夸张阴影；不出现倒计时、抢购、优惠券等电商化元素；不使用未成年人形象。

四、提示词结构要求
按「画面类型与画布尺寸 → 页面结构分区描述 → 每个分区的元素与文案示例 → 色彩与字体与形态 → 光影与质感 → 负向要求」的顺序组织；文案示例用简体中文并逐字取自《术语表（项目）》。

五、输出
只输出这段生图提示词，并在末尾用三行说明：你为谁设计、主端为什么是电脑端网页、这张图承担什么作用。
```

## 2. 第二步：生成并迭代主页

```text
按你刚才输出的提示词生成图片。生成后请逐项自检并告诉我：主页必须元素是否齐全、色值是否贴近主色 #2A6CBE 与激励色 #C97A16、是否有英文文字或禁止元素。
```

迭代方法：对不满意处逐条提出（如"把话题列表的标签胶囊改为描边样式""把搜索框左移、宽度加大"），每轮只改一到两处；满意的主页即全局风格基准，后续所有图片都以它的配色、圆角、密度与信息层级为准。

## 3. 第三步话术：规划其余图片并逐张撰写提示词

```text
主页已定稿，作为全局风格基准。请先只输出一份图片清单（不要生成图片），说明每张图的名称、所属端、作用，以及你建议的总数。

覆盖要求（必须满足）：
- 端：电脑端网页（1440×900）、手机端网页（390×844，网页形态而非 App 外壳）、管理后台（1440×900）；三个端都要覆盖。
- 必含功能域：
  1) 访客侧：板块与话题列表首页、话题详情（含评论、点赞收藏）、发帖编辑（含标签选用与可见条件设置）、站内搜索。
  2) 问答侧：问答列表、问题详情（含悬赏标识、答案列表与最佳答案高亮）、提问（含悬赏积分设置）、作答与采纳入口。
  3) 账号侧：登录注册、个人中心（我的内容〔含待审核／已驳回状态标识与驳回原因入口〕、我的积分与等级、我的收藏、我的关注与粉丝、我的私信与通知提醒、退出与注销）。
  4) 治理侧（管理后台）：待审队列（含通过／驳回操作与驳回原因填写）、举报处理、会员与内容管理（会员查询与维护、内容查询与维护）、板块与标签维护、运营内容维护、全站设置（审核策略、等级与积分规则）、管理端账号与角色授权。
- 关键信息点（各界面按需体现）：内容状态标识（待审核／已公开／已驳回／已删除）、悬赏积分与结算状态（待结算／已结算／已撤回）、会员等级与积分、驳回原因展示、举报人与被处置一方的通知提示、可见条件提示（等级／积分／回复可见）。
- 界面用词一律逐字取自《术语表（项目）》，不得自造近义词。

清单确认后，请逐张输出生图提示词（每次一张，结构同主页），我确认后再生成。
```

## 4. 第四步：批量生成

```text
按清单顺序逐张生成，每张生成后按同一标准自检：风格基准一致（配色、圆角、密度、信息层级）、界面文字全中文且与术语表一致、无禁止元素。有偏差时先修正再进入下一张。
```

单张迭代方法：只描述要改的地方与期望效果，一次一到两处，避免整张重写导致风格漂移。

## 5. 收尾：回填归档

图片全部满意后，按附 B 逐张登记；若对颜色做了微调，同步更新附 A 的色值与第 1 步话术中的色值，保持文档与产出同源。

## 附注 其他生图模型的差异

无对话记忆的模型（如即梦等单次生图工具）无法"先出提示词、再规划清单"：使用时把第 1 步与实际界面要点一次性写进单张提示词，先只出主页并定稿，再把主页图作为风格参考图连同第 3 步的覆盖要求逐张生图；附 A 与附 B 的用法不变。
