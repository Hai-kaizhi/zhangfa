# 交付说明：v0.7.0

> 定位：本版开发交付说明——承接《PRD（小版本）v0.7.0 运营复盘收官》认领条目（R108～R110）的开发交付与黑盒验收记录。本次为文档范本演练：不生成任何代码文件，实现位置按技术文档模块划分以模块级口径叙述；上游为模拟案例材料，模拟性质予以保留，证据均为文档范本演练的模拟证据。

## 1. 实现清单（条目｜实现位置｜实现要点）

| 条目 | 实现位置（模块级） | 实现要点（与 PRD 五块逐条对应） |
|---|---|---|
| R108 浏览量累计 ◆ | 运营与设置模块·浏览量累计服务（服务端）＋话题模块／问答与悬赏模块·内容详情路径挂接 | 触发：内容详情可见判定通过并返回后提交查看事件（内容标识＋访问身份）。交互：无人工界面（机制条目），系统链路按 PRD 4.1 流程图五步落地。字段：view_dedup（content_type／content_id／member_id／visitor_key／view_date，身份＋内容＋自然日联合唯一去重键）＋view_count（content_type＋content_id 联合唯一，累计次数只增不减、last_view_at 刷新）。规则：去重口径＝同一访问身份同一自然日只计一次（登录按 member_id、访客按 visitor_key）；仅已公开状态的话题与问题累计；作者不去除；身份缺失不累计（宁少计不多计）。异常：计数写入失败仅记录异常、不阻断内容展示，差异可由 view_dedup 重算校正 |
| R109 浏览量统计查看 | 管理后台·浏览量统计页（前端）＋运营与设置模块·统计查询接口（服务端） | 触发：站长或运营人员打开统计页并查询（能力点判定控制入口）。交互：筛选（内容类型话题／问题／全部默认全部；板块可选默认全部）→查询→列表五列（内容标题／内容类型胶囊／所属板块／累计浏览量／最近累计时间）按累计浏览量降序、同值按最近累计时间倒序、每页 20 条→行内「定位内容」。规则：仅呈现当前已公开内容；排序固定不可自定义；纯只读无写操作；无时间区间筛选（趋势分析未纳入）。异常：两种空态文案（「暂无浏览数据」／「当前筛选条件下暂无结果，可调整筛选」）；无权限者不显示入口、直接访问被拒 |
| R110 积分人工修正 ◆ | 成长模块·积分人工修正接口与同事务单元（服务端）＋管理后台·积分修正页（前端） | 触发：站长在管理后台积分修正页发起。交互：输入会员编号定位（显示昵称与当前余额）→填写修正数值（非零整数）与修正原因（必填 ≤200 字符）→提交并二次确认（回显会员、数值与修正后余额预览）→完成提示与新余额展示。字段：point_transaction 追加 admin_id／adjust_reason（仅人工修正流水携带，related 两字段为空），direction 随数值正负。规则：修正后余额不得为负；余额调整与修正流水同一本地事务；同表以 source_type＝人工修正区分；修正后即时重判等级（变更即时生效、不发通知）；不做服务端幂等（二次确认为防误操作手段）；仅站长可见入口。异常：六类拦截（编号未命中／数值为零或非整数／原因为空或超长／余额为负／事务失败回滚提示重试／非站长无权限），文案与 PRD 4.3 异常表逐字一致 |

范围外零实现核对：前台内容详情页无浏览量展示与任何界面变化；去重开关无配置界面；修正与等级变更不写通知提醒；流水查询界面沿用 v0.5.0 既有交付、本版未改动。

## 2. 验收锚自检（锚原文｜结果｜证据）

> 证据均为文档范本演练的模拟证据（界面叙述、接口叙述、模拟日志行），非真实系统运行记录。

**锚一（R108 浏览量累计 ◆）**——锚原文：「访客或会员打开一个已公开话题或问题的详情，该内容的浏览量加一；同一访问身份在同一自然日内再次打开同一内容不再累加；累计环节异常时内容详情仍正常展示」——**结果：通过**。证据：

- 首次查看：模拟日志 `2026-09-20 10:12:03 [view] first-hit content_type=话题 topic_no=1013 member_id=2001 view_date=2026-09-20 → view_count 56→57，last_view_at=10:12:03`；界面叙述：会员 2001 当日首次打开已公开话题 1013 详情，页面正常返回，统计页该话题累计浏览量显示 57。
- 重复查看不累加：模拟日志 `2026-09-20 15:40:11 [view] dedup-hit content_type=话题 topic_no=1013 member_id=2001 view_date=2026-09-20 → skip`；统计页数值仍为 57。
- 未登录访客身份：模拟日志 `2026-09-20 11:03:26 [view] first-hit content_type=问题 question_no=88 visitor_key=s-9f2c view_date=2026-09-20 → view_count 12→13`（访客按站点会话标识去重）。
- 累计失败不阻断：模拟日志 `2026-09-20 16:02:44 [view] count-write-failed content_type=话题 topic_no=1007 → content served，anomaly recorded`；界面叙述：该话题详情页内容完整展示，浏览量计数差异留待由 view_dedup 事实记录校正。
- 非统计对象拦截：模拟日志 `2026-09-20 09:58:07 [view] rejected content_type=评论 → 不累计`（评论与答案、待审核／已驳回／已删除内容均不进入计数链路）。

**锚二（R109 浏览量统计查看）**——锚原文：「站长或运营人员在管理后台浏览量统计页按内容类型（话题／问题）与板块筛选，列表按累计浏览量降序展示内容的累计浏览量与最近累计时间，可定位到具体内容」——**结果：通过**。证据：

- 列表与排序：界面叙述——站长登录管理后台打开「浏览量统计」页，内容类型选「全部」、板块选「全部」，点击「查询」；列表呈现五列（内容标题、内容类型胶囊、所属板块、累计浏览量、最近累计时间），首行「话题 1013｜话题｜站务与公告｜57｜2026-09-20 15:40」，其后按累计浏览量降序排列（57／41／33／12…），同值 33 的两行按最近累计时间倒序；分页器右下角显示每页 20 条；点击首行「定位内容」进入该话题的查看定位。
- 筛选：内容类型改选「问题」后查询，列表仅呈现问题类型内容（问题 88｜问题｜问答互助｜13｜2026-09-20 11:03 在列，话题行不再出现）；再叠加板块筛选「问答互助」后仅剩该板块问题。
- 空态：接口叙述——全站无数据时返回空列表，页面呈现「暂无浏览数据」与引导文案「内容被查看后自动累计」；筛选「问题＋站务与公告」（该组合无内容）时呈现「当前筛选条件下暂无结果，可调整筛选」。
- 权限拦截：界面叙述——仅持版主角色的账号登录后管理后台导航不出现「浏览量统计」入口；直接访问该地址返回无权限拒绝页。

**锚三（R110 积分人工修正 ◆）**——锚原文：「站长对某会员的积分账户填写非零修正数值与原因后提交，余额按数值调整且不为负，生成一条含原因与操作人的修正流水，必要时等级按新余额重判；修正后会员与经营方在流水查询中均能查到该条修正记录」——**结果：通过**。证据：

- 正常修正链路：界面叙述——站长在管理后台「积分修正」页输入会员编号 2001，页面显示「昵称：云间客｜当前积分余额：240」；填写修正数值「-170」、修正原因「重复发放行为积分，冲正多记部分」；二次确认弹窗回显「目标会员：云间客（2001）｜修正数值：-170｜修正后余额：70」，点击「确认修正」后页面提示「修正完成，当前余额：70」。模拟流水行：`point_transaction：account_id=2001 direction=支出 amount=170 source_type=人工修正 admin_id=1 adjust_reason=重复发放行为积分，冲正多记部分 related_type=— related_id=—`。
- 等级重判：模拟日志 `2026-09-20 17:21:05 [level] recheck member_id=2001 balance=70 → Lv2 初级会员（原 Lv3 中级会员），变更即时生效`（门槛 200，余额自 240 降至 70 跨过门槛：修正前 240 ∈ Lv3 区间〔200≤240＜500〕、修正后 70 ∈ Lv2 区间〔50≤70＜200〕，等级 Lv3→Lv2）；界面叙述：该会员前台等级展示随后显示 Lv2 与距下一等级积分差；未写任何通知提醒（口径沿用）。
- 两侧可查：界面叙述——会员 2001 在个人中心「我的积分与等级」流水查询中看到该条「人工修正｜支出 170｜2026-09-20」记录及原因；运营人员在经营方流水查询按会员 2001 与当日时间检索到同一行。
- 拦截态：界面叙述——数值填「0」提交提示「修正数值须为非零整数」；原因留空提交提示「修正原因为必填且不超过 200 字符」；对余额 70 的账户填「-80」提交提示「修正后余额不可为负」；会员编号填「9999」定位提示「该会员编号不存在」并留在输入态；以上拦截均保留已填内容。
- 同事务：模拟日志 `2026-09-20 17:24:40 [adjust] tx-commit member_id=2001 balance 240→70 transaction=同一本地事务（余额＋流水）`；构造写入失败时事务回滚，余额与流水均不变，页面提示「修正未完成，请重试」。

**自检结论**：三条验收锚 3/3 通过（证据为文档范本演练的模拟证据）；PRD 第 4 章各条目异常与拦截表所列场景均有对应模拟证据覆盖。
