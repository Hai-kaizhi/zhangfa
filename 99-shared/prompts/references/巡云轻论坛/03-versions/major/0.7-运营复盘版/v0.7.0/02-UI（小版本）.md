## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

核心界面＝管理后台「浏览量统计页」（本版信息量最大的操作面）。复制以下话术：

```text
你是资深 UI 设计师。我已提供《PRD（小版本）v0.7.0》《UI（项目）》脚本（含附 A 色板与令牌映射）与《术语表》三份资料。

请先只分析、只输出一段生图提示词，不要生成图片。

一、产品与本版范围
- 产品：自建自营的社区论坛「巡云轻论坛」；本版为收官小版本 v0.7.0 运营复盘收官，只交付管理后台的两类新界面：浏览量统计页与积分修正页（含其异常态与成功态）。
- 第一张图＝本版核心界面：管理后台（画布 1440×900）的「浏览量统计页」——站长与运营人员查看内容热度清单的操作面。
- 管理后台组件库为 Element Plus（项目层令牌映射已定）。

二、浏览量统计页必须出现的元素（缺一不可）
- 顶部：管理后台框架（站点名「巡云轻论坛」＋管理后台标识、主导航中可见「浏览量统计」入口高亮）。
- 筛选区：内容类型选择器（话题／问题／全部，默认全部）、板块选择器（可选，默认全部板块）、「查询」主按钮。
- 列表区五列：内容标题、内容类型（话题／问题胶囊标签）、所属板块、累计浏览量、最近累计时间；数据按累计浏览量降序呈现（首行数值最大）。
- 列表行操作：每行末尾「定位内容」文字按钮。
- 分页器：右下角，每页 20 条。
- 语义呈现：状态一律「色块＋文字」双表达；累计浏览量为纯数字计数，不出现任何趋势曲线、柱状图、折线图（统计报表未纳入本版）。
- 界面文字全部为简体中文，用词逐字取自《术语表》（如「话题」「问题」「板块」「站长」「运营人员」）。

三、风格锚定（必须严格遵守，与项目层主页基准同源）
- 主色（品牌蓝）#2A6CBE：顶部导航与主按钮（如「查询」）、链接、选中态；按下态 #1F5497；浅底选中 #E8F1FB。
- 语义色：成功 #15803D、警示 #B45309、危险 #B91C1C、信息 #2A6CBE。
- 中性色：页面底 #F5F7FA、卡片 #FFFFFF、分割线 #E5E8EB、次级文字 #5B6570、正文 #1F2328、禁用 #9AA4AF。
- 字体：中文系统字体栈（苹方／思源黑体／微软雅黑），正文 14px、标题 16px～20px，行高 1.6。
- 形态：卡片圆角 8px、按钮与输入框圆角 6px、列表行高 44px、标签与状态用胶囊；不靠颜色单独承载语义。
- 通用禁止：不出现英文界面文字；不出现应用商店、手机 App 图标、小程序外壳；不出现真人照片、第三方品牌标识与真实机构名；不使用大面积渐变、霓虹色、玻璃拟态与 3D 元素；不使用夸张阴影；不出现倒计时、抢购、优惠券等电商化元素；不使用未成年人形象。
- 本版附加禁止：不出现前台论坛界面（板块列表页、话题详情页、个人中心等——本版前台零变化）；不出现浏览量趋势图表；不出现积分商城、积分兑换、会员卡类元素。

四、提示词结构要求
按「画面类型与画布尺寸 → 页面结构分区描述 → 每个分区的元素与文案示例 → 色彩与字体与形态 → 光影与质感 → 负向要求」的顺序组织。

五、输出
只输出这段生图提示词，并在末尾用三行说明：你为谁设计、为什么核心界面是浏览量统计页、这张图承担什么作用。
```

## 2. 第二步：生成并迭代核心界面

```text
按你刚才输出的提示词生成图片。生成后请逐项自检并告诉我：统计页必须元素是否齐全（筛选区、五列列表、降序呈现、分页、定位按钮）、色值是否贴近主色 #2A6CBE、是否误出现趋势图表或前台界面、界面文字是否全中文。
```

迭代方法：对不满意处逐条提出（如"把累计浏览量列加粗并右对齐""筛选区改为卡片式一行排布"），每轮只改一到两处；满意的核心界面即本版基准，并与管理后台既有基准及项目层主页基准并检一次（配色、圆角、密度与信息层级同源，防跨版本风格漂移）。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

```text
核心界面已定稿，作为本版基准。请先只输出一份图片清单（不要生成图片），说明每张图的名称、所属端、作用，以及你建议的总数。

覆盖要求（必须满足，全部为管理后台 1440×900）：
- 端与主体：本版界面全部在管理后台，使用者为站长与运营人员；不生成任何前台界面。
- 认领条目对应：
  1) R109 浏览量统计查看：统计页列表态（已由核心界面定稿）；空态一「全站暂无浏览数据」（含一句引导文案：内容被查看后自动累计）；空态二「当前筛选条件下暂无结果，可调整筛选」（保留筛选区与空列表骨架）。
  2) R110 积分人工修正：积分修正页主态——会员编号输入与定位结果（显示会员昵称与当前积分余额）、修正数值输入（注明非零整数，正值入账、负值出账）、修正原因多行文本（必填，不超过 200 字符）、「提交修正」主按钮与修正后余额预览；二次确认弹窗（回显目标会员、修正数值与修正后余额，「确认修正」与「返回修改」）；拦截提示态——四类校验失败的表单反馈（该会员编号不存在／修正数值须为非零整数／修正原因为必填且不超过 200 字符／修正后余额不可为负，危险色提示条）；成功态——修正完成提示（成功色）与新余额展示。
  3) R108 浏览量累计：机制条目，无人工触发面——无界面、不生成图（前台内容详情页本版零变化）。
- 关键信息点：所有提示文案逐字取自上列口径；状态一律「色块＋文字」双表达；拦截用危险色 #B91C1C、成功用 #15803D。
- 界面用词一律逐字取自《术语表》，不得自造近义词。
- 本版附加禁止沿用第一步（无前台界面、无趋势图表、无积分商城类元素）。

清单确认后，请逐张输出生图提示词（每次一张，结构同核心界面），我确认后再生成。
```

## 4. 第四步：批量生成

```text
按清单顺序逐张生成，每张生成后按同一标准自检：与本版基准及项目层风格基准一致（配色、圆角、密度、信息层级）、界面文字全中文且与术语表一致、无禁止元素（含本版附加禁止）。有偏差时先修正再进入下一张。
```

单张迭代方法：只描述要改的地方与期望效果，一次一到两处，避免整张重写导致风格漂移。

## 附注 其他生图模型的差异

无对话记忆的模型（如即梦等单次生图工具）无法"先出提示词、再规划清单"：使用时把第 1 步与核心界面要点一次性写进单张提示词，先只出统计页并定稿，再把统计页图作为风格参考图连同第 3 步的覆盖要求逐张生图；附 A 与附 B 的用法不变。
