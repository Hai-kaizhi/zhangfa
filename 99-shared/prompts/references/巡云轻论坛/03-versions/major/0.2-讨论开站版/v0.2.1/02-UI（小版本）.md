## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

```text
你是资深 UI 设计师。我已提供《PRD（小版本）v0.2.1》《UI（项目）脚本》《术语表（项目）》三份资料。

请先只分析、只输出一段生图提示词，不要生成图片。

一、本版与核心界面
- 本版交付互动与账号治理：前台的点赞与收藏（对已公开话题与评论）、管理后台的违规处置面板（禁言／解除禁言／封号）；其余讨论闭环能力已随 v0.2.0 交付。
- 第一张图＝本版核心界面：管理后台（1440×900）的「违规处置面板」——本版信息量最大的操作面（会员定位＋禁言期限选择＋三类处置＋二次确认＋留痕入口）。
- 界面文字全部为简体中文，用词逐字取自《术语表（项目）》（会员账号、禁言、封号、正常、版主、处置原因）。

二、核心界面必须出现的元素（缺一不可）
- 顶部：站点后台标识「巡云轻论坛 管理后台」、当前登录账号（版主）、「个人设置」入口与「退出」。
- 会员定位区：来自待审队列条目或已公开内容作者处的入口示意（面包屑「待审队列 → 作者处置」），展示被处置会员昵称、编号与账号状态标签（正常〔绿〕／禁言〔棕黄〕／封号〔灰〕）。
- 禁言区：期限四选一（1 天／3 天／7 天／30 天，默认 7 天选中）、处置原因输入（≤200 字符，选填）、「执行禁言」主按钮。
- 解除禁言入口：对禁言中会员显示「解除禁言」按钮与禁言截止时间。
- 封号区：「封号」危险按钮；二次确认弹窗显示会员昵称、要求输入「封号」二字、确认按钮不可用态与可用态各示意一次。
- 留痕入口：处置记录入口按钮（本版只落痕迹不建查询面，按钮置灰并提示「记录留存，查询界面随后续版本」）。
- 异常态至少两处：对已封号会员禁言「该账号已封号，无需禁言」；对非禁言状态解除「该账号未处于禁言状态」。
- 不出现独立的会员搜索框（会员查询与维护随 0.6）。

三、风格锚定（必须严格遵守，沿用项目层基准，并与已发布各版界面同源）
- 主色（品牌蓝）#2A6CBE：顶栏、主按钮、链接、选中态；按下态 #1F5497；浅底 #E8F1FB。
- 语义色：成功 #15803D（正常）、警示 #B45309（禁言）、危险 #B91C1C（封号与破坏性操作）、信息 #2A6CBE。
- 中性色：页面底 #F5F7FA、卡片 #FFFFFF、分割线 #E5E8EB、次级文字 #5B6570、正文 #1F2328、禁用 #9AA4AF。
- 字体：中文系统字体栈（苹方／思源黑体／微软雅黑），正文 14px、标题 16～20px，行高 1.6。
- 形态：卡片圆角 8px、按钮与输入框圆角 6px、列表行高 44px；状态一律「色块＋文字」双表达。
- 通用禁止（项目层整段继承）：不出现英文界面文字；不出现应用商店、手机 App 图标、小程序外壳；不出现真人照片、第三方品牌标识与真实机构名；不使用大面积渐变、霓虹色、玻璃拟态与 3D 元素；不使用夸张阴影；不出现倒计时、抢购、优惠券等电商化元素；不使用未成年人形象。
- 本版附加禁止：不出现悬赏、积分、等级、私信、关注、举报、问答区、运营位（随后续版本）；不出现会员批量处置（未入池能力）；不出现支付、红包、现金、会员卡类元素；不出现会员搜索框。

四、提示词结构要求
按「画面类型与画布尺寸 → 页面结构分区描述 → 每个分区的元素与文案示例 → 色彩与字体与形态 → 光影与质感 → 负向要求」组织；文案示例用简体中文并逐字取自术语表与上述元素清单。

五、输出
只输出这段生图提示词，并在末尾三行说明：你为谁设计、为什么核心界面是违规处置面板、这张图承担什么作用。
```

## 2. 第二步：生成并迭代核心界面

```text
按你刚才输出的提示词生成图片。生成后逐项自检并告诉我：核心界面必须元素是否齐全、状态标签是否「色块＋文字」双表达、危险按钮是否用 #B91C1C、主色是否贴近 #2A6CBE、是否有英文文字或本版禁止元素（悬赏积分／会员搜索框等）。
```

迭代方法：逐条提出修改（一次一到两处），满意的核心界面即本版基准；随后与项目层主页基准图并检一次——配色密度、圆角、信息层级与主页一致才算通过（防跨版本风格漂移），不一致处以项目层主页为准修正。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

```text
核心界面已定稿，作为本版基准。请先只输出一份图片清单（不要生成图片），说明每张图的名称、所属端、作用，以及你建议的总数。

覆盖要求（必须满足，来源＝本版 PRD 认领条目 R46～R53）：
- 端与画布：电脑端网页（1440×900）、手机端网页（390×844，网页形态而非 App 外壳）、管理后台（1440×900）。
- 前台界面（互动）：
  1) 话题详情互动位：话题与评论的点赞按钮＋计数（点赞前后两态，计数即时加一／减一）；未登录点击「登录后参与互动」引导态。
  2) 收藏操作位：收藏前后两态（收藏成功提示、操作位变为已收藏）；重复收藏幂等提示「已收藏」；取消收藏后恢复可收藏。
  3) 手机端话题详情（390×844）：点赞与收藏的手机形态。
  4) 拦截与异常态：被禁言账号提交评论「账号被禁言，暂不能发言」；内容已删除时点赞「内容不存在或不可见」。
- 管理后台界面（治理）：
  5) 处置面板（核心界面已定稿，作为基准）。
  6) 处置效果核对：被禁言会员发言被拒的界面示意（前台视角）；封号账号登录被拒「账号不可用」。
  7) 通知效果：会员通知列表新增类型（禁言／解除禁言／封号）的条目示意（前台通知入口）。
- 机制条目（无界面、不生成图）：点赞唯一约束幂等（效果＝计数不重复）；点赞计数冗余校正（效果＝计数与关系一致）；期满自动解除（定时任务，效果＝状态回正常）；处置留痕（效果＝留痕入口置灰说明）。
- 界面文字一律逐字取自《术语表（项目）》与本版 PRD 的提示文案，不得自造近义词；通用禁止与本版附加禁止同第一步。

清单确认后，请逐张输出生图提示词（每次一张，结构同核心界面），我确认后再生成。
```

## 4. 第四步：批量生成

```text
按清单顺序逐张生成，每张生成后按同一标准自检：与本版基准一致（配色、圆角、密度、信息层级）、界面文字全中文且与术语表及 PRD 文案一致、无本版禁止元素。有偏差先修正再进入下一张。
```

单张迭代方法：只描述要改的地方与期望效果，一次一到两处，避免整张重写导致风格漂移。

## 5. 收尾：回填归档

图片全部满意后按附 B 逐张登记；如对颜色做了微调，不得在本版定新值——须同步修改项目层脚本附 A（唯一来源）后，本版话术与附 A 复本随之更新。

## 附注 其他生图模型的差异

无对话记忆的模型（如即梦等单次生图工具）无法"先出提示词、再规划清单"：使用时把第 1 步与目标界面要点一次性写进单张提示词，先生成核心界面并与项目层主页基准并检定稿，再逐张生图；附 A 与附 B 用法不变。
