## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

```text
你是资深 UI 设计师。我已提供《PRD（小版本）v0.2.0》《UI（项目）脚本》《术语表（项目）》三份资料。

请先只分析、只输出一段生图提示词，不要生成图片。

一、本版与核心界面
- 本版交付讨论闭环：前台浏览搜索、发帖与评论、先审后发、结果通知，另有管理后台的待审队列与敏感词词表；点赞收藏与账号处置随下一小版本。
- 第一张图＝本版核心界面：电脑端网页（1440×900）的「话题详情页」——本版信息量最大的操作面（正文＋标签＋可见条件提示＋评论列表＋发表评论框＋状态反馈）。
- 界面文字全部为简体中文，用词逐字取自《术语表（项目）》（话题、评论、板块、标签、待审核、已公开、已驳回、审核中、会员、访客、版主）。

二、核心界面必须出现的元素（缺一不可）
- 顶部：站点名（取自站点信息配置）、板块导航、站内搜索入口、登录／注册入口或已登录会员昵称、通知入口（铃铛占位）。
- 话题区：标题、作者昵称与头像、发布时间、标签胶囊（1～5 个）、正文；顶部状态标注位（本图按已公开展示）。
- 评论列表：按时间正序的两级层级（评论与缩进回复）、每条含作者、时间与内容；含一条「该评论已删除」占位。
- 发表评论框：多行输入与「发表评论」按钮，下方提示「提交后待审核，通过后公开」。
- 可见条件提示态（并排示意一次）：一条「回复后可见」的条件提示卡（不显示正文）。
- 空态：评论列表空态「暂无评论，沙发等你来」。
- 异常态至少两处：评论越界「评论需 2～1000 个字符」；未登录点击评论「登录后参与讨论」引导。
- 不出现点赞、收藏图标或按钮（随下一小版本），不出现悬赏、积分、等级、私信、关注、举报、问答区与运营位元素。

三、风格锚定（必须严格遵守，沿用项目层基准）
- 主色（品牌蓝）#2A6CBE：导航、主按钮、链接、选中态；按下态 #1F5497；浅底 #E8F1FB。
- 语义色：成功 #15803D（已公开）、警示 #B45309（待审核、审核中）、危险 #B91C1C（已驳回、删除）、信息 #2A6CBE。
- 中性色：页面底 #F5F7FA、卡片 #FFFFFF、分割线 #E5E8EB、次级文字 #5B6570、正文 #1F2328、禁用 #9AA4AF。
- 字体：中文系统字体栈（苹方／思源黑体／微软雅黑），正文 14px、标题 16～20px，行高 1.6。
- 形态：卡片圆角 8px、按钮与输入框圆角 6px、列表行高 44px、头像圆形、标签与状态用胶囊；状态一律「色块＋文字」双表达。
- 通用禁止（项目层整段继承）：不出现英文界面文字；不出现应用商店、手机 App 图标、小程序外壳；不出现真人照片、第三方品牌标识与真实机构名；不使用大面积渐变、霓虹色、玻璃拟态与 3D 元素；不使用夸张阴影；不出现倒计时、抢购、优惠券等电商化元素；不使用未成年人形象。
- 本版附加禁止：不出现点赞、收藏图标与按钮（随 v0.2.1）；不出现悬赏、积分、等级、私信、关注、举报、问答区、运营位（随后续版本）；不出现支付、红包、现金、会员卡类元素；访客视角不出现「待审核」「已驳回」等未公开状态标识（治理机制在作者我的内容视图与管理后台体现）。

四、提示词结构要求
按「画面类型与画布尺寸 → 页面结构分区描述 → 每个分区的元素与文案示例 → 色彩与字体与形态 → 光影与质感 → 负向要求」组织；文案示例用简体中文并逐字取自术语表与上述元素清单。

五、输出
只输出这段生图提示词，并在末尾三行说明：你为谁设计、为什么核心界面是话题详情页、这张图承担什么作用。
```

## 2. 第二步：生成并迭代核心界面

```text
按你刚才输出的提示词生成图片。生成后逐项自检并告诉我：核心界面必须元素是否齐全、状态与条件提示是否「色块＋文字」双表达、主色是否贴近 #2A6CBE、是否有英文文字或本版禁止元素（点赞收藏图标／悬赏积分／运营位等）。
```

迭代方法：逐条提出修改（一次一到两处），满意的核心界面即本版基准；随后与项目层主页基准图并检一次——配色密度、圆角、信息层级与主页一致才算通过（防跨版本风格漂移），不一致处以项目层主页为准修正。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

```text
核心界面已定稿，作为本版基准。请先只输出一份图片清单（不要生成图片），说明每张图的名称、所属端、作用，以及你建议的总数。

覆盖要求（必须满足，来源＝本版 PRD 认领条目 R24～R45）：
- 端与画布：电脑端网页（1440×900）、手机端网页（390×844，网页形态而非 App 外壳）、管理后台（1440×900）。
- 前台界面：
  1) 首页板块导航：启用板块名称与说明卡片；空态「暂无板块，请稍后再来」；停用板块不出现。
  2) 板块内容列表：已公开话题按发布时间倒序（标题、作者、评论数、点赞数〔本版显示 0 的展示位〕、标签胶囊）；空态「本板块暂无话题」。
  3) 标签聚合页：按标签查看同类已公开话题；空态「该标签暂无话题」。
  4) 话题搜索页：搜索框与结果列表（只含已公开话题）；空态「未找到相关话题」；关键词为空提示「请输入关键词」。
  5) 发帖编辑页：标题（2～100 字符）、正文、标签选择（1～5 个）、可见条件四选一（公开／回复可见／等级可见〔标注将于后续版本生效〕／积分可见〔标注将于后续版本生效〕）；异常态「标题需 2～100 个字符」「最多选用 5 个标签」；提交成功态「已提交，待审核」。
  6) 我的内容视图：我的话题列表含状态标签（待审核〔棕黄〕／已公开〔绿〕／已驳回〔红〕／审核中标注）；已驳回详情显示驳回原因与「重新提交」按钮。
  7) 删除确认：话题删除「删除后话题与评论不可恢复」；评论删除确认。
  8) 通知列表：按时间倒序（类型：审核通过／审核驳回／评论公开）、点击进入对应内容；空态「暂无通知」；关联内容已删除的跳转态「内容不存在或不可见」。
  9) 手机端网页适配：首页与话题详情的手机形态（390×844）。
  10) 空态与异常：停用板块直接访问「该板块已停用」；禁言账号提交评论拦截态「账号被禁言，暂不能发言」；未登录参与引导「登录后参与讨论」。
- 管理后台界面：
  11) 待审队列：按内容类型（话题／评论）与时间筛选、命中敏感词条目置顶带命中标记、分页；空态「暂无待审内容」。
  12) 审核通过与驳回：驳回原因填写（2～200 字符）与行内校验；处理后队列移除。
  13) 敏感词词表：列表（词条、启停）、新增与编辑表单、删除确认；异常态「词条已存在」「词条需 2～30 个字符」。
- 机制条目（无界面、不生成图）：命中校验（效果＝队列命中标记）；写入通知提醒（效果＝通知列表）；可见判定（效果＝条件提示卡）；评论计数（效果＝列表数字）。
- 界面文字一律逐字取自《术语表（项目）》与本版 PRD 的提示文案，不得自造近义词；通用禁止与本版附加禁止同第一步。

清单确认后，请逐张输出生图提示词（每次一张，结构同核心界面），我确认后再生成。
```

## 4. 第四步：批量生成

```text
按清单顺序逐张生成，每张生成后按同一标准自检：与本版基准一致（配色、圆角、密度、信息层级）、界面文字全中文且与术语表及 PRD 文案一致、无本版禁止元素。有偏差先修正再进入下一张。
```

单张迭代方法：只描述要改的地方与期望效果，一次一到两处，避免整张重写导致风格漂移。

## 5. 收尾：回填归档

图片全部满意后按附 B 逐张登记；如对颜色做了微调，不得在本版定新值——须同步修改项目层脚本附 A（唯一来源）后，本版话术与附 A 复本随之更新。

## 附注 其他生图模型的差异

无对话记忆的模型（如即梦等单次生图工具）无法"先出提示词、再规划清单"：使用时把第 1 步与目标界面要点一次性写进单张提示词，先生成核心界面并与项目层主页基准并检定稿，再逐张生图；附 A 与附 B 用法不变。
