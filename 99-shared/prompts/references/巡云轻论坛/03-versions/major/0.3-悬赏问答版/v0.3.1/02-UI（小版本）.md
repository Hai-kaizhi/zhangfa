## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

```text
你是资深 UI 设计师。我已提供《PRD（小版本）v0.3.1》《UI（项目）生图脚本》《术语表（项目）》三份资料（如另附项目 PRD 与技术文档一并参考）。

请先只分析、只输出一段生图提示词，不要生成图片。

一、产品与主端
- 产品：自建自营的社区论坛「巡云轻论坛」，本版为问答与悬赏闭环版本（提问、悬赏、作答、采纳结算、到期退回、问答浏览与搜索）。
- 第一张图＝本版核心界面：电脑端网页（画布 1440×900）的「问题详情页」——本版信息量最大的操作面，聚合问题、悬赏、答案与采纳入口。
- 界面文字全部为简体中文，用词逐字取自《术语表（项目）》。

二、核心界面必须出现的元素（缺一不可）
- 顶部：站点名「巡云轻论坛」、板块导航、站内搜索入口、登录状态。
- 问题区：问题标题、正文、追加补充块（标注追加时间）、提问人昵称与头像、发布时间；本问题状态标签「待解答」（警示色语义、色块＋文字双表达）。
- 悬赏区：悬赏积分标识「悬赏 100 积分」（激励琥珀色与浅底）、悬赏状态「待结算」。
- 答案区：按时间展示的已公开答案列表（作答人昵称与头像、正文、发布时间）；列表上方作答输入框与「提交答案」按钮（未登录时为「登录后作答」引导）。
- 提问人视角操作：每条已公开答案带「采纳为最佳答案」按钮（主色）；页面右上「关闭问题」入口（危险色文字链，附终态提示）。
- 状态双表达：悬赏与积分用激励琥珀、状态标签一律「色块＋文字」，不靠颜色单独承载语义。
- 不出现任何支付、红包、现金、会员卡类元素；不出现「待审核」「已驳回」内容状态（先审后发状态只在作者侧反馈与管理后台体现，见第三步覆盖要求）。

三、风格锚定（必须严格遵守，引自项目层脚本）
- 主色（品牌蓝）#2A6CBE：顶部导航与主按钮、链接、选中态；按下态 #1F5497；浅底选中 #E8F1FB。
- 副色（激励琥珀）#C97A16：悬赏、积分、等级标识专用；浅底 #FAF1E3。
- 语义色：成功 #15803D（已通过、已采纳、已结算）、警示 #B45309（待审核、待处理）、危险 #B91C1C（驳回、删除、封号）、信息 #2A6CBE。
- 中性色：页面底 #F5F7FA、卡片 #FFFFFF、分割线 #E5E8EB、次级文字 #5B6570、正文 #1F2328、禁用 #9AA4AF。
- 字体：中文系统字体栈（苹方／思源黑体／微软雅黑），正文 14px、标题 16px～20px，行高 1.6。
- 形态：卡片圆角 8px、按钮与输入框圆角 6px、列表行高 44px、头像圆形、标签与状态用胶囊；状态一律「色块＋文字」双表达，不靠颜色单独承载语义。
- 通用禁止：不出现英文界面文字；不出现应用商店、手机 App 图标、小程序外壳；不出现真人照片、第三方品牌标识与真实机构名；不使用大面积渐变、霓虹色、玻璃拟态与 3D 元素；不使用夸张阴影；不出现倒计时、抢购、优惠券等电商化元素；不使用未成年人形象。

四、本版附加禁止
- 不出现话题发表与评论界面的任何改动（沿用既有界面）；不出现个人中心的积分与等级页、流水页（随 0.5）；不出现举报与治理侧删除入口（随 0.6）；不出现积分人工修正入口（随 0.7）；不出现收藏问题或收藏答案的按钮（本版不做问答收藏）。

五、提示词结构要求
按「画面类型与画布尺寸 → 页面结构分区描述 → 每个分区的元素与文案示例 → 色彩与字体与形态 → 光影与质感 → 负向要求」的顺序组织；文案示例用简体中文并逐字取自《术语表（项目）》与本话术。

六、输出
只输出这段生图提示词，并在末尾用三行说明：你为谁设计、为什么核心界面是问题详情页、这张图承担什么作用。
```

## 2. 第二步：生成并迭代核心界面

```text
按你刚才输出的提示词生成图片。生成后请逐项自检并告诉我：必须元素是否齐全（问题区、悬赏区、答案列表与作答框、采纳按钮、关闭入口、待解答与待结算状态双表达）、色值是否贴近主色 #2A6CBE 与激励琥珀 #C97A16、是否有英文文字或禁止元素。
```

迭代方法：对不满意处逐条提出（如「把悬赏区改为问题标题右侧的胶囊标识」「把采纳按钮改为文字链＋确认弹层示意」），每轮只改一到两处；满意后即本版基准，并与项目层脚本生成的主页基准并检一次——核对配色、圆角、密度与信息层级同源，防跨版本风格漂移。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

```text
核心界面已定稿，作为本版风格基准。请先只输出一份图片清单（不要生成图片），说明每张图的名称、所属端、作用，以及你建议的总数。

覆盖要求（必须满足）：
- 端：本版界面集中在前台——电脑端网页（1440×900）为主，手机端网页（390×844，网页形态而非 App 外壳）至少覆盖问答列表与问题详情两张（同一站点自适应）；管理后台本版无新增界面。
- 前台必含界面（核心界面已生成，其余按此清单补齐，可合并或拆分并说明理由）：
  1) 问答列表页：板块内「讨论／问答」标签页切换、已公开问题列表（标题、作者、悬赏积分标识、发布时间）、按时间倒序；空态一——本板块暂无已公开问题（引导发起新问答）。
  2) 提问页：标题与正文输入、悬赏积分步进器（10～500、步长 10）、当前积分余额展示、所属板块显示；异常态一——余额不足拦截（危险色提示「积分余额不足，请调整悬赏」）；异常态二——悬赏额非法提示「悬赏积分为 10～500、步长 10」。
  3) 编辑问题与追加补充：编辑表单（已公开问题编辑后标注「审核中」，原文保留可见）；追加补充输入（单次 ≤2000 字符提示）。
  4) 作答与补充答案：作答输入框与提交反馈（提交后提示「已提交，待审核」）；作者侧状态标识——待审核／已驳回（含驳回原因入口）。
  5) 采纳与关闭反馈：采纳确认弹层（「采纳后不可更换，悬赏将结算给答题人」）；关闭问题确认弹层（「关闭为终态，待结算悬赏将退回」）；已采纳态——最佳答案置顶并带「最佳」标识（成功色语义）、悬赏状态「已结算」；已关闭态——问题状态「已关闭」、悬赏状态「已撤回」。
  6) 异常态集：被采纳答案的「不可编辑、不可删除」提示；终态问题（已采纳／已关闭）无作答与编辑入口的页面态。
  7) 问答搜索结果页：关键词检索结果分「问题」「答案」两类呈现；空态二——无匹配结果（提示调整关键词）；答案结果点击进入所属问题详情。
- 无界面声明（不生成图）：悬赏到期退回（定时任务，结果在详情页状态与通知体现）；站内搜索输入入口沿用 0.2 既有界面不重画；管理后台待审队列沿用 0.2 既有界面不重画（问题与答案作为既有类型筛选的数据出现，无界面变化）；个人中心我的内容与积分等级展示随 0.5。
- 关键信息点：内容状态标识（待审核／已公开／已驳回）、悬赏状态（待结算／已结算／已撤回）与问题状态（待解答／已采纳／已关闭）一律「色块＋文字」双表达；界面用词逐字取自《术语表（项目）》与本清单。
- 本版范围外界面不得出现（同第一步附加禁止）。

清单确认后，请逐张输出生图提示词（每次一张，结构同核心界面），我确认后再生成。
```

## 4. 第四步：批量生成

```text
按清单顺序逐张生成，每张生成后按同一标准自检：与本版核心界面基准一致（配色、圆角、密度、信息层级）、界面文字全中文且与术语表一致、无禁止元素。有偏差时先修正再进入下一张。
```

单张迭代方法：只描述要改的地方与期望效果，一次一到两处，避免整张重写导致风格漂移。

## 附注 其他生图模型的差异

无对话记忆的模型（如即梦等单次生图工具）无法「先出提示词、再规划清单」：使用时把第 1 步与实际界面要点一次性写进单张提示词，先只出核心界面并定稿，再把核心界面图作为风格参考图连同第 3 步的覆盖要求逐张生图；附 A 与附 B 的用法不变。
