## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

```text
你是资深 UI 设计师。我已提供《PRD（小版本）v0.3.0》《UI（项目）生图脚本》《术语表（项目）》三份资料（如另附项目 PRD 与技术文档一并参考）。

请先只分析、只输出一段生图提示词，不要生成图片。

一、产品与主端
- 产品：自建自营的社区论坛「巡云轻论坛」，本版为成长账本与规则版本（积分账本与等级引擎）。
- 第一张图＝本版核心界面：管理后台（画布 1440×900）的「全站设置 · 等级与积分规则配置」页——本版唯一人工操作面，仅站长可见。
- 界面文字全部为简体中文，用词逐字取自《术语表（项目）》。

二、核心界面必须出现的元素（缺一不可）
- 管理后台框架：左侧导航（「全站设置」处于选中态）、顶部站点名「巡云轻论坛」与「管理后台」标识、站长身份显示。
- 页面标题区：「全站设置 · 等级与积分规则配置」，附一行说明「保存后即时生效，不追溯已判等级」。
- 区块一「行为积分值」：五行配置行——「注册」＋10、「话题被公开」＋5、「评论被公开」＋2、「问题被公开」＋5、「答案被公开」＋5；每行为行为名称＋积分输入框（整数）；区块底部一行说明文字「答案被采纳结算与发起悬赏按悬赏额执行，不在此配置」。
- 区块二「等级门槛」：五行档位行——「Lv1 新手上路 0」（输入框呈禁用态）、「Lv2 初级会员 50」、「Lv3 中级会员 200」、「Lv4 高级会员 500」、「Lv5 资深会员 1500」；每行为档位名称＋门槛积分输入框；区块底部一行说明「门槛须递增，Lv1 固定为 0」。
- 积分与档位标识使用激励琥珀色点缀（数值与档位名），状态与语义一律「色块＋文字」双表达。
- 操作区：主色「保存」按钮；一条成功提示（绿色）「已保存，即时生效且不追溯已判等级」。
- 页脚或区块尾一行留痕说明「配置变更留痕可追溯」。

三、风格锚定（必须严格遵守，引自项目层脚本）
- 主色（品牌蓝）#2A6CBE：顶部导航与主按钮、链接、选中态；按下态 #1F5497；浅底选中 #E8F1FB。
- 副色（激励琥珀）#C97A16：悬赏、积分、等级标识专用；浅底 #FAF1E3。
- 语义色：成功 #15803D（已通过、已采纳、已结算）、警示 #B45309（待审核、待处理）、危险 #B91C1C（驳回、删除、封号）、信息 #2A6CBE。
- 中性色：页面底 #F5F7FA、卡片 #FFFFFF、分割线 #E5E8EB、次级文字 #5B6570、正文 #1F2328、禁用 #9AA4AF。
- 字体：中文系统字体栈（苹方／思源黑体／微软雅黑），正文 14px、标题 16px～20px，行高 1.6。
- 形态：卡片圆角 8px、按钮与输入框圆角 6px、列表行高 44px、头像圆形、标签与状态用胶囊；状态一律「色块＋文字」双表达，不靠颜色单独承载语义。
- 通用禁止：不出现英文界面文字；不出现应用商店、手机 App 图标、小程序外壳；不出现真人照片、第三方品牌标识与真实机构名；不使用大面积渐变、霓虹色、玻璃拟态与 3D 元素；不使用夸张阴影；不出现倒计时、抢购、优惠券等电商化元素；不使用未成年人形象。

四、本版附加禁止
- 不出现悬赏问答操作界面（提问、作答、采纳——随下一小版本）；不出现会员个人中心的积分与等级页（随 0.5）；不出现积分人工修正入口（随 0.7）；不出现「待审核」「已驳回」等内容状态标识（本版无内容审核面）。

五、提示词结构要求
按「画面类型与画布尺寸 → 页面结构分区描述 → 每个分区的元素与文案示例 → 色彩与字体与形态 → 光影与质感 → 负向要求」的顺序组织；文案示例用简体中文并逐字取自《术语表（项目）》与本话术。

六、输出
只输出这段生图提示词，并在末尾用三行说明：你为谁设计、为什么核心界面是这张配置页、这张图承担什么作用。
```

## 2. 第二步：生成并迭代核心界面

```text
按你刚才输出的提示词生成图片。生成后请逐项自检并告诉我：必须元素是否齐全（行为积分值五行、等级门槛五行、Lv1 禁用态、保存与成功提示）、色值是否贴近主色 #2A6CBE 与激励琥珀 #C97A16、是否有英文文字或禁止元素。
```

迭代方法：对不满意处逐条提出（如「把等级门槛区块上移、与行为积分值区块等宽」「把成功提示改为页面顶部横条」），每轮只改一到两处；满意后即本版基准，并与项目层脚本生成的主页基准并检一次——核对配色、圆角、密度与信息层级同源，防跨版本风格漂移。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

```text
核心界面已定稿，作为本版风格基准。请先只输出一份图片清单（不要生成图片），说明每张图的名称、所属端、作用，以及你建议的总数。

覆盖要求（必须满足）：
- 端：本版仅管理后台（1440×900）有界面，全部图片属管理后台。
- 核心界面「全站设置 · 等级与积分规则配置」正常态已生成，其余按以下清单补齐（可合并或拆分，说明理由）：
  1) 拦截态一：等级门槛非递增——保存被拦截，页面出现危险色提示「等级门槛须递增」，输入框标红，原配置保持生效。
  2) 拦截态二：行为积分值非法（非整数、负数或超出 0～999）——保存被拦截，出现危险色提示「积分值为 0～999 的整数」。
  3) 幂等提示态：重复保存相同值——出现信息色提示「无变更，配置未变化」，不产生新变更记录。
- 机制条目无界面声明（不生成图）：账户开立（注册页沿用既有界面、本版无变化，不重画）、积分入账、积分出账与预扣、流水记录、等级判定、等级变更——均为系统机制，无人工触发面。
- 空态声明：本版无空列表面——配置项上线即有初始值，不存在空配置页，无需空态图。
- 关键信息点：拦截与幂等提示文案逐字取自上述要求；页面其余用词逐字取自《术语表（项目）》。
- 本版范围外界面不得出现（同第一步附加禁止）。

清单确认后，请逐张输出生图提示词（每次一张，结构同核心界面），我确认后再生成。
```

## 4. 第四步：批量生成

```text
按清单顺序逐张生成，每张生成后按同一标准自检：与本版核心界面基准一致（配色、圆角、密度、信息层级）、界面文字全中文且与术语表一致、无禁止元素。有偏差时先修正再进入下一张。
```

单张迭代方法：只描述要改的地方与期望效果，一次一到两处，避免整张重写导致风格漂移。

图片全部满意后，按附 B 逐张登记；若对颜色做了微调，须同步更新项目层脚本附 A 的色值（附 A 是品牌色唯一来源）与本版第 1 步话术中的色值，保持文档与产出同源。

## 附注 其他生图模型的差异

无对话记忆的模型（如即梦等单次生图工具）无法「先出提示词、再规划清单」：使用时把第 1 步与实际界面要点一次性写进单张提示词，先只出核心界面并定稿，再把核心界面图作为风格参考图连同第 3 步的覆盖要求逐张生图；附 A 与附 B 的用法不变。
