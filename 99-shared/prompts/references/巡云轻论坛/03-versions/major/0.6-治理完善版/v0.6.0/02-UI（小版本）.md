## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

```text
你是资深 UI 设计师。我已提供《PRD（小版本）v0.6.0》《UI（项目）生图脚本》《术语表（项目）》三份资料（如另附项目 PRD 与技术文档一并参考）。

请先只分析、只输出一段生图提示词，不要生成图片。

一、产品与主端
- 产品：自建自营的社区论坛「巡云轻论坛」，本版为治理闭环与运营管理面版本（举报、治理侧删除、留痕查询、运营内容、会员与内容检索维护）。
- 第一张图＝本版核心界面：管理后台（画布 1440×900）的「待处理举报详情页」——举报处置的版主主操作面，承载本版主题的信息量最大界面。
- 界面文字全部为简体中文，用词逐字取自《术语表（项目）》。

二、核心界面必须出现的元素（缺一不可）
- 管理后台框架：左侧导航（「举报处置」处于选中态、其余为「待审队列」「审核留痕查询」「运营内容维护」「会员查询与维护」「内容查询与维护」）、顶部站点名与版主身份。
- 举报信息区：举报编号「6001」、举报人昵称与举报时间、举报理由全文、状态标签「待处理」（警示色，色块＋文字双表达）。
- 被举报内容区：内容类型「话题」、内容摘要卡片（标题、作者昵称、发布时间）与「查看原文」链接。
- 处置操作区：结论二选一——「举报成立」（主色按钮）与「举报驳回」（次要按钮）；成立时的处置动作三选（删除内容／禁言／封号，禁言含期限选择 1／3／7／30 天）；处置理由输入框（占位「填写处置理由，1～200 字符」）与字数提示。
- 侧栏留痕预览：该内容的既有审核记录时间线（结论、操作人、时间）。
- 状态双表达：待处理用警示色；不出现任何支付、红包、现金、会员卡类元素。

三、风格锚定（必须严格遵守，引自项目层脚本）
- 主色（品牌蓝）#2A6CBE：顶部导航与主按钮、链接、选中态；按下态 #1F5497；浅底选中 #E8F1FB。
- 副色（激励琥珀）#C97A16：悬赏、积分、等级标识专用；浅底 #FAF1E3。
- 语义色：成功 #15803D（已通过、已采纳、已结算）、警示 #B45309（待审核、待处理）、危险 #B91C1C（驳回、删除、封号）、信息 #2A6CBE。
- 中性色：页面底 #F5F7FA、卡片 #FFFFFF、分割线 #E5E8EB、次级文字 #5B6570、正文 #1F2328、禁用 #9AA4AF。
- 字体：中文系统字体栈（苹方／思源黑体／微软雅黑），正文 14px、标题 16px～20px，行高 1.6。
- 形态：卡片圆角 8px、按钮与输入框圆角 6px、列表行高 44px、头像圆形、标签与状态用胶囊；状态一律「色块＋文字」双表达，不靠颜色单独承载语义。
- 通用禁止：不出现英文界面文字；不出现应用商店、手机 App 图标、小程序外壳；不出现真人照片、第三方品牌标识与真实机构名；不使用大面积渐变、霓虹色、玻璃拟态与 3D 元素；不使用夸张阴影；不出现倒计时、抢购、优惠券等电商化元素；不使用未成年人形象。

四、本版附加禁止
- 不出现申诉流程入口（未纳入）；不出现自动审核或机器判定标识（明确不做）；不出现浏览量统计页与积分人工修正入口（随 0.7）；不出现前台话题、问答、个人中心界面的任何改动（沿用既有界面，仅新增举报入口按钮）。

五、提示词结构要求
按「画面类型与画布尺寸 → 页面结构分区描述 → 每个分区的元素与文案示例 → 色彩与字体与形态 → 光影与质感 → 负向要求」的顺序组织；文案示例用简体中文并逐字取自《术语表（项目）》与本话术。

六、输出
只输出这段生图提示词，并在末尾用三行说明：你为谁设计、为什么核心界面是待处理举报详情页、这张图承担什么作用。
```

## 2. 第二步：生成并迭代核心界面

```text
按你刚才输出的提示词生成图片。生成后请逐项自检并告诉我：必须元素是否齐全（举报信息区、被举报内容摘要与查看原文、结论二选一与处置动作三选、理由输入与字数提示、侧栏留痕时间线、待处理状态双表达）、色值是否贴近主色 #2A6CBE、是否有英文文字或禁止元素。
```

迭代方法：对不满意处逐条提出（如「把处置动作三选改为卡片单选」「把留痕时间线移到右侧栏顶部」），每轮只改一到两处；满意后即本版基准，并与项目层脚本生成的主页基准并检一次——核对配色、圆角、密度与信息层级同源，防跨版本风格漂移。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

```text
核心界面已定稿，作为本版风格基准。请先只输出一份图片清单（不要生成图片），说明每张图的名称、所属端、作用，以及你建议的总数。

覆盖要求（必须满足）：
- 端：管理后台（1440×900）为主——举报处置队列、留痕查询、运营内容维护、会员与内容检索；前台（电脑端 1440×900 与手机端 390×844）至少覆盖举报入口与运营位两类。
- 管理后台必含界面（核心界面已生成，其余按此清单补齐，可合并或拆分并说明理由）：
  1) 待处理举报队列：列表（编号、被举报内容摘要、举报人、时间、待处理标识）；空态一——暂无待处理举报。
  2) 举报驳回路径：驳回理由填写与确认（不成立路径，与核心界面成立路径对照）。
  3) 审核留痕查询页：按内容或操作人筛选的结果时间线（结论、原因、操作人、时间）；空态二——无匹配记录。
  4) 治理侧删除确认弹层：「删除为终态不可恢复，将解除点赞与收藏并通知作者」＋处置理由必填；被采纳答案拦截态——提示「被采纳的答案不可删除，改为标记处置结果」。
  5) 运营内容维护页：条目列表（标题、位置、状态启用／停用、跳转目标）＋新增表单（标题、摘要、跳转目标选择站内话题或问题、位置选择首页横幅／板块侧栏）；异常态一——位置启用上限 5 条拦截提示；异常态二——启用中条目改位置提示须先停用；删除确认（软删除记录保留）。
  6) 会员查询与维护页：按昵称／编号／状态（正常／禁言／封号／已注销）检索的列表＋资料详情（昵称与备注维护）；空态三——无匹配会员；账号状态变更入口显示为指向治理处置的跳转说明。
  7) 内容查询与维护两张：话题范围（话题与评论，含板块归属更正）与问答范围（问题与答案，悬赏状态只读展示）；被采纳答案删除拦截态；空态四——无匹配内容。
- 前台必含界面：
  8) 举报入口与提交：内容操作区的「举报」按钮、理由填写弹层（1～200 字符）、重复举报提示「已收到你的举报」、提交成功反馈；手机端一张（话题详情操作区含举报按钮）。
  9) 我的举报列表（个人中心）：状态标识（待处理／已处理／已驳回）与结论查看；空态五——还没有发起过举报。
  10) 前台运营位呈现：首页横幅与板块侧栏各一条运营内容示例（标题＋摘要＋「查看详情」跳转）；停用后该位置空态。
- 无界面声明（不生成图）：通知提醒的写入与送达（系统行为，列表沿用 0.4 界面）；待审队列沿用 0.2 既有界面不重画（举报处置独立成面）；话题、问答、个人中心等既有界面不重画（仅新增举报按钮）。
- 关键信息点：三态状态标识、处置动作与期限取值、位置枚举与上限、跳转仅站内等文案逐字呈现；界面用词逐字取自《术语表（项目）》与本清单。
- 本版范围外界面不得出现（同第一步附加禁止）。

清单确认后，请逐张输出生图提示词（每次一张，结构同核心界面），我确认后再生成。
```

## 4. 第四步：批量生成

```text
按清单顺序逐张生成，每张生成后按同一标准自检：与本版核心界面基准一致（配色、圆角、密度、信息层级）、界面文字全中文且与术语表一致、无禁止元素。有偏差时先修正再进入下一张。
```

单张迭代方法：只描述要改的地方与期望效果，一次一到两处，避免整张重写导致风格漂移。

## 附注 其他生图模型的差异

无对话记忆的模型（如即梦等单次生图工具）无法「先出提示词、再规划清单」：使用时把第 1 步与实际界面要点一次性写进单张提示词，先只出核心界面并定稿，再把核心界面图作为风格参考图连同第 3 步的覆盖要求逐张生图；附 A 与附 B 的用法不变。
