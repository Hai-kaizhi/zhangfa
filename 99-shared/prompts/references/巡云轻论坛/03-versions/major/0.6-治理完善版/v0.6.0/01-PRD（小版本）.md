# PRD（小版本）：v0.6.0 治理闭环与运营管理面

> 定位：开发级需求说明书——承接大版本 PRD 0.6 治理完善版与其 02 批次一，认领自需求池（R96～R107，状态已迁移为已认领（v0.6.0））；用途与验收标准逐字锚定上游、只细化不改写；上游为模拟案例材料，模拟性质予以保留。

## 1. 版本概述

**承接与目标**：本版认领 0.6 治理完善版批次一「治理闭环与运营管理面」全部 12 条（R96～R107，简单场景采纳整批——该大版本仅此一批），交付：举报闭环（发起→核实处置／驳回→我的举报）、处置与回溯（删除违规内容、审核留痕查询）、运营内容维护（新增／编辑／删除与前台运营位）与检索维护面（会员、话题范围内容、问答范围内容）；0.2 遗留的「治理侧删除缺失」过渡由 R101 正式补齐。本版可验收形态：可演示路线图完成标志——一名会员举报违规内容，版主核实后完成处置（含内容删除）并通知双方，处置结论可在审核留痕中回溯；运营人员能检索会员与内容并维护运营内容（上游 02 批次一可验收形态原文）。本版为站内能力版本、无对外发布台阶。

**范围外声明**：申诉流程与自动审核机器判定不做（路线图明确不做，PRD 不做 AI 助手）；浏览量统计与积分人工修正随 0.7；被处置内容连带隐藏同作者其他内容未纳入（04C 待业务确认）；会员账号状态变更不在 R105 内执行（指向 0.2 已交付的禁言与封号处置入口，R97 作为举报处置动作消费）。

**条目内顺序与依赖**（引用上游批内口径：举报闭环先行、运营管理面收口）：开发序建议举报闭环先行（R96→R97／R98→R99，R101 删除与 R100 留痕随闭环联调）→ 运营管理面收口（R102～R104、R105～R107 三族可并行）；同事务契约不回退——举报状态变更与处置留痕、双方通知同一事务（口径二）、治理侧删除与互动关系清理及留痕通知同事务、运营内容保存与留痕同事务。

**本版定案值沿用**（0.6 PRD §1，均为推导拍板或行业惯例默认）：运营内容形态＝结构化运营位条目（标题 2～24 字符、摘要 ≤100 字符、跳转仅站内话题或问题、位置枚举首页横幅／板块侧栏、新增即默认启用、每位置启用上限 5 条、软删除记录保留）；举报重复合并（同一举报人对同一内容只保留一条待处理项）；结论通知类型＝「举报成立」「举报驳回」（术语表 §7 已登记），处置含禁言封号时被处置方沿用既有处置类通知。

## 3. 核心用户旅程

**旅程承接说明**：承接上游大版本 PRD 同名三条旅程，均落在批次一认领范围内，本版细化到开发级取值（理由字数、合并口径、留痕字段、位置上限）；我的举报、审核留痕查询、会员查询与维护、内容查询与维护为简单操作型功能不成旅程（验收标准可覆盖）。

### 3.1 旅程一：举报核实与处置闭环（会员、版主·跨主体）

```mermaid
sequenceDiagram
    participant 会员
    participant 前台站点
    participant 版主
    participant 审核与治理模块
    会员->>前台站点: 对已公开内容点击举报 填写理由（≤200 字符）
    前台站点->>审核与治理模块: 写入举报（待处理，合并重复举报）
    版主->>审核与治理模块: 查看待处理举报 核实内容与理由
    alt 举报成立
        版主->>审核与治理模块: 执行处置（删除内容或禁言 封号）
        Note over 版主,审核与治理模块: 举报置已处理 处置留痕 双方通知同一事务
        审核与治理模块-->>会员: 通知 举报成立
        审核与治理模块-->>会员: 被处置方收到处置结果通知
    else 举报不成立
        版主->>审核与治理模块: 填写理由驳回举报
        审核与治理模块-->>会员: 通知 举报驳回（含理由）
    end
```

本旅程演示口径一前半段与口径二：举报进入待处理（同一内容重复举报合并为一条）；版主核实后两路结论均与留痕、通知同事务完成。

操作步骤清单：1. 会员对已公开内容点击举报、填写理由提交；2. 举报进入待处理队列（重复举报被合并）；3. 版主查看待处理举报并核实；4. 成立则执行处置（删除违规内容或禁言、封号）、不成立则填写理由驳回；5. 结论、处置留痕（处置人、时间、理由）与双方通知同一事务完成；6. 会员在我的举报查看结论。

```mermaid
    D --> E[同一事务 解除点赞与收藏 写处置留痕 通知作者]
    E --> F[来源为举报时 同步举报结论为已处理]
    F --> G[留痕查询面 按内容或操作人回溯 处置人 时间 理由]
```

本旅程演示治理侧删除（0.2 过渡的正式补齐）与留痕回溯：删除为终态、互动关系同事务清理、留痕可检索；被采纳的答案不删除、改为保留并标记处置结果。

操作步骤清单：1. 版主对违规内容执行删除（来源可为举报核实或主动巡查）；2. 幂等校验当前状态后置已删除终态；3. 同一事务解除点赞与收藏、写处置留痕、通知作者；4. 来源为举报时同步举报结论；5. 在审核留痕查询按内容或操作人回溯该记录。

### 4.2 R96 举报发起

**功能说明**：对已公开内容提交举报并说明理由——举报进入待处理队列，重复举报合并。触发：会员在已公开内容（话题、评论、问题、答案）的操作区点击举报。

**交互与流程**：

```mermaid
flowchart TB
    A[会员点击内容的举报按钮] --> B{内容是否已公开}
    B -->|非公开或已删除| C[举报入口不可用并提示]
    B -->|已公开| D[填写举报理由 ≤200 字符]
    D --> E{本人是否已举报过该内容}
    E -->|是| F[合并至既有待处理项 提示已收到举报]
    E -->|否| G[写入举报置为待处理]
    G --> H[提示提交成功 进入版主待处理队列]
```

操作步骤清单：1. 会员在已公开内容操作区点击举报；2. 填写理由（1～200 字符）提交；3. 首次举报写入待处理；4. 对同一内容的重复举报合并至既有待处理项并提示已收到；5. 提交成功提示。

**字段与校验**：

| 信息项 | 必填 | 校验 |
|---|---|---|
| 被举报内容 | 是 | 须为已公开状态的话题／评论／问题／答案（多态引用：内容类型＋内容标识） |
| 举报理由 | 是 | 1～200 字符 |

**规则与边界**：1. 仅已公开内容可举报（非公开与已删除不可举报，入口不可用）。2. 同一举报人对同一内容的重复举报合并为一条待处理项（本版定案；不同举报人对同一内容各成一条）。3. 举报为治理档案：终态（已处理／已驳回）后不可再变更、不删除。4. 举报不通知被举报方（避免打草惊蛇，处置结论才通知双方——本版拍板，从「结论通知相关方」锚推导）。

**异常与拦截**：1. 非公开内容→入口不可用并提示。2. 理由为空或超 200 字符→提示调整。3. 重复提交（并发双击）→合并幂等，只产生一条待处理项。

### 4.3 R97 举报核实与处置 ◆

**功能说明**：核实后作出处置或驳回，结论通知相关方——举报处置的版主主操作。触发：版主在管理后台打开待处理举报。

**交互与流程**：

```mermaid
flowchart TB
    A[版主打开待处理举报] --> B[查看被举报内容与举报理由]
    B --> C[核实判断]
    C -->|成立| D{选择处置动作}
    D -->|删除内容| E[执行治理侧删除 R101 路径]
    D -->|处置账号| F[执行禁言或封号 沿用 0.2 处置]
    E --> G[同一事务 举报置已处理 写处置留痕 通知双方]
    F --> G
    C -->|不成立| H[转入举报驳回 R98 路径]
```

操作步骤清单：1. 版主在待处理举报队列打开某条举报，查看被举报内容与理由（内容原文可跳转）；2. 核实后选择结论：成立则选择处置动作（删除违规内容，或禁言、封号沿用 0.2），不成立则转入驳回；3. 成立路径同一事务完成：处置执行、举报置已处理（写结论、处置人、处置时间）、写处置留痕、通知举报人（举报成立）与被处置方（处置结果）；4. 处置完成后举报从待处理队列消失。

**字段与校验**：

| 信息项 | 必填 | 校验 |
|---|---|---|
| 处置动作 | 成立时必选 | 删除内容／禁言／封号三选（禁言期限取值沿用 0.2：1／3／7／30 天） |
| 处置理由 | 是 | 1～200 字符，写入处置留痕与通知摘要 |

**规则与边界**：1. 举报状态变更、处置留痕、双方通知同一事务（R97 锚、口径二），任一失败整体回滚。2. 处置动作消费既有能力：内容删除走 R101 路径（含互动清理）、账号处置走 0.2 禁言与封号（含留痕与通知）。3. 同一事务内仅处置一次：重复提交被终态校验拒绝（幂等）。4. 通知口径：举报人收「举报成立」；被处置方在删除场景收「举报成立」视角文案、在禁言封号场景沿用既有处置类通知（本版定案）。

**异常与拦截**：1. 举报已被处理（并发）→终态校验拒绝，界面刷新。2. 被举报内容在核实前已被删除→举报仍可处置（结论基于既有事实），处置动作仅剩账号处置或驳回。3. 事务失败→整体回滚，举报保持待处理。

### 4.7 R101 删除违规内容 ◆

**功能说明**：对内容执行删除，删除为终态——治理侧内容删除的正式交付。触发：版主在举报处置中选择删除，或在内容巡查／检索面发起删除。

**规则与边界**：1. 删除为终态、前台与搜索不再出现（R101 锚）。2. 互动关系清理与删除同事务（0.2 删除话题清理口径推广至四类内容，本版拍板）。3. 被采纳的答案不可删除、保留内容并标记处置结果（问答契约沿用）。4. 幂等：重复删除不产生多条处置记录。

**异常与拦截**：1. 被采纳答案→拦截删除并提示，改走标记处置。2. 重复删除→幂等返回。3. 事务失败→整体回滚，内容状态不变。

```mermaid
    B --> C{是否有结果}
    C -->|无| D[空态 无匹配内容]
    C -->|有| E[列表展示 标题 作者 状态 悬赏状态]
    E --> F[查看详情 悬赏状态只读]
    F --> G[资料性更正 留痕]
    F --> H[删除入口 被采纳答案不可删 其余走治理侧处置]
```

操作步骤清单：1. 运营人员按关键词、作者、状态与时间区间检索问题与答案；2. 列表与详情查看，悬赏状态随问题只读展示；3. 资料性更正留痕执行；4. 删除：被采纳的答案不可删除（拦截并提示）、其余内容转治理侧处置路径并留痕。

**字段与校验**：

| 信息项 | 必填 | 校验 |
|---|---|---|
| 检索条件 | 至少一项 | 关键词、作者、状态、时间区间 |
| 展示要素 | — | 悬赏状态（待结算／已结算／已撤回）随问题只读展示 |

**规则与边界**：1. 被采纳的答案不可删除（R107 锚，治理处置沿用标记口径）。2. 悬赏状态只读（账本与悬赏状态变更归成长与问答模块）。3. 维护与处置均留痕。

**异常与拦截**：1. 被采纳答案删除→拦截并提示。2. 无匹配→空态。3. 越权→拦截。
