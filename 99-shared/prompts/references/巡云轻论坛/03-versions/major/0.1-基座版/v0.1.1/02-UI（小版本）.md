## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

```text
你是资深 UI 设计师。我已提供《PRD（小版本）v0.1.1》《UI（项目）脚本》《术语表（项目）》三份资料。

请先只分析、只输出一段生图提示词，不要生成图片。

一、本版与核心界面
- 本版只交付站点结构与规则：管理后台的板块管理、标签管理与全站设置（站点信息、审核策略、设置查看）；不涉及任何内容、会员与消息类功能，前台界面随 0.2 交付。
- 第一张图＝本版核心界面：管理后台（1440×900）的「板块与标签管理·板块页」——本版信息量最大的操作面（板块列表＋新增／编辑表单＋排序＋停用启用＋删除确认）。
- 界面文字全部为简体中文，用词逐字取自《术语表（项目）》（板块、标签、全站设置、站长、运营人员、启用、停用）。

二、核心界面必须出现的元素（缺一不可）
- 顶部：站点后台标识「巡云轻论坛 管理后台」（站点名取自站点信息配置）、当前登录账号、「个人设置」入口与「退出」。
- 板块列表：列＝板块名、说明、排序值、状态标签（启用为绿、停用为棕黄）、创建时间、操作列（编辑、排序、停用／启用、删除）；列表含至少一行启用、一行停用；行首拖拽把手示意排序。
- 新增板块表单（抽屉或弹层）：板块名输入、说明输入、「新增板块」主按钮。
- 停用确认弹窗：「停用后不再接收新内容，已有内容仍可读」。
- 删除确认弹窗：显示板块名与编号，要求输入「删除」二字，确认按钮不可用态与可用态各示意一次。
- 空态：板块列表空态文案「暂无板块，点击新增板块开始」。
- 异常态至少两处：名称重复「板块名已存在」；越界「板块名需 2～24 个字符」。

三、风格锚定（必须严格遵守，沿用项目层基准，并与已发布的 v0.1.0 账号与角色管理界面同源）
- 主色（品牌蓝）#2A6CBE：顶栏、主按钮、链接、选中态；按下态 #1F5497；浅底 #E8F1FB。
- 语义色：成功 #15803D（启用）、警示 #B45309（停用）、危险 #B91C1C（删除类破坏性操作）、信息 #2A6CBE。
- 中性色：页面底 #F5F7FA、卡片 #FFFFFF、分割线 #E5E8EB、次级文字 #5B6570、正文 #1F2328、禁用 #9AA4AF。
- 字体：中文系统字体栈（苹方／思源黑体／微软雅黑），正文 14px、标题 16～20px，行高 1.6。
- 形态：卡片圆角 8px、按钮与输入框圆角 6px、列表行高 44px；状态一律「色块＋文字」双表达。
- 通用禁止（项目层整段继承）：不出现英文界面文字；不出现应用商店、手机 App 图标、小程序外壳；不出现真人照片、第三方品牌标识与真实机构名；不使用大面积渐变、霓虹色、玻璃拟态与 3D 元素；不使用夸张阴影；不出现倒计时、抢购、优惠券等电商化元素；不使用未成年人形象。
- 本版附加禁止：不出现话题、问题、答案、评论、内容列表、悬赏、积分、等级、私信、通知提醒、审核队列、举报等字样与元素（随 0.2 及以后版本）；不出现前台访客页面（本版无前台界面）；不出现支付、红包、现金、会员卡类元素。

四、提示词结构要求
按「画面类型与画布尺寸 → 页面结构分区描述 → 每个分区的元素与文案示例 → 色彩与字体与形态 → 光影与质感 → 负向要求」组织；文案示例用简体中文并逐字取自术语表与上述元素清单。

五、输出
只输出这段生图提示词，并在末尾三行说明：你为谁设计、为什么核心界面是板块页、这张图承担什么作用。
```

## 2. 第二步：生成并迭代核心界面

```text
按你刚才输出的提示词生成图片。生成后逐项自检并告诉我：核心界面必须元素是否齐全、状态标签是否为「色块＋文字」双表达、主色是否贴近 #2A6CBE、是否有英文文字或本版禁止元素（话题／内容列表／悬赏／积分等）。
```

迭代方法：逐条提出修改（一次一到两处），满意的核心界面即本版基准；随后与项目层主页基准图并检一次——配色密度、圆角、信息层级与主页一致才算通过（防跨版本风格漂移），不一致处以项目层主页为准修正。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

```text
核心界面已定稿，作为本版基准。请先只输出一份图片清单（不要生成图片），说明每张图的名称、所属端、作用，以及你建议的总数。

覆盖要求（必须满足，来源＝本版 PRD 认领条目 R13～R23，全部在管理后台 1440×900）：
  1) 板块编辑页：回显板块名与说明，修改保存成功态；异常态「板块名已存在」「说明不超过 100 字」。
  2) 板块排序：拖拽把手与排序值输入两种方式、批量保存成功态；异常态「排序值需为 1～9999 的整数」。
  3) 板块停用与启用：停用确认（停用后列表状态标签变化）、启用恢复、重复停用幂等提示「该板块已是停用状态」。
  4) 板块删除：无内容时删除确认（输入「删除」二字）；有内容时拦截态「请先迁移或处置该板块下的内容」（拦截规则先行就绪、内容随 0.2 上线，界面需画出该拦截提示态）。
  5) 标签页：标签列表（标签名、使用次数列、创建时间）；新增与编辑表单；异常态「标签名已存在」「标签名需 2～24 个字符」。
  6) 标签删除：使用次数为零时删除确认（输入「删除」二字）；使用中拦截态「标签正在被话题使用，请先调整相关话题」（判定先行就绪，界面需画出拦截提示态）。
  7) 全站设置·站点信息：站点名与站点说明表单、保存成功后顶栏站点名即时更新示意；异常态「站点名需 2～30 个字符」「站点说明不超过 200 字」。
  8) 全站设置·审核策略：话题／问题／答案／评论四类内容复选（默认全选）、保存成功态；重复保存相同值的幂等提示「无变更」；异常态「至少勾选一类内容」。
  9) 设置查看页：只读展示站点信息与审核策略当前生效值，标注只读并指向修改入口。
  10) 空态必须画出：板块列表空态、标签列表空态、配置缺失时显示默认值并标注「默认值」。
- 机制条目（无界面、不生成图）：审核策略的消费（0.2 起由内容审核读取）；板块停用对内容提交的拦截与标签使用次数派生（0.2 起生效）——先行基座机制，仅在第 4、6 项以拦截提示态表达。
- 界面文字一律逐字取自《术语表（项目）》与本版 PRD 的提示文案，不得自造近义词；通用禁止与本版附加禁止同第一步。

清单确认后，请逐张输出生图提示词（每次一张，结构同核心界面），我确认后再生成。
```

## 4. 第四步：批量生成

```text
按清单顺序逐张生成，每张生成后按同一标准自检：与本版基准一致（配色、圆角、密度、信息层级）、界面文字全中文且与术语表及 PRD 文案一致、无本版禁止元素。有偏差先修正再进入下一张。
```

单张迭代方法：只描述要改的地方与期望效果，一次一到两处，避免整张重写导致风格漂移。

## 5. 收尾：回填归档

图片全部满意后按附 B 逐张登记；如对颜色做了微调，不得在本版定新值——须同步修改项目层脚本附 A（唯一来源）后，本版话术与附 A 复本随之更新。

## 附注 其他生图模型的差异

无对话记忆的模型（如即梦等单次生图工具）无法"先出提示词、再规划清单"：使用时把第 1 步与目标界面要点一次性写进单张提示词，先生成核心界面并与项目层主页基准并检定稿，再逐张生图；附 A 与附 B 用法不变。
