## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

```text
你是资深 UI 设计师。我已提供《PRD（小版本）v0.1.0》《UI（项目）脚本》《术语表（项目）》三份资料。

请先只分析、只输出一段生图提示词，不要生成图片。

一、本版与核心界面
- 本版只交付身份与权限基座：会员注册登录（电脑端网页与手机端网页）＋管理后台的账号与角色管理、个人设置；不涉及任何内容、积分与消息类功能。
- 第一张图＝本版核心界面：管理后台（1440×900）的「账号与角色管理」页——本版信息量最大的操作面（账号列表＋开通表单＋角色分配＋能力点勾选）。
- 界面文字全部为简体中文，用词逐字取自《术语表（项目）》（会员账号、管理端账号、管理端角色、站长、运营人员、版主、启用、停用）。

二、核心界面必须出现的元素（缺一不可）
- 顶部：站点后台标识「巡云轻论坛 管理后台」、当前登录账号（站长）、「个人设置」入口与「退出」。
- 账号列表：列＝账号名、编号、角色标签（可多个）、状态标签（启用为绿、停用为棕黄、已注销为灰）、备注、操作列（编辑、停用／启用、注销）；列表含至少一行启用、一行停用、一行已注销。
- 开通账号表单（抽屉或弹层）：账号名输入、备注输入、角色多选（复选框组）、「开通账号」主按钮。
- 开通成功结果态：显示账号名与一次性初始密码，提示「仅本次可见，请通过安全渠道转交」。
- 角色页入口或并排区块：角色列表（角色名、能力点勾选集合）。
- 空态：账号列表空态文案「暂无账号，点击开通账号开始」。
- 异常态至少两处：账号名已存在「账号名已存在」；未选角色「至少选择一个角色」。

三、风格锚定（必须严格遵守，沿用项目层基准）
- 主色（品牌蓝）#2A6CBE：顶栏、主按钮、链接、选中态；按下态 #1F5497；浅底 #E8F1FB。
- 语义色：成功 #15803D（启用）、警示 #B45309（停用）、危险 #B91C1C（注销类破坏性操作）、信息 #2A6CBE。
- 中性色：页面底 #F5F7FA、卡片 #FFFFFF、分割线 #E5E8EB、次级文字 #5B6570、正文 #1F2328、禁用 #9AA4AF。
- 字体：中文系统字体栈（苹方／思源黑体／微软雅黑），正文 14px、标题 16～20px，行高 1.6。
- 形态：卡片圆角 8px、按钮与输入框圆角 6px、列表行高 44px；状态一律「色块＋文字」双表达。
- 通用禁止（项目层整段继承）：不出现英文界面文字；不出现应用商店、手机 App 图标、小程序外壳；不出现真人照片、第三方品牌标识与真实机构名；不使用大面积渐变、霓虹色、玻璃拟态与 3D 元素；不使用夸张阴影；不出现倒计时、抢购、优惠券等电商化元素；不使用未成年人形象。
- 本版附加禁止：不出现板块、标签、话题、问题、答案、悬赏、积分、等级、私信、通知提醒、审核、举报、会员注销等字样与元素（随后续版本）；不出现支付、红包、现金、会员卡类元素。

四、提示词结构要求
按「画面类型与画布尺寸 → 页面结构分区描述 → 每个分区的元素与文案示例 → 色彩与字体与形态 → 光影与质感 → 负向要求」组织；文案示例用简体中文并逐字取自术语表与上述元素清单。

五、输出
只输出这段生图提示词，并在末尾三行说明：你为谁设计、为什么核心界面是账号与角色管理、这张图承担什么作用。
```

## 2. 第二步：生成并迭代核心界面

```text
按你刚才输出的提示词生成图片。生成后逐项自检并告诉我：核心界面必须元素是否齐全、状态标签是否为「色块＋文字」双表达、主色是否贴近 #2A6CBE、是否有英文文字或本版禁止元素（板块／标签／话题／悬赏／积分等）。
```

迭代方法：逐条提出修改（一次一到两处），满意的核心界面即本版基准；随后与项目层主页基准图并检一次——配色密度、圆角、信息层级与主页一致才算通过（防跨版本风格漂移），不一致处以项目层主页为准修正。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

```text
核心界面已定稿，作为本版基准。请先只输出一份图片清单（不要生成图片），说明每张图的名称、所属端、作用，以及你建议的总数。

覆盖要求（必须满足，来源＝本版 PRD 认领条目 R1～R12）：
- 端与画布：电脑端网页（1440×900）、手机端网页（390×844，网页形态而非 App 外壳）、管理后台（1440×900）。
- 前台界面（会员身份）：
  1) 注册页：账号名、密码、确认密码三项，成功态（提示「注册成功」并进入个人资料页）；异常态必须画出——账号名已存在「账号名已存在，请直接登录」、密码强度不足「密码至少 8 位，且需同时包含字母与数字」、两次不一致「两次输入的密码不一致」。
  2) 登录页：账号名与密码，错误态「账号名或密码错误」（不得区分账号是否存在）、锁定态「失败次数过多，请 10 分钟后再试」。
  3) 个人资料页：昵称（默认＝账号名）、头像（默认头像）、密码修改与重置表单（原密码、新密码、确认新密码）；成功态「密码已修改，请重新登录」；头像超限提示「仅支持 jpg、png、webp，且不超过 2MB」。
  4) 退出确认与登录失效引导态：确认弹窗「确定退出登录？」、过期后访问需登录页面的引导。
- 管理后台界面（账号与角色）：
  5) 管理后台登录页：账号名与密码；停用账号登录被拒「账号不可用，请联系站长」。
  6) 首次登录强制改密页（admin 初始账号与新开通账号共用）：设置新密码。
  7) 账号编辑页与角色分配：备注编辑（账号名只读）、角色多选勾选、两角色并集生效的入口变化示意。
  8) 账号停用／启用与注销：停用确认「停用后该账号将不能登录」、注销二次确认（显示账号名与编号、要求输入「注销」二字、确认按钮不可用态）、已注销行（启用入口消失）。
  9) 角色定义与调整页：角色名、能力点勾选集合；异常态「角色名已存在」「至少勾选一个能力点」。
  10) 个人设置页（站长／运营人员／版主共用）：自身备注与凭据重置；越权拦截态「只能维护自己的账号」。
  11) 空态必须画出：无角色账号登录后的管理后台空态（零管理入口，仅个人设置与退出）、账号列表空态、角色列表空态。
- 机制条目（无界面、不生成图）：能力点判定（随 R10／R11 的机制，无独立界面——其效果以第 7 与第 11 项的入口差异表达）；登录态会话与操作留痕（无人工界面）。
- 界面文字一律逐字取自《术语表（项目）》与本版 PRD 的提示文案，不得自造近义词；通用禁止与本版附加禁止同第一步。

清单确认后，请逐张输出生图提示词（每次一张，结构同核心界面），我确认后再生成。
```

## 4. 第四步：批量生成

```text
按清单顺序逐张生成，每张生成后按同一标准自检：与本版基准一致（配色、圆角、密度、信息层级）、界面文字全中文且与术语表及 PRD 文案一致、无本版禁止元素。有偏差先修正再进入下一张。
```

单张迭代方法：只描述要改的地方与期望效果，一次一到两处，避免整张重写导致风格漂移。

## 5. 收尾：回填归档

图片全部满意后按附 B 逐张登记；如对颜色做了微调，不得在本版定新值——须同步修改项目层脚本附 A（唯一来源）后，本版话术与附 A 复本随之更新。

## 附注 其他生图模型的差异

无对话记忆的模型（如即梦等单次生图工具）无法"先出提示词、再规划清单"：使用时把第 1 步与目标界面要点一次性写进单张提示词，先生成核心界面并与项目层主页基准并检定稿，再逐张生图；附 A 与附 B 用法不变。
