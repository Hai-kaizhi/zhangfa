## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

```text
你是资深 UI 设计师。我已提供《PRD（小版本）v0.4.0》《UI（项目）生图脚本》《术语表（项目）》三份资料（如另附项目 PRD 与技术文档一并参考）。

请先只分析、只输出一段生图提示词，不要生成图片。

一、产品与主端
- 产品：自建自营的社区论坛「巡云轻论坛」，本版为站内往来与关注版本（私信、关注与粉丝、通知提醒已读与清理）。
- 第一张图＝本版核心界面：电脑端网页（画布 1440×900）的「私信往来页」——消息中心内与某位会员的双向往来对话页，本版信息量最大的操作面。
- 界面文字全部为简体中文，用词逐字取自《术语表（项目）》。

二、核心界面必须出现的元素（缺一不可）
- 顶部：站点名「巡云轻论坛」、板块导航、站内搜索入口、登录状态、消息中心入口（带未读角标「3」）。
- 左栏（会话列表）：消息中心的双栏布局——「私信」「通知提醒」两个标签页（当前在「私信」），会话列表按最近往来倒序展示若干会员（昵称、头像、最近一条摘要、时间、未读数字角标）。
- 主区（往来对话）：对方会员昵称与头像、关注状态按钮（「已关注」，可点击取消）；按时间正序展示双方私信气泡（对方左侧浅底、本人右侧主色浅底），其中对方一条带「未读」胶囊标识。
- 输入区：正文输入框（占位文案「输入私信内容，最多 1000 字符」）与「发送」主按钮；输入框下方字数提示「0／1000」。
- 右上提醒条：一条「新私信」通知提醒样式示例（激励信息区外的信息色提示，含发送方昵称摘要）。
- 状态双表达：未读标识一律「色块＋文字」，不靠颜色单独承载语义。
- 不出现任何支付、红包、现金、会员卡类元素。

三、风格锚定（必须严格遵守，引自项目层脚本）
- 主色（品牌蓝）#2A6CBE：顶部导航与主按钮、链接、选中态；按下态 #1F5497；浅底选中 #E8F1FB。
- 副色（激励琥珀）#C97A16：悬赏、积分、等级标识专用；浅底 #FAF1E3。
- 语义色：成功 #15803D（已通过、已采纳、已结算）、警示 #B45309（待审核、待处理）、危险 #B91C1C（驳回、删除、封号）、信息 #2A6CBE。
- 中性色：页面底 #F5F7FA、卡片 #FFFFFF、分割线 #E5E8EB、次级文字 #5B6570、正文 #1F2328、禁用 #9AA4AF。
- 字体：中文系统字体栈（苹方／思源黑体／微软雅黑），正文 14px、标题 16px～20px，行高 1.6。
- 形态：卡片圆角 8px、按钮与输入框圆角 6px、列表行高 44px、头像圆形、标签与状态用胶囊；状态一律「色块＋文字」双表达，不靠颜色单独承载语义。
- 通用禁止：不出现英文界面文字；不出现应用商店、手机 App 图标、小程序外壳；不出现真人照片、第三方品牌标识与真实机构名；不使用大面积渐变、霓虹色、玻璃拟态与 3D 元素；不使用夸张阴影；不出现倒计时、抢购、优惠券等电商化元素；不使用未成年人形象。

四、本版附加禁止
- 不出现个人中心聚合页（我的内容、我的积分与等级等——随 0.5）；不出现关注流或推荐流界面（未纳入）；不出现群聊、多人会话与@ 提醒；不出现实时推送弹层；不出现外部邮件或短信通知；不出现话题与问答界面的任何改动（沿用既有界面）。

五、提示词结构要求
按「画面类型与画布尺寸 → 页面结构分区描述 → 每个分区的元素与文案示例 → 色彩与字体与形态 → 光影与质感 → 负向要求」的顺序组织；文案示例用简体中文并逐字取自《术语表（项目）》与本话术。

六、输出
只输出这段生图提示词，并在末尾用三行说明：你为谁设计、为什么核心界面是私信往来页、这张图承担什么作用。
```

## 2. 第二步：生成并迭代核心界面

```text
按你刚才输出的提示词生成图片。生成后请逐项自检并告诉我：必须元素是否齐全（双栏消息中心、会话列表与未读角标、往来气泡与未读标识、关注按钮、输入框与字数提示）、色值是否贴近主色 #2A6CBE、是否有英文文字或禁止元素。
```

迭代方法：对不满意处逐条提出（如「把未读胶囊改为警示色浅底」「把字数提示移到输入框右下角」），每轮只改一到两处；满意后即本版基准，并与项目层脚本生成的主页基准并检一次——核对配色、圆角、密度与信息层级同源，防跨版本风格漂移。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

```text
核心界面已定稿，作为本版风格基准。请先只输出一份图片清单（不要生成图片），说明每张图的名称、所属端、作用，以及你建议的总数。

覆盖要求（必须满足）：
- 端：本版界面集中在前台——电脑端网页（1440×900）为主，手机端网页（390×844，网页形态而非 App 外壳）至少覆盖消息中心与私信往来页两张（同一站点自适应）；管理后台本版无新增界面。
- 前台必含界面（核心界面已生成，其余按此清单补齐，可合并或拆分并说明理由）：
  1) 消息中心·通知提醒标签页：提醒列表（类型、摘要、时间、未读标识），「全部已读」与「清理全部已读」按钮；已读条目带「清理」操作；空态一——提醒列表为空（清理后）。
  2) 未读清理拦截态：对未读提醒点击清理→危险色提示「未读提醒不可清理」。
  3) 我的关注／我的粉丝页：双标签列表（昵称、头像、粉丝数汇总），按关注时间倒序；空态二——尚未关注任何人；空态三——暂无粉丝。
  4) 关注与取消关注按钮态集：未关注「＋关注」（主色）→ 已关注（浅底）→ 取消确认；拦截态——关注自己时按钮禁用并提示「不能关注自己」。
  5) 私信异常态集：发送方被禁言→发送被拒提示；接收方已注销→拒绝提示；正文超 1000 字符→提示精简；往来空态（空态四）——首次发起私信的输入引导。
  6) 删除私信确认弹层：提示「仅删除你自己一侧的记录，对方不受影响」，确认后本人侧该条消失。
  7) 手机端两张：消息中心（双标签与角标）、私信往来页。
- 无界面声明（不生成图）：「新私信」通知提醒的写入为系统机制（提醒在列表中自然出现）；管理后台无新增界面——标记已读（通知提醒）与清理通知提醒由管理端账号沿用 0.2 个人设置的通知提醒入口操作，不重画；站内搜索、话题、问答等界面沿用既有，不重画。
- 关键信息点：未读标识与角标、粉丝数、字数提示 0／1000、全部已读与清理按钮文案，均按上述文字逐字呈现；界面用词逐字取自《术语表（项目）》与本清单。
- 本版范围外界面不得出现（同第一步附加禁止）。

清单确认后，请逐张输出生图提示词（每次一张，结构同核心界面），我确认后再生成。
```

## 4. 第四步：批量生成

```text
按清单顺序逐张生成，每张生成后按同一标准自检：与本版核心界面基准一致（配色、圆角、密度、信息层级）、界面文字全中文且与术语表一致、无禁止元素。有偏差时先修正再进入下一张。
```

单张迭代方法：只描述要改的地方与期望效果，一次一到两处，避免整张重写导致风格漂移。

## 附注 其他生图模型的差异

无对话记忆的模型（如即梦等单次生图工具）无法「先出提示词、再规划清单」：使用时把第 1 步与实际界面要点一次性写进单张提示词，先只出核心界面并定稿，再把核心界面图作为风格参考图连同第 3 步的覆盖要求逐张生图；附 A 与附 B 的用法不变。
