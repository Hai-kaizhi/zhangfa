# 交付说明：v0.4.0

> 定位：本版（站内往来与关注）开发交付说明——承接《PRD（小版本）v0.4.0》认领条目 R77～R86 的实现与验收自检；本版为文档范本演练，无真实代码产物，运行与证据均为文档范本演练的模拟口径；上游为模拟案例材料，模拟性质予以保留。

## 1. 实现清单（条目｜代码位置｜实现要点）

| 条目 | 代码位置 | 实现要点 |
|---|---|---|
| R77 关注 | 单体应用·互动模块（关注服务）；前台·各会员入口的关注按钮 | 校验非本人（关注自己拒绝并提示）；写入 follow（follower_id＋followed_id 联合唯一，重复请求幂等吸收）；双方列表与粉丝数由关系记录派生即时更新 |
| R78 取消关注 | 单体应用·互动模块（关注服务·取消路径） | 存在关系则删除记录、双方列表同步移除、粉丝数减一；非关注中幂等返回无副作用；粉丝数由关系重算 |
| R79 我的关注 | 前台·我的关注列表页（只读派生视图） | 按关注时间倒序、每页 20 条展示昵称与头像（经会员摘要接口）；空态提示；点击进入对方入口 |
| R80 我的粉丝 | 前台·我的粉丝列表页（只读派生视图） | 按关注时间倒序、每页 20 条展示昵称与头像与粉丝总数；空态提示；列表与计数均由关系重算 |
| R81 发送私信 ◆ | 单体应用·消息模块（私信服务·发送链路）；前台·往来页输入区 | 前置校验链（发送方非禁言非封号→接收方存在且未注销→正文 1～1000 字符），任一不过拒绝且无写入；私信写入与「新私信」通知提醒同一事务（任一失败整体回滚）；接收方未读角标加一；不设好友／关注前置与频率上限（本版定案） |
| R82 查看往来 | 前台·消息中心往来页（双栏，会话列表＋往来区） | 按发送时间正序、每页 20 条展示双方私信，按侧过滤已删除（本人一侧）；未读私信带未读标识；会话列表按最近往来倒序；空态可发起首条私信 |
| R83 标记已读（私信） | 单体应用·消息模块（私信服务·已读路径） | 接收方打开未读私信即置 is_read、未读数派生减一；置位幂等；发送方一侧不变化 |
| R84 删除私信 | 单体应用·消息模块（私信服务·按侧删除路径）；确认弹层 | 按本人身份写 sender_deleted_at 或 receiver_deleted_at（按侧软删除，互不影响）；本人往来不再可见该条；重复删除幂等；不提供恢复 |
| R85 标记已读（通知提醒） | 单体应用·消息模块（提醒服务·已读路径）；前台提醒列表与 0.2 个人设置入口 | 逐条或「全部已读」一次置位（按接收人视角）；未读数相应减少；已读提醒保留列表；查看入口沿用 0.2 界面 |
| R86 清理通知提醒 | 单体应用·消息模块（提醒服务·清理路径） | 仅已读可清理：逐条或「清理全部已读」写入 deleted_at（软删除移出本人列表、业务事实保留）；未读清理拒绝并提示；重复清理幂等；不自动过期 |

范围核对：仅实现 R77～R86；范围外声明（PRD §1）零越界——个人中心聚合面、关注流与推荐、群聊与多人会话、实时推送、外部通知均未出现；管理后台零改动（R85／R86 沿用 0.2 个人设置通知提醒入口）。

## 3. 运行方式

本版为文档范本演练，无真实代码产物；按技术文档（项目）口径的运行形态如下（模拟叙述）：

1. 环境：单体应用（Java＋Spring Boot，内含前台与管理后台 Vue 静态资源）单实例部署，MySQL 数据库。
2. 升级顺序：先执行数据库升级（新建 follow、private_message 两表，notification 表增列 deleted_at，字段按 PRD §5 与术语表 §7）→ 部署应用（前台新增消息中心与我的关注／我的粉丝入口；关注按钮出现在各会员入口）→ 按 PRD 完成标志两条路径演练验收。
3. 依赖说明：账号状态校验调用 0.1 已交付的会员与权限模块；「新私信」提醒经 0.2 通知提醒统一写入机制；未读角标为进入页面拉取（不做实时推送，K 沿用）。

## 4. 已知限制与待确认

- 本版为文档范本演练：无真实代码产物，全部证据为模拟证据（界面叙述、接口叙述、日志行），不构成真实运行事实（模拟性质承接）。
- 范围外承接：个人中心聚合面与注销随 0.5（「接收方为已注销账号拒绝发送」的注销路径随 0.5，本版接口校验先行；各列表入口随 0.5 汇聚为个人中心）；关注流的排序与推荐未纳入（暂缓清单）；实时长连接推送、群聊与外部通知不做（K·明确不采用）。
