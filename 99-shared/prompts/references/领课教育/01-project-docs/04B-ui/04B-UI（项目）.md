# 领课教育 · UI 生图脚本

> 本文档是「领课教育」的 UI 生图脚本：**生图提示词由对话中的 GPT 撰写**，本文档只给「资料清单」与「可直接复制的话术」，以及 GPT 必须遵循的风格锚定（色板、字体、组件形态、通用禁止）；主流程＝GPT 同一对话 ＋ GPT-image。上游为模拟案例，模拟性质保留。

## 0. 准备：给 GPT 哪些资料

| 资料 | 位置 | 必给／可选 |
|---|---|---|
| 原始需求（需求方业务构想） | `00-inputs/01-原始需求.md` | 必给 |
| 概念文档（项目） | `01-project-docs/01-concept/01-概念文档（项目）.md` | 必给 |
| PRD（项目） | `01-project-docs/02-prd/02-PRD（项目）.md` | 必给 |
| 技术文档（项目）（前端组件库选型） | `01-project-docs/03-tech-doc/03-技术文档（项目）.md` | 可选（用于主题令牌映射：Element Plus） |
| 已有界面截图或参考图 | 使用者自备 | 可选 |

**主端判定**：本项目主端为**学员端**（门户网页）——产品最终服务的使用方所在端，也承载最完整的核心业务闭环；第一张图从学员端主页开始。

## 1. 第一步话术：让 GPT 产出主页（第一张图）的生图提示词

> 复制下面整段发给 GPT（资料已在上文给过）：

```
你是资深 UI/UX 设计师，精通中文界面设计与生图提示词撰写。

我先给你一份在线教育系统的产品资料（原始需求、概念文档、PRD，可能还有技术文档）。请先通读，只做理解，不要生成任何图片。

任务：为这个产品的【学员端（面向学员的门户网页）主页】撰写第一张图的生图提示词。

一、这张图必须包含的元素（学员端主页）：
- 顶部：站点标识与名称、主导航（首页／课程／我的课程／我的订单）、搜索框、登录／注册入口
- 首屏：推荐位（课程推荐卡片组，含课程封面、课程标题、讲师名、价格）
- 分类区：课程分类入口（横向分类导航）
- 继续学习区：已登录状态下展示「我的课程」最近学习的课程卡片与学习进度
- 页脚：站点基础信息与帮助入口

二、全局风格锚定（必须严格遵守，不得自行改色）：
- 产品气质：可信、清晰、有学习氛围的在线教育平台；界面克制、信息层级清楚，不花哨
- 主色（品牌色）：#0056D2（用于主按钮、选中态、链接与关键强调）
- 副色／点缀色：#03C7E8（仅用于进度条、数据可视化与轻量强调，不用于大面积背景）
- 中性色：页面底 #F5F6F8；卡片与内容底 #FFFFFF；标题文字 #1C1D1F；正文 #454545；辅助文字 #707070；分隔线与描边 #E1DDDB
- 语义色：成功 #0D7D4D；警告 #D6B600；危险 #AB0D02；信息 #00688D
- 色板配比：中性色承担 80% 以上面积，主色用于操作与强调，点缀色占比不超过 5%
- 字体：中文无衬线（PingFang SC／Microsoft YaHei／Noto Sans CJK SC），数字与拉丁用 Inter；标题与正文层次靠字重与字号，不靠颜色堆叠
- 组件形态：卡片圆角 8px、按钮圆角 6px、输入框圆角 6px；描边 1px；阴影克制（仅用于浮层），不用大面积渐变色与发光效果
- 无障碍：正文文字与背景对比度不低于 4.5:1；不使用在白底上对比不足的浅色文字

三、通用禁止（任何一张图都不允许出现）：
- 全中文界面（不得出现英文界面文案与英文占位词）；只允许极少量数字与金额
- 不出现第三方品牌标识、平台水印、二维码、联系方式
- 不出现真实人物照片、真实机构名与真实版权课程名（本项目为模拟案例，课程与讲师名为虚构）
- 不出现直播、在线考试与题库、任务打卡与积分证书、社区问答与博文等本期不做功能的入口
- 不出现手机 App 与小程序界面形态（本产品三端均为网页形态）
- 不出现机构端与讲师端的界面元素混入学员端
- 不使用深色模式与高饱和撞色，不使用拟物与 3D 装饰元素

四、输出要求：
1. 先只输出**生图提示词本身**，不要生成图片。
2. 提示词用中文撰写，结构为：画面类型与宽高比 → 页面结构与区块顺序 → 各区块的界面元素与文案 → 整体风格锚定（色值、字体、组件形态）→ 禁止项。
3. 宽高比：桌面端 16:10（1440×900 视口）。
4. 界面文字直接写进提示词（生图模型的文字渲染不可靠，我会在生图后逐处校正）。
5. 先只给我这一张（主页）的提示词，等我确认后再生图；不要提前规划其他页面。
```

## 2. 第二步：生成并迭代主页

> 拿到提示词后复制下面这句：

```
请按上面的提示词生成图片。生成后请对照提示词自检：区块是否齐全、色值是否按锚定执行、界面文字是否可读且无英文、是否有被禁止的元素。列出偏差，并给出修正后的提示词。
```

迭代方法：

1. 每次只改一处（区块、色值、文案），避免一次改多项后分不清哪次变动生效。
2. 满意的主页即为**全局风格基准**：后续所有图片都以它为准，不重新定义色板与组件形态。
3. 生图必然色偏：图片像素取色仅作参考，**色值以本文档附 A 为唯一来源**（代码层按附 A 实现）。
4. 主页若出现本期不做功能的入口或英文字样，直接判为不合格并要求重出，不要手动修补。

## 3. 第三步话术：规划其余图片并逐张撰写提示词

> 主页定稿后复制下面整段：

```
主页已定稿，它现在是整个产品的风格基准：色板、字体层次、组件形态一律以它为准，不得改变。

请规划其余需要出图的界面，并按覆盖要求逐张撰写生图提示词。

一、覆盖要求（必须全部覆盖，一张图或一组图覆盖一项）：
1. 学员端（桌面 16:10）：首页（已有）、课程分类与搜索结果列表、课程详情（课程介绍／讲师介绍／目录／价格与购买按钮）、我的课程与课时播放页（含学习进度）、学习记录、我的订单、个人中心（资料与密码）
2. 学员端（手机 9:19.5，390×844）：首页与课程详情两项，验证手机浏览器的适配形态
3. 讲师端（桌面 16:10）：讲师工作台首页、入驻申请页、我的课程列表、课程编辑（课时与附件资料维护）、讲师信息维护页、个人中心（资料与密码）、课程收益页
4. 机构端（桌面 16:10，PC 管理后台）：登录页、账号与角色授权、站点与对接参数配置、课程分类管理、讲师入驻审核（含审核意见）、课程审核、订单管理与统计、个人设置
5. 状态与异常态（可合入对应界面图，也可单独出图）：课程状态标记（草稿／待审核／未通过／已发布／已下架）、审核意见展示、空态（无课程／无订单／无学习记录）、无学习资格时的播放页提示、待支付与支付失败提示

二、各界面的关键信息点（必须画出来）：
- 学员端所有课程卡片：课程标题、讲师名、价格；已购课程另标学习进度
- 课程详情：讲师介绍区、课程目录（课时清单）、价格与购买按钮，未登录与已登录两种状态可任选其一并标注
- 讲师端课程列表：每行显示课程状态与最近一次审核意见
- 讲师端收益页：按课程分组的收益数字与时间范围筛选
- 机构端审核页：申请／课程信息、审核通过与不通过两个操作、审核意见输入
- 机构端订单管理与统计：订单列表（订单编号、课程、学员、金额、状态、支付时间）与统计区（成交金额与订单量）
- 机构端账号与角色授权：账号列表与角色授予界面

三、宽高比：桌面端一律 16:10（1440×900）；学员端手机图 9:19.5（390×844）。管理后台与工作台为 PC 网页形态，不做手机形态。

四、输出顺序要求：
1. 先给出**图片清单**：每张图一行（图名／所属端／作用／宽高比），并说明总数与顺序理由，等我确认。
2. 确认后再**逐张输出生图提示词**（一次一张，结构同主页那张：画面类型与宽高比 → 页面结构 → 元素与文案 → 风格锚定 → 禁止项），不要一次输出全部。
3. 全部遵循主页的风格锚定与通用禁止；不得引入新的色值。
```

## 4. 第四步：批量生成

> 清单确认后，逐张复制：

```
按这张的提示词生成图片。生成后自检并列出偏差：区块是否齐全、色值是否与风格锚定一致、文字是否全中文、是否出现被禁止的元素；有偏差时给出修正后的提示词。
```

单张迭代方法：只改一句话（改区块／改色／改文案），每次生成后与主页并排比对风格一致性；连续两次仍偏离时，回到提示词层面重写该区块描述，而不是继续叠加修正语。

## 5. 收尾：回填归档

1. 把每张图的最终结果与偏差填写到**附 B 生图回填区**。
2. 若生图过程中对色值做了微调（只允许微调明度），同步更新**附 A** 的色值表与主题令牌映射，确保代码层与设计同源。
3. 界面文案以本文档与 PRD 的用词为准：生图模型的界面文字不可靠，出图后逐处校正为术语表登记的称谓（学员／讲师／机构、我的课程、讲师工作台等）。

## 附注 其他生图模型的差异

对无对话记忆的模型（如即梦等）：把本文档第 1 步话术中的「风格锚定」与「通用禁止」两段原文，连同 GPT 已写好的单张生图提示词，拼成一段一次性提交；每张图都重复带上风格锚定，避免模型自行改色。第 3 步的「让 GPT 规划清单」改为人工按覆盖要求逐项对照，仍遵守「数量与顺序由规划结果说明、不写死」的原则。
