## 3. 运行方式

（文档范本演练口径的模拟叙述，随真实代码交付后按此执行）

1. 数据初始化：无新增表与字段（统计模块为派生查询，依赖 v0.6.0／v0.6.1 的订单、支付记录、学习记录表）；建议确认订单表 `paid_at` 与状态字段有索引以支撑区间聚合。
2. 后端：Spring Boot 可执行服务启动（统计模块随模块化单体首次加载）；机构端能力点配置确认「订单统计」授予机构管理员与机构运营人员、「课程收益」授予机构管理员（讲师收益随讲师身份自带）。
3. 前端：学员端 `web-portal`（个人中心记录入口）、机构端 `web-admin`（订单统计与收益）、讲师端 `web-teacher`（收益页，导航新增）分别构建／启动。
4. 验证路径：学员走「个人中心→我的订单→详情与待支付续付／学习记录→续学」；机构走「订单统计（默认与自定义、超限拦截、取消扣除核对）→收益对照」；讲师走「收益页＋越权分支」；按第 2 节证据口径逐条复现，重点交叉核对同一课程在订单统计与两侧收益中的金额一致。

## 4. 已知限制与待确认

1. 统计以查询时点实时计算、不做预聚合（04C-统计 2.5 沿用）——大订单量下的查询性能优化（预聚合缓存）随规模需要回池评估；单次查询跨度上限 1 年已限流。
2. 统计导出本版不排期（回池评估）；收益只做呈现、不做结算（暂缓清单）；统计维度扩展（按讲师、按周／月）建议已回池。
3. 已知限制（PRD 第 6 章拍板值随版携带）：学习记录页进入课程由 0.6「继续学习」高亮承接（不按最近课时直达——直达建议已回池）；机构运营人员无收益视角（路线图口径）。
4. 待确认（沿用 PRD 待议，不影响本版验收）：机构代查过渡退出后的客服口径；统计默认区间的业务接受度。
5. 术语表待登记清单已随本版 PRD 第 6 章回报（新登记「订单统计视图」不落库派生查询视图；全部落库字段沿用零新增），以主流程合入为准。
