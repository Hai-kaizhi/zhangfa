# 领课教育 v0.1.0 · UI 生图脚本（小版本）

> 本文档是 v0.1.0（学员账号与登录基座）的 UI 生图脚本：**生图提示词由对话中的 GPT 撰写**，本文档只给资料清单与可复制的话术；风格锚定（色板、字体、组件形态、通用禁止、令牌映射）**整段沿用项目层脚本、不在本版重新拍板**（唯一来源：《UI（项目）》附 A）；覆盖只圈本版认领条目（R1～R5）触及的界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质保留。

## 0. 准备：给 GPT 哪些资料

| 资料 | 位置 | 必给／可选 |
|---|---|---|
| PRD（小版本）：v0.1.0 | `04-workspace/v0.1.0/01-PRD（小版本）.md` | 必给 |

**本版核心界面判定**：注册页——本版信息点最多的操作面（手机号／密码／确认密码／昵称＋逐项校验反馈），第一张图从它开始。

## 1. 第一步话术：让 GPT 产出本版核心界面（注册页）的生图提示词

> 复制下面整段发给 GPT（资料已在上文给过）：

```
你是资深 UI/UX 设计师，精通中文界面设计与生图提示词撰写。

我给你一份在线教育系统的小版本 PRD（v0.1.0 学员账号与登录基座）、项目层 UI 脚本与术语表。请先通读，只做理解，不要生成任何图片。

任务：为【学员端·注册页】撰写第一张图的生图提示词。

一、这张图必须包含的元素（信息点逐条来自 PRD）：
- 页面结构：站点标识与名称（顶部）、注册表单卡片（居中）、底部「已有账号？直接登录」入口
- 表单字段：手机号（11 位）、密码（8～20 位，须同时包含字母和数字）、确认密码、昵称（选填，≤20 个字符）、注册按钮
- 字段级校验反馈示例（必须画出至少一组错误态）：「请输入正确的手机号」「两次输入的密码不一致」
- 拦截态提示示例：「该手机号已注册，请直接登录」
- 昵称字段旁辅助说明：「未填写将自动生成默认昵称」
- 页面为桌面端网页，手机浏览器可用（自适应）

二、风格锚定（整段沿用项目层脚本，必须严格遵守，不得自行改色、不得引入新色值）：
- 产品气质：可信、清晰、有学习氛围的在线教育平台；界面克制、信息层级清楚，不花哨
- 主色（品牌色）：#0056D2（用于主按钮、选中态、链接与关键强调）
- 副色／点缀色：#03C7E8（仅用于进度条、数据可视化与轻量强调，不用于大面积背景）
- 中性色：页面底 #F5F6F8；卡片与内容底 #FFFFFF；标题文字 #1C1D1F；正文 #454545；辅助文字 #707070；分隔线与描边 #E1DDDB
- 语义色：成功 #0D7D4D；警告 #D6B600；危险 #AB0D02（错误提示用）；信息 #00688D
- 色板配比：中性色承担 80% 以上面积，主色用于操作与强调，点缀色占比不超过 5%
- 字体：中文无衬线（PingFang SC／Microsoft YaHei／Noto Sans CJK SC），数字与拉丁用 Inter
- 组件形态：卡片圆角 8px、按钮圆角 6px、输入框圆角 6px；描边 1px；阴影克制（仅用于浮层），不用大面积渐变色与发光效果
- 无障碍：正文文字与背景对比度不低于 4.5:1

三、通用禁止（整段继承项目层，任何一张图都不允许）：
- 全中文界面，不得出现英文界面文案与英文占位词；只允许极少量数字
- 不出现第三方品牌标识、平台水印、二维码、联系方式
- 不出现真实人物照片、真实机构名与真实版权课程名（本项目为模拟案例）
- 不使用深色模式与高饱和撞色，不使用拟物与 3D 装饰元素

四、本版附加禁止（v0.1.0 范围外界面不得出现）：
- 不出现课程、订单、学习记录、我的课程、搜索等业务界面与字样（课程相关随后续版本）
- 不出现机构端（管理后台）与讲师端界面元素
- 不出现「找回密码」「手机验证码」「第三方登录（微信／QQ 等）」入口（本版无此能力）
- 不出现手机号修改入口（本版手机号只读）

五、输出要求：
1. 先只输出**生图提示词本身**，不要生成图片。
2. 提示词用中文撰写，结构为：画面类型与宽高比 → 页面结构与区块顺序 → 各区块的界面元素与文案 → 整体风格锚定（色值、字体、组件形态）→ 禁止项。
3. 宽高比：桌面端 16:10（1440×900 视口）。
4. 界面文字直接写进提示词（生图文字渲染不可靠，出图后我会逐处校正为 PRD 文案）。
5. 先只给我这一张（注册页）的提示词，等我确认后再生图；不要提前规划其他页面。
```

## 2. 第二步：生成并迭代核心界面

> 拿到提示词后复制下面这句：

```
请按上面的提示词生成图片。生成后自检：字段与提示文案是否齐全、色值是否按风格锚定执行、界面文字是否全中文且无范围外元素（课程／机构端／第三方登录等）。列出偏差，并给出修正后的提示词。
```

迭代方法（验收三问）：① 字段与校验反馈是否与 PRD 逐条对得上；② 色值是否与风格锚定一致（以项目层附 A 为准，不照图取色）；③ 是否出现本版附加禁止中的元素。每次只改一处；满意后即本版基准，并与项目层主页基准并检一次（并排比对风格是否漂移，发现漂移以项目层基准为准修正）。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 核心界面定稿后复制下面整段：

```
注册页已定稿，是本版风格基准；全局风格仍以项目层脚本为唯一来源。

请规划本版（v0.1.0）其余需要出图的界面。覆盖要求如下——每条认领条目的操作面、每张异常与拦截态、每个空态边界都要有对应界面；机制条目无界面不生成。

一、界面覆盖要求（来自 PRD R1～R5）：
1. 登录页（R2）：手机号＋密码表单、登录按钮、「还没有账号？去注册」入口；异常态：凭据错误提示「手机号或密码错误」、锁定提示「尝试次数过多，请 15 分钟后再试」、停用提示「账号已停用，请联系机构」
2. 个人中心·个人资料页（R3）：昵称（必填）、邮箱（选填）、手机号（只读展示）、学员编号（只读展示、不可修改）、保存按钮；成功提示「保存成功」；错误态：「昵称不能超过 20 个字符」「请输入正确的邮箱地址」；空态／边界：昵称为默认昵称「学员＋编号后 4 位」的展示形态
3. 个人中心·修改密码页（R4）：原密码、新密码、确认新密码、提交按钮；错误态：「原密码不正确」「新密码不能与原密码相同」「两次输入的密码不一致」；成功后跳转登录页的引导态「密码已修改，请重新登录」
4. 会话过期态（R2／R5 边界）：登录后停留页面出现过期提示并引导至登录页的形态
5. 机制条目声明：R5 登录鉴权与按端隔离为服务端机制，无界面、不生成图（跨端拦截在接口层，不需要界面图）

二、各界面关键信息点：表单字段、必填标记、字段级错误提示文案、按钮文案一律按 PRD 第 4 章逐字转译；提示文案中的等待时长（15 分钟）必须画出。

三、宽高比：桌面端 16:10（1440×900）；每个界面另出一张手机浏览器形态 9:19.5（390×844）验证自适应，由你在清单中合并或单列并说明。

四、输出顺序要求：
1. 先给出**图片清单**（图名／所属界面／作用／宽高比），说明总数与顺序理由，等我确认。
2. 确认后逐张输出生图提示词（一次一张，结构同注册页那张），不要一次输出全部。
3. 全部沿用注册页的风格锚定与通用禁止、本版附加禁止；不得引入新的色值。
```

## 4. 第四步：批量生成

> 清单确认后逐张复制：

```
按这张的提示词生成图片。生成后自检并列出偏差：信息点是否齐全、色值是否与风格锚定一致、文案是否全中文、是否出现本版范围外元素；有偏差时给出修正后的提示词。
```

单张迭代方法：只改一句话（改区块／改色／改文案），每次生成后与注册页基准并排比对；连续两次仍偏离时重写该区块描述，不叠加修正语。

## 5. 收尾：回填归档

1. 把每张图的最终结果与偏差填写到**附 B 生图回填区**。
2. 色彩微调只允许发生在项目层脚本附 A（唯一来源）——本版脚本随之同步更新，本版不得私自改色值。
3. 界面文案以本版 PRD 与术语表为准（学员、学员端、个人中心、学员编号等称谓逐字沿用），出图后逐处校正。

## 附注 其他生图模型的差异

对无对话记忆的模型（如即梦等）：把第 1 步话术中的「风格锚定」与「通用禁止／本版附加禁止」两段原文，连同 GPT 已写好的单张生图提示词拼成一段一次性提交；每张图都重复带上风格锚定。第 3 步的「让 GPT 规划清单」改为人工按覆盖要求逐项对照（界面 1～5＋手机形态），仍不写死总数。
