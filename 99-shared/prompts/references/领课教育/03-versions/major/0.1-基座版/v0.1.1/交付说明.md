## 1. 实现清单（条目｜代码位置｜实现要点）

| 条目 | 代码位置 | 实现要点 |
|---|---|---|
| R6 登录控制 ◆ | 后端：账号与权限模块 `admin` 包 `POST /api/admin/login`、会话占用标记组件；前端：机构端 `views/login` 与被踢提示拦截 | 登录成功按「账号＋端」更新占用标记（`session_occupation`），使既有会话失效；登录、退出、改密、停用四处更新占用标记（04C 3.6）；首登／重置后强制改密页；失败 5 次锁 15 分钟、会话 7 天（沿用 0.1 默认值） |
| R7 能力点校验 | 后端：鉴权过滤器在 R5 鉴权之后的能力点校验层＋注解声明；前端：机构端导航与操作按能力点显隐 | 按所持角色的 `capabilities` 集合判定；授权变更下一次请求即生效；个人设置不属能力点；服务端为准（前端隐藏不作边界） |
| R8 账号开通 ◆ | 后端：`POST /api/admin/accounts`；前端：机构端 `views/account`（开通表单）；数据：`admin_account` | 姓名／手机号／初始密码校验；手机号唯一（唯一索引兜底）；开通即 `opened` 状态＋`opened_by` 留痕同事务；生成机构端账号编号（`AD`＋6 位） |
| R9 角色授权 ◆ | 后端：`PUT /api/admin/accounts/{id}/roles`；前端：账号管理授权弹层；数据：`admin_account_role`、`admin_role` | 授予／收回写关联（`granted_by`／`granted_at` 留痕）同事务；即时生效；收回至零个角色账号退回 `opened`；停用账号不可授权；重复授予幂等 |
| R10 账号停用 | 后端：`POST /api/admin/accounts/{id}/disable`；前端：停用确认弹层 | 二次确认；停用同事务解除全部关联（留痕）＋`disabled_by`／`disabled_at`＋既有会话失效；不可停用自己；终态不可恢复 |
| R11 账号资料与凭据重置 | 后端：`PUT /api/admin/profile`（自助）、`POST /api/admin/accounts/{id}/reset-credential`（重置）；前端：`views/settings` 与重置弹层 | 自助仅限本人（姓名＋改密，原密码校验、改密后会话失效）；管理员重置他人凭据（不可重置自己），重置后旧凭据失效、下次登录强制改密 |

数据落地：`admin_account`（`no`／`mobile`／`password`／`name`／`status`／`opened_by`／`disabled_by`／`disabled_at`／`created_at`／`updated_at`）、`admin_role`（预置两行：机构管理员、机构运营人员；`name`／`description`／`capabilities`）、`admin_account_role`（`admin_account_id`＋`admin_role_id` 组合唯一、`granted_by`／`granted_at`），命名与 PRD 第 5 章及术语表逐字一致；会话存 Redis（`side=admin`＋`session_occupation` 占用标记）。系统预置：初始化脚本写入预置角色与首个机构管理员账号（首登强制改密）。

## 3. 运行方式

- 后端：账号与权限模块随单后端应用启动（连 MySQL 与 Redis）；执行数据库迁移脚本建 `admin_account`、`admin_role`、`admin_account_role` 三表与 `mobile`、组合唯一索引；执行初始化脚本写入预置角色（机构管理员、机构运营人员及能力点集合）与首个机构管理员账号（首登强制改密）。
- 前端：机构端工程本地 `dev` 启动或 `build` 部署（登录、强制改密、账号管理、个人设置路由）。
- 验证路径：预置管理员首登改密 → 开通账号 → 授权 → 新账号首登改密并按角色使用 → 第二处登录踢下线 → 停用（即 PRD 旅程一遍）。
