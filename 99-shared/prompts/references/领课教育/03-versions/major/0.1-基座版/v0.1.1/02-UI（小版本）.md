> 本文档是 v0.1.1（机构端账号与权限）的 UI 生图脚本：**生图提示词由对话中的 GPT 撰写**，本文档只给资料清单与可复制的话术；风格锚定（色板、字体、组件形态、通用禁止、令牌映射）**整段沿用项目层脚本、不在本版重新拍板**（唯一来源：《UI（项目）》附 A）；覆盖只圈本版认领条目（R6～R11）触及的机构端界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质保留。

**本版核心界面判定**：机构端·账号管理页——本版信息量最多的操作面（账号列表＋状态标签＋开通／授权／停用／重置四类操作入口），第一张图从它开始。

## 1. 第一步话术：让 GPT 产出本版核心界面（账号管理页）的生图提示词

> 复制下面整段发给 GPT（资料已在上文给过）：

```
你是资深 UI/UX 设计师，精通中文界面设计与生图提示词撰写。

我给你一份在线教育系统的小版本 PRD（v0.1.1 机构端账号与权限）、项目层 UI 脚本与术语表。请先通读，只做理解，不要生成任何图片。

任务：为【机构端·账号管理页】撰写第一张图的生图提示词。

一、这张图必须包含的元素（信息点逐条来自 PRD）：
- 页面结构：PC 管理后台布局——左侧导航（账号管理、个人设置；按能力点显隐）、顶部站点与账号信息（含退出入口）、右侧内容区
- 内容区：账号管理列表＋「开通账号」主按钮
- 列表列：机构端账号编号（AD＋6 位）、姓名、手机号、所持角色、状态标签、操作
- 状态标签三种形态（必须画出）：已开通（未授权）／已授权／已停用
- 操作列按角色能力点显隐：授权、停用、重置凭据（机构管理员可见）；示例行中至少一行展示无操作按钮的形态（能力点不足）
- 空态（必须画出）：列表无账号时显示「暂无账号，点击开通账号开始」
- 开通账号表单（弹层或右侧抽屉，二选一并在提示词中说明）：姓名（2～20 个字符）、手机号（11 位）、初始密码（8～20 位且同时包含字母和数字）、提交与取消
- 表单错误态（必须画出至少一组）：「该手机号已被占用，请更换」

二、风格锚定（整段沿用项目层脚本，必须严格遵守，不得自行改色、不得引入新色值）：
- 产品气质：可信、清晰、有学习氛围的在线教育平台；机构端为 PC 管理后台，界面克制、信息层级清楚
- 主色（品牌色）：#0056D2（用于主按钮、选中态、链接与关键强调）
- 副色／点缀色：#03C7E8（仅用于进度与可视化，不用于大面积背景）
- 中性色：页面底 #F5F6F8；卡片与内容底 #FFFFFF；标题文字 #1C1D1F；正文 #454545；辅助文字 #707070；分隔线与描边 #E1DDDB
- 语义色：成功 #0D7D4D（已授权状态标签）；警告 #D6B600（已开通（未授权）状态标签）；危险 #AB0D02（已停用状态标签与危险操作）；信息 #00688D
- 色板配比：中性色承担 80% 以上面积，主色用于操作与强调，点缀色占比不超过 5%
- 字体：中文无衬线（PingFang SC／Microsoft YaHei／Noto Sans CJK SC），数字与拉丁用 Inter；表格数字启用等宽
- 组件形态：卡片圆角 8px、按钮圆角 6px、输入框圆角 6px；描边 1px；阴影克制（仅用于浮层弹层）；不用大面积渐变与发光
- 无障碍：正文文字与背景对比度不低于 4.5:1

三、通用禁止（整段继承项目层，任何一张图都不允许）：
- 全中文界面，不得出现英文界面文案与英文占位词；只允许极少量数字与编号（如 AD000001）
- 不出现第三方品牌标识、平台水印、二维码、联系方式
- 不出现真实人物照片、真实机构名（本项目为模拟案例）
- 不使用深色模式与高饱和撞色，不使用拟物与 3D 装饰元素

四、本版附加禁止（v0.1.1 范围外界面不得出现）：
- 不出现课程、订单、站点配置、讲师审核、分类、统计等业务导航与界面（随 0.2 及以后版本）——左侧导航只有账号管理与个人设置
- 不出现学员端元素（注册入口、课程卡片）与讲师端元素
- 不出现角色的自定义编排／新增角色界面（本版角色仅预置两个）
- 不出现「启用／恢复已停用账号」入口（停用为终态）

五、输出要求：
1. 先只输出**生图提示词本身**，不要生成图片。
2. 提示词用中文撰写，结构为：画面类型与宽高比 → 页面结构与区块顺序 → 各区块的界面元素与文案 → 整体风格锚定（色值、字体、组件形态）→ 禁止项。
3. 宽高比：PC 管理后台 16:10（1440×900 视口）。
4. 界面文字直接写进提示词（生图文字渲染不可靠，出图后我会逐处校正为 PRD 文案）。
5. 先只给我这一张（账号管理页）的提示词，等我确认后再生图；不要提前规划其他页面。
```

## 2. 第二步：生成并迭代核心界面

> 拿到提示词后复制下面这句：

```
请按上面的提示词生成图片。生成后自检：列表列与状态标签三种形态是否齐全、操作列能力点显隐是否有示例、开通表单字段与错误提示是否与 PRD 一致、色值是否按风格锚定执行、界面文字是否全中文且无范围外元素（课程／站点配置／学员端等）。列出偏差，并给出修正后的提示词。
```

迭代方法（验收三问）：① 列表列、状态标签、操作与表单信息点是否与 PRD 逐条对得上；② 色值是否与风格锚定一致（以项目层附 A 为准，不照图取色）；③ 是否出现本版附加禁止中的元素。每次只改一处；满意后即本版基准，并与项目层主页基准并检一次（并排比对风格是否漂移，发现漂移以项目层基准为准修正）。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 核心界面定稿后复制下面整段：

```
账号管理页已定稿，是本版风格基准；全局风格仍以项目层脚本为唯一来源。

请规划本版（v0.1.1）其余需要出图的机构端界面。覆盖要求如下——每条认领条目的操作面、每张异常与拦截态、每个空态边界都要有对应界面；机制条目无独立界面不生成。

一、界面覆盖要求（来自 PRD R6～R11）：
1. 机构端登录页（R6）：手机号＋密码表单、登录按钮；异常态：「手机号或密码错误」「尝试次数过多，请 15 分钟后再试」「账号已停用，请联系机构管理员」
2. 强制修改密码页（R6／R8／R11 边界）：首次登录或凭据被重置后进入；新密码＋确认新密码；提示「首次登录请修改初始密码」
3. 被挤下线提示态（R6）：第一处会话失效后的提示「登录状态已失效，请重新登录」与返回登录页引导
4. 角色授权弹层（R9）：预置角色多选（机构管理员、机构运营人员）、当前授予态；收回全部角色的二次确认「收回全部角色后该账号将仅剩个人设置，确认？」
5. 停用确认弹层（R10）：「停用后该账号立即无法登录且不可恢复，确认停用？」；拦截态：「不能停用当前登录账号」
6. 重置凭据弹层（R11）：设置新初始密码；已停用账号行无此入口
7. 个人设置页（R11 自助）：姓名（可改）、手机号（只读）、修改密码（原密码＋新密码＋确认新密码）；错误态：「原密码不正确」「新密码不能与原密码相同」
8. 能力点显隐形态（R7 机制的表现，必须画出）：机构运营人员角色登录后同一后台的形态——左侧仅个人设置、无账号管理入口；其调用无权限能力时提示「无权限」的拦截态
9. 机制条目声明：R7 能力点校验为服务端机制，无独立界面、不单独生成图（其表现以上述显隐与拦截态呈现）
10. 空态：账号管理空列表（若第一张图未含，需单独一张）

二、各界面关键信息点：表单字段、必填标记、字段级错误提示、二次确认文案、状态标签文案一律按 PRD 第 4 章逐字转译；等待时长（15 分钟）与「不可恢复」字样必须画出。

三、宽高比：全部为 PC 管理后台 16:10（1440×900）；本版无手机形态。

四、输出顺序要求：
1. 先给出**图片清单**（图名／所属界面／作用／宽高比），说明总数与顺序理由，等我确认。
2. 确认后逐张输出生图提示词（一次一张，结构同账号管理页那张），不要一次输出全部。
3. 全部沿用账号管理页的风格锚定与通用禁止、本版附加禁止；不得引入新的色值。
```

## 4. 第四步：批量生成

> 清单确认后逐张复制：

```
按这张的提示词生成图片。生成后自检并列出偏差：信息点是否齐全、色值是否与风格锚定一致、文案是否全中文、是否出现本版范围外元素；有偏差时给出修正后的提示词。
```

单张迭代方法：只改一句话（改区块／改色／改文案），每次生成后与账号管理页基准并排比对；连续两次仍偏离时重写该区块描述，不叠加修正语。

## 5. 收尾：回填归档

1. 把每张图的最终结果与偏差填写到**附 B 生图回填区**。
2. 色彩微调只允许发生在项目层脚本附 A（唯一来源）——本版脚本随之同步更新，本版不得私自改色值。
3. 界面文案以本版 PRD 与术语表为准（机构管理员、机构运营人员、机构端账号编号、已开通（未授权）／已授权／已停用等称谓与状态逐字沿用），出图后逐处校正。

## 附注 其他生图模型的差异

对无对话记忆的模型（如即梦等）：把第 1 步话术中的「风格锚定」与「通用禁止／本版附加禁止」两段原文，连同 GPT 已写好的单张生图提示词拼成一段一次性提交；每张图都重复带上风格锚定。第 3 步的「让 GPT 规划清单」改为人工按覆盖要求逐项对照（界面 1～10），仍不写死总数。
