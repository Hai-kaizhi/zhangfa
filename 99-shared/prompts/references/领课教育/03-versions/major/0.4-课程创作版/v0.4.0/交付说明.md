## 3. 运行方式

（文档范本演练口径的模拟叙述，随真实代码交付后按此执行）

1. 数据初始化：MySQL 执行 `sql/v0.4.0/course.sql` 建 `course` 表（既有库执行增量脚本即可；`course_order`／`study_record` 随 0.6 建表，本版引用拦截查询按表存在性守卫）；Redis 与登录态配置沿用 0.3.1。
2. 后端：Spring Boot 可执行服务启动（课程模块随模块化单体一并加载），按 04A 开发规范的运行配置连接数据库与缓存。
3. 前端：讲师端 `web-teacher` 与机构端 `web-admin` 分别以 Vite 构建／启动，组件库 Element Plus 主题令牌按项目层 UI 脚本附 A 落值。
4. 验证路径：以讲师账号（讲师端）走「我的课程→新建课程→详情→编辑→删除」，以机构管理员与机构运营人员账号（机构端）核对课程列表与删除权限差异；失败分支按第 2 节证据口径逐条复现。

## 4. 已知限制与待确认

1. 引用拦截在本版正常使用中不触发（订单与学习记录随 0.6 产生），拦截提示仅经构造数据验证（规则就绪口径，同 PRD 4.5）。
2. 已知限制（PRD 第 6 章拍板值随版携带）：课程列表无筛选条件（建议已回池）；无封面图；讲师创建数量与频率无上限；归属分类不强制二级叶子。
3. 待确认（沿用 PRD 待议，不影响本版验收）：课程是否必须挂二级叶子分类；价格是否改为整数直接录入。
4. 术语表待登记清单已随本版 PRD 第 6 章回报（`price`／`category_id`／`teacher_id` 新增，`name`／`intro`／`deleted_at` 扩展适用对象），以主流程合入为准。
