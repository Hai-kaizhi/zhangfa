## 3. 运行方式

（文档范本演练口径的模拟叙述，随真实代码交付后按此执行）

1. 数据初始化：MySQL 执行 `sql/v0.5.1/course-alter.sql`（`course` 表增量：新增下架留痕三字段；状态写入无结构变更）；存量已发布课程立即可在学员端呈现。
2. 后端：Spring Boot 可执行服务启动（新增门户查询组件随课程模块加载，走既有学员端只读口径）；机构端能力点配置确认「课程下架」授予机构管理员与机构运营人员角色。
3. 前端：学员端门户 `web-portal`（本版首次交付）以 Vite 构建／启动；机构端 `web-admin` 更新下架入口；讲师端无变更。
4. 验证路径：访客走「首页→分类→搜索→详情→未发布课程详情拦截」；机构走「下架（含原因校验与三类拦截）→学员端四入口复验」；按第 2 节证据口径逐条复现。

## 4. 已知限制与待确认

1. 首页推荐为发布时间倒序的自动规则（默认 8 门），无人工推荐位（暂缓清单）；课程卡片无封面图（占位呈现，封面能力已建议回池）。
2. 搜索为课程名称包含匹配，不做简介、拼音与全文检索（扩展已建议回池）；列表与搜索的筛选与排序细化为留版本级。
3. 已知限制（PRD 第 6 章拍板值随版携带）：详情页不展示附件（学员获取随 0.6）；已下架为终态、重新上线＝新建课程重新送审；「购买功能即将开放」为静态提示条。
4. 待确认（沿用 PRD 待议，不影响本版验收）：一级分类包含二级课程的口径；空关键词等同全量列表；下架原因长度 5～200 字。
5. 术语表待登记清单已随本版 PRD 第 6 章回报（课程新增 `offline_by`／`offline_at`／`offline_reason`），以主流程合入为准。
