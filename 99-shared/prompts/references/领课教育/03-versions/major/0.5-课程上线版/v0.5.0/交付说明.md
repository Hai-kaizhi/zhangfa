## 2. 验收锚自检（锚原文｜结果｜证据）

锚原文逐字引自 PRD 第 2 章认领条目表；证据为文档范本演练的模拟叙述（界面叙述、接口叙述、日志行）。测试数据沿用 v0.4.1 交付说明中的 CR00000001（讲师甲，含两课时两附件的草稿）。

| 锚原文 | 结果 | 证据 |
|---|---|---|
| 讲师对草稿或未通过状态的本人课程提交上架审核，基本信息完整且至少含一个课时时课程转为待审核并进入机构待审列表；状态不允许、信息不完整或无课时时提交失败并逐项提示；非本人课程无法提交 | 通过 | ① 界面叙述：讲师甲在「我的课程」对 CR00000001（草稿、含两课时）点击「提交上架审核」，确认后状态标签即时变为「待审核」、送审按钮隐藏；机构运营人员登录机构端「课程审核」，待审列表首行出现 CR00000001（课程名、归属讲师＝讲师甲、送审时间）。② 失败分支：讲师甲新建一门未填介绍的草稿课程提交，提示「请补全课程介绍」且状态仍为草稿；对一门删空课时的课程提交，提示「请先为课程添加至少一个课时」；对已处于待审核的课程重复提交，提示「当前状态不支持提交审核」。③ 接口叙述：`POST /api/teacher/courses/CR00000001/submit-review` 返回 200，响应 `"status":"pending"`；讲师乙对同一课程发起返回 404，`"message":"课程不存在或无权操作"`。④ 日志行：`[SubmitReviewService] review submitted no=CR00000001 by=teacher:1001`（同事务写入 `submitted_by=1001`、`submitted_at`） |
| 机构运营人员对待审核课程作出结论：通过则课程转为已发布并即时进入学员端可见范围；不通过则课程转为未通过并必须填写修改意见，讲师端可见修改意见；审核结论与课程状态同事务落库并留痕 | 通过 | ① 界面叙述：机构运营人员打开 CR00000001 审核页，只读预览课程信息与课时目录，选「通过」提交——待审列表移出该课程；讲师甲刷新「我的课程」，状态标签变为「已发布」（学员端可见范围的状态口径达成，门户界面随 v0.5.1）。② 不通过分支：对另一门待审核课程 CR00000003 选「不通过」、未填意见提交被拦截（「不通过时必须填写 5～500 字修改意见」）；补填意见「介绍过短且第 2 课时标题与内容不符，请补充后重提」提交成功——课程转「未通过」，讲师甲在课程详情看到修改意见与审核时间，修改后重新提交再次进入待审核。③ 接口叙述：`POST /api/admin/courses/CR00000001/review`（`{"conclusion":"approve"}`）返回 200，响应 `"status":"published"`；不通过请求（`{"conclusion":"reject","remark":"…"}`）返回 200，`"status":"rejected"`；以仅持「课程查看」能力点、不含「课程审核」的运营助理账号发起同一请求返回 403，`"message":"无审核权限"`；两运营人员先后对同一课程提交结论，后到者返回 409，`"message":"课程状态已变更，请刷新列表"`。④ 日志行：`[CourseReviewService] review concluded no=CR00000001 result=published auditor=admin:3001`（同事务写入 `audit_admin_id=3001`／`audited_at`／结论）；`[CourseReviewService] review denied no=CR00000003 reason=no-remark` |

自检结论：2 条验收锚逐条通过，无不通过项；课程状态机把关链路（草稿→待审核→已发布／未通过→修改重提）全程可演示。

## 3. 运行方式

（文档范本演练口径的模拟叙述，随真实代码交付后按此执行）

1. 数据初始化：MySQL 执行 `sql/v0.5.0/course-alter.sql`（`course` 表增量：新增 `submitted_by`／`submitted_at`；状态与审核字段起用无需结构变更）；既有课程数据不受影响（存量草稿课程可正常送审）。
2. 后端：Spring Boot 可执行服务启动（课程模块状态机组件随模块化单体一并加载）；机构端能力点配置中确认「课程审核」能力点已授予机构运营人员角色。
3. 前端：讲师端 `web-teacher` 与机构端 `web-admin` 分别以 Vite 构建／启动（讲师端新增状态标签与送审入口、机构端新增「课程审核」菜单）。
4. 验证路径：以讲师账号走「草稿课程送审→失败分支（缺项／无课时／重复送审）→待审核锁写核对」；以机构运营人员账号走「待审列表→审核通过→已发布；另一门不通过→意见落库→讲师端查看意见→修改重提」；以无审核能力点账号与并发双开核对两条拦截分支，按第 2 节证据口径逐条复现。

## 4. 已知限制与待确认

1. 「通过即进入学员端可见范围」在本版＝课程状态到达已发布（可见性以状态为唯一依据）；学员端首页、分类浏览与搜索、课程详情四个门户界面随 v0.5.1 交付，本版无可供学员浏览的页面。
2. 已下架状态字段就绪但无写入路径（课程下架随 v0.5.1 R43）。
3. 已知限制（PRD 第 6 章拍板值随版携带）：待审核课程对讲师锁写、不提供送审撤回；待审列表无筛选与批量审核；修改意见长度 5～500 字。
4. 待确认（沿用 PRD 待议，不影响本版验收）：已发布课程修改回草稿导致学员端可见性中断的口径，若机构要求修改期间保持旧版可见需回大版本 PRD 重议。
5. 术语表待登记清单已随本版 PRD 第 6 章回报（课程新增 `submitted_by`／`submitted_at` 送审留痕两字段），以主流程合入为准。
