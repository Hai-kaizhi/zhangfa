## 3. 运行方式

- 后端：讲师模块（入驻申请部分）随单后端应用启动（连 MySQL 与 Redis）；执行迁移脚本建 `teacher_apply` 与 `teacher_account`（`student_id` 关联、`TC` 编号唯一索引）。
- 前端：学员端（申请页、状态页）与机构端（入驻审核列表与详情、讲师信息列表）各自工程启动或构建部署。
- 验证路径：学员提交申请（重复提交拦截）→ 运营审核一条通过＋一条不通过（意见必填）→ 通过者状态页见凭据提示、不通过者见意见并重新申请 → 机构端讲师信息与学员端接口核对（即 PRD 旅程一遍）。
