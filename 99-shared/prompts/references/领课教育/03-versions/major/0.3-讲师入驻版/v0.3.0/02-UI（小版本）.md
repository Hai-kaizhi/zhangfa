# 领课教育 v0.3.0 · UI 生图脚本（小版本）

> 本文档是 v0.3.0（申请与审核）的 UI 生图脚本：**生图提示词由对话中的 GPT 撰写**，本文档只给资料清单与可复制的话术；风格锚定（色板、字体、组件形态、通用禁止、令牌映射）**整段沿用项目层脚本、不在本版重新拍板**（唯一来源：《UI（项目）》附 A）；覆盖只圈本版认领条目（R20～R23）触及的学员端与机构端界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质保留。

## 0. 准备：给 GPT 哪些资料

| 资料 | 位置 | 必给／可选 |
|---|---|---|
| PRD（小版本）：v0.3.0 | `04-workspace/v0.3.0/01-PRD（小版本）.md` | 必给 |

**本版核心界面判定**：机构端·入驻审核详情页——本版信息量最多的操作面（四项申请信息只读＋结论操作＋意见输入＋状态标签），第一张图从它开始。

## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

> 复制下面整段发给 GPT（资料已在上文给过）：

```
你是资深 UI/UX 设计师，精通中文界面设计与生图提示词撰写。

我给你一份在线教育系统的小版本 PRD（v0.3.0 申请与审核）、项目层 UI 脚本与术语表。请先通读，只做理解，不要生成任何图片。

任务：为【机构端·入驻审核详情页】撰写第一张图的生图提示词。

一、这张图必须包含的元素（信息点逐条来自 PRD）：
- 页面结构：PC 管理后台布局——左侧导航（站点配置、分类管理、入驻审核、讲师信息、个人设置），顶部站点与账号信息；内容区为审核详情
- 详情区：申请人学员编号、真实姓名、联系方式、个人介绍、资质说明（全部只读展示）
- 结论操作区：通过／不通过两个操作；意见输入框（不通过时必填提示）
- 状态标签：待审核（当前详情态）；列表中已通过／未通过两种标签形态（必须画出至少一组）
- 错误态（必须画出至少一组）：不通过未填意见时提示「不通过时审核意见须为 5～200 字」
- 已审申请形态：结论区消失、显示「该申请已审核」只读态

二、风格锚定（整段沿用项目层脚本，必须严格遵守，不得自行改色、不得引入新色值）：
- 产品气质：可信、清晰、有学习氛围的在线教育平台；机构端为 PC 管理后台，界面克制、信息层级清楚
- 主色（品牌色）：#0056D2（用于主按钮、选中态、链接与关键强调）
- 副色／点缀色：#03C7E8（仅用于进度与可视化，不用于大面积背景）
- 中性色：页面底 #F5F6F8；卡片与内容底 #FFFFFF；标题文字 #1C1D1F；正文 #454545；辅助文字 #707070；分隔线与描边 #E1DDDB
- 语义色：成功 #0D7D4D（已通过标签）；警告 #D6B600（待审核标签）；危险 #AB0D02（未通过标签与错误提示）；信息 #00688D
- 色板配比：中性色承担 80% 以上面积，主色用于操作与强调，点缀色占比不超过 5%
- 字体：中文无衬线（PingFang SC／Microsoft YaHei／Noto Sans CJK SC），数字与拉丁用 Inter；编号数字启用等宽
- 组件形态：卡片圆角 8px、按钮圆角 6px、输入框圆角 6px；描边 1px；阴影克制（仅浮层）；不用大面积渐变与发光
- 无障碍：正文文字与背景对比度不低于 4.5:1

三、通用禁止（整段继承项目层，任何一张图都不允许）：
- 全中文界面，不得出现英文界面文案与英文占位词；只允许极少量数字与编号（如 ST00000011）
- 不出现第三方品牌标识、平台水印、二维码、联系方式、真实人物照片、真实机构名（本项目为模拟案例）
- 不使用深色模式与高饱和撞色，不使用拟物与 3D 装饰元素

四、本版附加禁止（v0.3.0 范围外界面不得出现）：
- 不出现课程、课时、附件上传、订单、播放器界面（随 0.4／0.6）
- 不出现讲师端界面（登录页、讲师工作台随 v0.3.1）
- 不出现账号开通／角色授权入口（0.1 已交付能力的入口不在本批界面）
- 不出现资质材料附件上传控件（本版申请全文字项）

五、输出要求：
1. 先只输出**生图提示词本身**，不要生成图片。
2. 提示词用中文撰写，结构为：画面类型与宽高比 → 页面结构与区块顺序 → 各区块的界面元素与文案 → 整体风格锚定（色值、字体、组件形态）→ 禁止项。
3. 宽高比：PC 管理后台 16:10（1440×900 视口）。
4. 界面文字直接写进提示词（生图文字渲染不可靠，出图后我会逐处校正为 PRD 文案）。
5. 先只给我这一张的提示词，等我确认后再生图；不要提前规划其他页面。
```

## 2. 第二步：生成并迭代核心界面

> 拿到提示词后复制下面这句：

```
请按上面的提示词生成图片。生成后自检：详情字段与只读形态是否齐全、结论操作与意见必填校验是否画出、三种状态标签是否在位、已审只读态是否呈现、色值是否按风格锚定执行、界面文字是否全中文且无范围外元素（课程／讲师端／附件上传等）。列出偏差，并给出修正后的提示词。
```

迭代方法（验收三问）：① 详情字段、操作与校验、状态标签是否与 PRD 逐条对得上；② 色值是否与风格锚定一致（以项目层附 A 为准，不照图取色）；③ 是否出现本版附加禁止中的元素。每次只改一处；满意后即本版基准，并与项目层主页基准并检一次（并排比对风格是否漂移，发现漂移以项目层基准为准修正）。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 核心界面定稿后复制下面整段：

```
审核详情页已定稿，是本版风格基准；全局风格仍以项目层脚本为唯一来源。

请规划本版（v0.3.0）其余需要出图的界面。覆盖要求如下——每条认领条目的操作面、每张异常与拦截态、每个空态边界都要有对应界面；先行基座与机制部分显式声明无界面。

一、界面覆盖要求（来自 PRD R20～R23）：
1. 学员端·申请成为讲师页（R20）：表单四字段（真实姓名、联系方式、个人介绍、资质说明——资质说明标注选填）、提交按钮；错误态：「请输入 2～20 个字符的真实姓名」「个人介绍须为 20～500 字」；拦截态：「已有待审核的申请，请等待审核结果」「您已是讲师」
2. 学员端·我的入驻申请页（R21）：三种状态形态——待审核（显示「审核中」）、已通过（显示审核意见〔如有〕＋讲师端初始凭据提示框：登录标识与初始密码＋「首次登录需修改密码，讲师端登录随下一版本开放」）、未通过（显示审核意见＋「重新申请」按钮）；空态：「尚未申请，去申请成为讲师」
3. 机构端·入驻审核列表（R22）：列（申请人学员编号、真实姓名、联系方式、提交时间、状态标签）；待审核排前；空态「暂无待审核申请」
4. 机构端·讲师信息列表（R23 机构端口径）：已入驻讲师只读列（讲师编号 TC＋8 位、姓名、对外介绍）；空态「暂无已入驻讲师」
5. 重新申请预填形态（R21→R20 边界）：未通过后点「重新申请」，表单预填上次信息可修改
6. 先行基座声明：R23 学员端讲师信息接口无界面、不生成图（课程详情展示随 0.5 交付）

二、各界面关键信息点：字段、必填与选填标记、字数边界提示、三种状态标签文案、意见必填校验、初始凭据提示框文案一律按 PRD 第 4 章逐字转译；「随下一版本开放」字样必须画出。

三、宽高比：机构端 16:10（1440×900）；学员端界面（1、2、5）另出手机浏览器形态 9:19.5（390×844）验证自适应，由你在清单中合并或单列并说明。

四、输出顺序要求：
1. 先给出**图片清单**（图名／所属界面／作用／宽高比），说明总数与顺序理由，等我确认。
2. 确认后逐张输出生图提示词（一次一张，结构同第一张），不要一次输出全部。
3. 全部沿用第一张的风格锚定与通用禁止、本版附加禁止；不得引入新的色值。
```

## 4. 第四步：批量生成

> 清单确认后逐张复制：

```
按这张的提示词生成图片。生成后自检并列出偏差：信息点是否齐全、色值是否与风格锚定一致、文案是否全中文、是否出现本版范围外元素；有偏差时给出修正后的提示词。
```

单张迭代方法：只改一句话（改区块／改色／改文案），每次生成后与第一张基准并排比对；连续两次仍偏离时重写该区块描述，不叠加修正语。

## 5. 收尾：回填归档

1. 把每张图的最终结果与偏差填写到**附 B 生图回填区**。
2. 色彩微调只允许发生在项目层脚本附 A（唯一来源）——本版脚本随之同步更新，本版不得私自改色值。
3. 界面文案以本版 PRD 与术语表为准（学员、讲师、机构运营人员、入驻申请、待审核／已通过／未通过、讲师编号等称谓与状态逐字沿用），出图后逐处校正。

## 附注 其他生图模型的差异

对无对话记忆的模型（如即梦等）：把第 1 步话术中的「风格锚定」与「通用禁止／本版附加禁止」两段原文，连同 GPT 已写好的单张生图提示词拼成一段一次性提交；每张图都重复带上风格锚定。第 3 步的「让 GPT 规划清单」改为人工按覆盖要求逐项对照（界面 1～6），仍不写死总数。
