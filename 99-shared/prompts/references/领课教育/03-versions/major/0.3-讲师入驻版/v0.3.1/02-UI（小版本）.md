# 领课教育 v0.3.1 · UI 生图脚本（小版本）

> 本文档是 v0.3.1（讲师端就绪）的 UI 生图脚本：**生图提示词由对话中的 GPT 撰写**，本文档只给资料清单与可复制的话术；风格锚定（色板、字体、组件形态、通用禁止、令牌映射）**整段沿用项目层脚本、不在本版重新拍板**（唯一来源：《UI（项目）》附 A）；覆盖只圈本版认领条目（R24～R26）触及的讲师端界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质保留。

**本版核心界面判定**：讲师端·个人中心（讲师信息页）——本版信息量最多的操作面（姓名＋对外介绍编辑＋保存反馈＋只读标识），第一张图从它开始。

## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

> 复制下面整段发给 GPT（资料已在上文给过）：

```
你是资深 UI/UX 设计师，精通中文界面设计与生图提示词撰写。

我给你一份在线教育系统的小版本 PRD（v0.3.1 讲师端就绪）、项目层 UI 脚本与术语表。请先通读，只做理解，不要生成任何图片。

任务：为【讲师端·个人中心（讲师信息页）】撰写第一张图的生图提示词。

一、这张图必须包含的元素（信息点逐条来自 PRD）：
- 页面结构：讲师端布局——左侧或顶部导航（工作台、个人中心；个人中心含讲师信息与账号资料两个入口）、顶部站点与账号信息（含退出入口）
- 内容区：讲师信息表单——姓名（2～20 个字符）、对外介绍（20～500 字，多行文本）、手机号（只读展示）、讲师编号 TC00000001（只读展示）、保存按钮
- 成功态：保存后提示「保存成功」，页面显示更新后内容
- 错误态（必须画出至少一组）：「请输入 2～20 个字符的姓名」「介绍须为 20～500 字」
- 辅助说明：「保存后机构端与学员端将展示最新介绍」

二、风格锚定（整段沿用项目层脚本，必须严格遵守，不得自行改色、不得引入新色值）：
- 产品气质：可信、清晰、有学习氛围的在线教育平台；讲师端为网页工作台，界面克制、信息层级清楚
- 主色（品牌色）：#0056D2（用于主按钮、选中态、链接与关键强调）
- 副色／点缀色：#03C7E8（仅用于进度与可视化，不用于大面积背景）
- 中性色：页面底 #F5F6F8；卡片与内容底 #FFFFFF；标题文字 #1C1D1F；正文 #454545；辅助文字 #707070；分隔线与描边 #E1DDDB
- 语义色：成功 #0D7D4D；警告 #D6B600；危险 #AB0D02（错误提示）；信息 #00688D
- 色板配比：中性色承担 80% 以上面积，主色用于操作与强调，点缀色占比不超过 5%
- 字体：中文无衬线（PingFang SC／Microsoft YaHei／Noto Sans CJK SC），数字与拉丁用 Inter；编号数字启用等宽
- 组件形态：卡片圆角 8px、按钮圆角 6px、输入框圆角 6px；描边 1px；阴影克制（仅浮层）；不用大面积渐变与发光
- 无障碍：正文文字与背景对比度不低于 4.5:1

三、通用禁止（整段继承项目层，任何一张图都不允许）：
- 全中文界面，不得出现英文界面文案与英文占位词；只允许极少量数字与编号（如 TC00000001）
- 不出现第三方品牌标识、平台水印、二维码、联系方式、真实人物照片、真实机构名（本项目为模拟案例）
- 不使用深色模式与高饱和撞色，不使用拟物与 3D 装饰元素

四、本版附加禁止（v0.3.1 范围外界面不得出现）：
- 不出现课程、课时、附件上传、收益、订单界面（课程随 0.4、收益随 0.7、交易随 0.6）
- 不出现学员端与机构端界面元素
- 不出现手机号修改入口（本版只读）
- 不出现多因子验证、找回密码入口（本版无此能力）

五、输出要求：
1. 先只输出**生图提示词本身**，不要生成图片。
2. 提示词用中文撰写，结构为：画面类型与宽高比 → 页面结构与区块顺序 → 各区块的界面元素与文案 → 整体风格锚定（色值、字体、组件形态）→ 禁止项。
3. 宽高比：桌面端 16:10（1440×900 视口）。
4. 界面文字直接写进提示词（生图文字渲染不可靠，出图后我会逐处校正为 PRD 文案）。
5. 先只给我这一张的提示词，等我确认后再生图；不要提前规划其他页面。
```

## 2. 第二步：生成并迭代核心界面

> 拿到提示词后复制下面这句：

```
请按上面的提示词生成图片。生成后自检：表单字段与只读项是否齐全、成功态与错误态是否画出、辅助说明是否在位、色值是否按风格锚定执行、界面文字是否全中文且无范围外元素（课程／收益／学员端等）。列出偏差，并给出修正后的提示词。
```

迭代方法（验收三问）：① 字段、校验反馈、只读项是否与 PRD 逐条对得上；② 色值是否与风格锚定一致（以项目层附 A 为准，不照图取色）；③ 是否出现本版附加禁止中的元素。每次只改一处；满意后即本版基准，并与项目层主页基准并检一次（并排比对风格是否漂移，发现漂移以项目层基准为准修正）。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 核心界面定稿后复制下面整段：

```
讲师信息页已定稿，是本版风格基准；全局风格仍以项目层脚本为唯一来源。

请规划本版（v0.3.1）其余需要出图的讲师端界面。覆盖要求如下——每条认领条目的操作面、每张异常与拦截态、每个空态边界都要有对应界面；机制部分显式声明无界面。

一、界面覆盖要求（来自 PRD R24～R26）：
1. 讲师端登录页（R24）：手机号＋密码表单、登录按钮；异常态：「手机号或密码错误」「尝试次数过多，请 15 分钟后再试」「账号不可用」
2. 强制修改密码页（R24 首登边界）：新密码＋确认新密码；提示「首次登录请修改初始密码」；错误态：「新密码不能与原密码相同」「两次输入的密码不一致」
3. 讲师端工作台首页（R26/R25 背景与空态）：登录后默认页——空态「课程功能随下一版本开放」＋个人中心入口（不得出现课程管理入口）
4. 账号资料页（R25）：手机号（只读）、讲师编号（只读）、修改密码（原密码＋新密码＋确认新密码）；错误态：「原密码不正确」；成功态：提示修改成功并引导「请重新登录」
5. 会话过期态（R24/R25 边界）：过期提示并引导至登录页
6. 机制声明：讲师登录态与学员端／机构端互不通用为服务端机制，无界面、不生成图（跨端拦截在接口层）

二、各界面关键信息点：字段、必填标记、字段级错误提示、锁定等待时长（15 分钟）、空态文案一律按 PRD 第 4 章逐字转译；「随下一版本开放」「请重新登录」字样必须画出。

三、宽高比：全部为桌面端 16:10（1440×900）——讲师端为网页工作台，沿用项目层口径不做手机形态（手机形态仅限学员端界面，本版无学员端界面），不得出现手机端界面形态。

四、输出顺序要求：
1. 先给出**图片清单**（图名／所属界面／作用／宽高比），说明总数与顺序理由，等我确认。
2. 确认后逐张输出生图提示词（一次一张，结构同第一张），不要一次输出全部。
3. 全部沿用第一张的风格锚定与通用禁止、本版附加禁止；不得引入新的色值。
```

## 4. 第四步：批量生成

> 清单确认后逐张复制：

```
按这张的提示词生成图片。生成后自检并列出偏差：信息点是否齐全、色值是否与风格锚定一致、文案是否全中文、是否出现本版范围外元素；有偏差时给出修正后的提示词。
```

单张迭代方法：只改一句话（改区块／改色／改文案），每次生成后与第一张基准并排比对；连续两次仍偏离时重写该区块描述，不叠加修正语。

## 5. 收尾：回填归档

1. 把每张图的最终结果与偏差填写到**附 B 生图回填区**。
2. 色彩微调只允许发生在项目层脚本附 A（唯一来源）——本版脚本随之同步更新，本版不得私自改色值。
3. 界面文案以本版 PRD 与术语表为准（讲师、讲师端、讲师编号、个人中心等称谓逐字沿用），出图后逐处校正。

## 附注 其他生图模型的差异

对无对话记忆的模型（如即梦等）：把第 1 步话术中的「风格锚定」与「通用禁止／本版附加禁止」两段原文，连同 GPT 已写好的单张生图提示词拼成一段一次性提交；每张图都重复带上风格锚定。第 3 步的「让 GPT 规划清单」改为人工按覆盖要求逐项对照（界面 1～6），仍不写死总数。
