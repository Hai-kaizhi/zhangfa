## 3. 运行方式

（文档范本演练口径的模拟叙述，随真实代码交付后按此执行）

1. 数据初始化：MySQL 执行 `sql/v0.6.0/course_order.sql`、`sql/v0.6.0/pay_record.sql` 建两表（含未取消订单唯一索引与外部单据号唯一索引）；存量课程数据不受影响。
2. 外部服务：支付渠道商户参数（0.1 定案渠道）配置于站点配置并连通性校验通过；渠道回调地址与验签密钥按渠道规范登记。
3. 后端：Spring Boot 可执行服务启动（交易模块与超时关闭定时任务随模块化单体加载）；机构端能力点配置确认「订单管理」授予机构运营人员角色。
4. 前端：学员端 `web-portal` 更新（购买按钮、支付页）、机构端 `web-admin` 更新（订单管理）；讲师端无变更。
5. 验证路径：内部账号走「下单→扫码支付（渠道沙箱）→回调→已支付→机构查询与详情」主链路；按第 2 节证据口径逐条复现拦截分支（不可购买／重复下单／已购买／取消与不可取消／越权）与回写分支（幂等／金额不一致／支付失败／验签失败）及超时关闭（可临时缩短任务间隔验证后恢复 2 小时口径）。

## 4. 已知限制与待确认

1. 学员侧订单列表与详情入口随 0.7：本版学员经再下单提示进入待支付订单支付页，订单信息咨询由机构代查（回退人工过渡）；学员编号暂非机构列表筛选项（建议已回池）。
2. 免费课程（价格 0）经渠道 0 元通道完成（若渠道不支持 0 元单的直转优化建议已回池）。
3. 已知限制（PRD 第 6 章拍板值随版携带）：订单不删除（终态以已取消表达）；取消与回调并发以先落库者为准；异常支付流水处置为线下人工（不建售后对象）；灰度台阶属上线安排（本版完成开发与黑盒验收，环境联调与真实单随发布运营执行）。
4. 待确认（沿用 PRD 待议，不影响本版验收）：订单管理能力点默认授予口径；超时时长 2 小时的业务接受度（灰度期间复核）。
5. 术语表待登记清单已随本版 PRD 第 6 章回报（订单新增 `amount`／`paid_at`／`canceled_at`／`cancel_type`；支付记录新增 `order_id`／`out_trade_no`／`amount`／`result`／`paid_at`），以主流程合入为准。
