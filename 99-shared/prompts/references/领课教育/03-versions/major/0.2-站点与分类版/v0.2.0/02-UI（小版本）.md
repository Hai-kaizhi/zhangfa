> 本文档是 v0.2.0（站点信息与分类骨架）的 UI 生图脚本：**生图提示词由对话中的 GPT 撰写**，本文档只给资料清单与可复制的话术；风格锚定（色板、字体、组件形态、通用禁止、令牌映射）**整段沿用项目层脚本、不在本版重新拍板**（唯一来源：《UI（项目）》附 A）；覆盖只圈本版认领条目（R12～R17）触及的机构端界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质保留。

**本版核心界面判定**：机构端·分类管理页——本版信息量最多的操作面（层级树＋排序＋增删改＋状态标记），第一张图从它开始。

## 1. 第一步话术：让 GPT 产出本版核心界面（分类管理页）的生图提示词

> 复制下面整段发给 GPT（资料已在上文给过）：

```
你是资深 UI/UX 设计师，精通中文界面设计与生图提示词撰写。

我给你一份在线教育系统的小版本 PRD（v0.2.0 站点信息与分类骨架）、项目层 UI 脚本与术语表。请先通读，只做理解，不要生成任何图片。

任务：为【机构端·分类管理页】撰写第一张图的生图提示词。

一、这张图必须包含的元素（信息点逐条来自 PRD）：
- 页面结构：PC 管理后台布局——左侧导航（站点配置、分类管理、个人设置），顶部站点与账号信息（含退出入口），右侧内容区
- 内容区：分类管理——层级树（最多 2 级：顶级＋子级）＋「新增分类」主按钮
- 树节点信息：分类名、排序号、操作（编辑、删除）；已删除分类带「已删除」标记（必须画出至少一个）
- 新增／编辑分类表单（弹层或右侧抽屉，二选一说明）：分类名（2～20 个字符）、上级分类（下拉，可空＝顶级）、排序号（1～999）
- 表单错误态（必须画出至少一组）：「同级已存在同名分类」「层级最多为 2 级」
- 删除二次确认弹层：「删除后该分类将从可用口径移出、记录保留，确认删除？」
- 空态（必须画出）：分类树为空时显示「暂无分类，点击新增分类开始」

二、风格锚定（整段沿用项目层脚本，必须严格遵守，不得自行改色、不得引入新色值）：
- 产品气质：可信、清晰、有学习氛围的在线教育平台；机构端为 PC 管理后台，界面克制、信息层级清楚
- 主色（品牌色）：#0056D2（用于主按钮、选中态、链接与关键强调）
- 副色／点缀色：#03C7E8（仅用于进度与可视化，不用于大面积背景）
- 中性色：页面底 #F5F6F8；卡片与内容底 #FFFFFF；标题文字 #1C1D1F；正文 #454545；辅助文字 #707070；分隔线与描边 #E1DDDB
- 语义色：成功 #0D7D4D；警告 #D6B600（已删除标记）；危险 #AB0D02（删除操作与错误提示）；信息 #00688D
- 色板配比：中性色承担 80% 以上面积，主色用于操作与强调，点缀色占比不超过 5%
- 字体：中文无衬线（PingFang SC／Microsoft YaHei／Noto Sans CJK SC），数字与拉丁用 Inter；表格数字启用等宽
- 组件形态：卡片圆角 8px、按钮圆角 6px、输入框圆角 6px；描边 1px；阴影克制（仅浮层）；不用大面积渐变与发光
- 无障碍：正文文字与背景对比度不低于 4.5:1

三、通用禁止（整段继承项目层，任何一张图都不允许）：
- 全中文界面，不得出现英文界面文案与英文占位词；只允许极少量数字
- 不出现第三方品牌标识、平台水印、二维码、联系方式
- 不出现真实人物照片、真实机构名与真实课程名（本项目为模拟案例）
- 不使用深色模式与高饱和撞色，不使用拟物与 3D 装饰元素

四、本版附加禁止（v0.2.0 范围外界面不得出现）：
- 不出现课程列表、课时、附件、订单、讲师等业务界面（课程随 0.4 起、交易随 0.6）
- 不出现对接参数的编辑入口（对接参数维护随 v0.2.1，本版只读展示）
- 不出现人工推荐位、轮播配置、页面装修界面（本期不做）
- 不出现账号开通／角色授权入口（机构管理员专属能力的入口仅在站点配置页出现，账号管理导航本版保留但不属于本批界面）

五、输出要求：
1. 先只输出**生图提示词本身**，不要生成图片。
2. 提示词用中文撰写，结构为：画面类型与宽高比 → 页面结构与区块顺序 → 各区块的界面元素与文案 → 整体风格锚定（色值、字体、组件形态）→ 禁止项。
3. 宽高比：PC 管理后台 16:10（1440×900 视口）。
4. 界面文字直接写进提示词（生图文字渲染不可靠，出图后我会逐处校正为 PRD 文案）。
5. 先只给我这一张（分类管理页）的提示词，等我确认后再生图；不要提前规划其他页面。
```

## 2. 第二步：生成并迭代核心界面

> 拿到提示词后复制下面这句：

```
请按上面的提示词生成图片。生成后自检：层级树与排序是否齐全、已删除标记与错误态是否画出、表单字段与校验提示是否与 PRD 一致、色值是否按风格锚定执行、界面文字是否全中文且无范围外元素（课程／对接参数编辑等）。列出偏差，并给出修正后的提示词。
```

迭代方法（验收三问）：① 树结构、状态标记、表单与错误提示是否与 PRD 逐条对得上；② 色值是否与风格锚定一致（以项目层附 A 为准，不照图取色）；③ 是否出现本版附加禁止中的元素。每次只改一处；满意后即本版基准，并与项目层主页基准并检一次（并排比对风格是否漂移，发现漂移以项目层基准为准修正）。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 核心界面定稿后复制下面整段：

```
分类管理页已定稿，是本版风格基准；全局风格仍以项目层脚本为唯一来源。

请规划本版（v0.2.0）其余需要出图的机构端界面。覆盖要求如下——每条认领条目的操作面、每张异常与拦截态、每个空态边界都要有对应界面；先行基座与机制部分显式声明无界面。

一、界面覆盖要求（来自 PRD R12～R17）：
1. 站点配置页·机构管理员形态（R12／R13）：站点信息表单（站点名称、站点标识、基础文案、保存按钮）＋对接参数只读区（密钥脱敏形如 ****abcd、未配置显示「未配置」空态）＋最近修改留痕（最近修改人与时间）；错误态：「请输入 2～20 个字符的站点名称」「该站点标识不可用，请更换」；修改入口在本形态可见
2. 站点配置页·机构运营人员形态（R12，能力点显隐表现，必须画出）：同页只读形态——站点信息无编辑入口与保存按钮，对接参数仍脱敏只读；左侧导航含分类管理与站点配置、无账号管理入口
3. 新增分类表单成功态与编辑表单（R14／R15）：字段与校验提示同第一张图；编辑态含「上级分类不能选择自己或其子级」拦截提示
4. 删除拦截与确认（R16）：二次确认弹层；拦截态：「请先删除或移出其子分类」
5. 空态：分类树空态（若第一张图未含需单独一张）
6. 先行基座声明：R17 学员端可用分类口径为接口先行，无界面、不生成图（界面随 0.5 交付）

二、各界面关键信息点：表单字段、必填标记、字段级错误提示、确认弹层文案、状态标记一律按 PRD 第 4 章逐字转译；脱敏格式（****abcd）与「未配置」空态必须画出。

三、宽高比：全部为 PC 管理后台 16:10（1440×900）；本版无手机形态。

四、输出顺序要求：
1. 先给出**图片清单**（图名／所属界面／作用／宽高比），说明总数与顺序理由，等我确认。
2. 确认后逐张输出生图提示词（一次一张，结构同分类管理页那张），不要一次输出全部。
3. 全部沿用分类管理页的风格锚定与通用禁止、本版附加禁止；不得引入新的色值。
```

## 4. 第四步：批量生成

> 清单确认后逐张复制：

```
按这张的提示词生成图片。生成后自检并列出偏差：信息点是否齐全、色值是否与风格锚定一致、文案是否全中文、是否出现本版范围外元素；有偏差时给出修正后的提示词。
```

单张迭代方法：只改一句话（改区块／改色／改文案），每次生成后与分类管理页基准并排比对；连续两次仍偏离时重写该区块描述，不叠加修正语。

## 5. 收尾：回填归档

1. 把每张图的最终结果与偏差填写到**附 B 生图回填区**。
2. 色彩微调只允许发生在项目层脚本附 A（唯一来源）——本版脚本随之同步更新，本版不得私自改色值。
3. 界面文案以本版 PRD 与术语表为准（站点配置、课程分类、机构管理员、机构运营人员、已删除等称谓与状态逐字沿用），出图后逐处校正。

## 附注 其他生图模型的差异

对无对话记忆的模型（如即梦等）：把第 1 步话术中的「风格锚定」与「通用禁止／本版附加禁止」两段原文，连同 GPT 已写好的单张生图提示词拼成一段一次性提交；每张图都重复带上风格锚定。第 3 步的「让 GPT 规划清单」改为人工按覆盖要求逐项对照（界面 1～6），仍不写死总数。
