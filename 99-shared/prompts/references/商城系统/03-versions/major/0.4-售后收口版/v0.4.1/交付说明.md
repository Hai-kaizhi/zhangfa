# 交付说明：v0.4.1

> 定位：v0.4.1 售后完结版的开发交付说明——承接本版 PRD 认领条目（R42 ◆ 退货审核与退款、R43 ◆ 库存数量变动（回补路径）、R44 收支记录写入（支出路径）、R45 收支台账查询），按「代码已按 PRD 实现」口径编写；本项目为模拟示范案例（文档范本演练），无真实代码产物，证据为模拟口径。

## 1. 实现清单（条目｜代码位置｜实现要点）

| 条目 | 代码位置 | 实现要点 |
|---|---|---|
| R42 ◆ 退货审核与退款 | 服务端·交易模块分包（退货审核与完结服务）＋管理端·售后处理页＋商城端·售后进度卡片 | 待审核／待退货列表与详情（凭证大图）；拒绝必填理由（5~100 字）回传买家可见；通过→待退货＋订单售后中；确认收货→经适配层渠道退款（K6）→回执到账后同一本地事务五项落位（支付单已退款、库存回补、支出写入、退货单退款完成、订单回已完成）；审核与完结字段写入 trade_return（`audit_conclusion`／`audit_reason`／`audited_at`／`received_at`／`refunded_at`，与术语表 v0.4.1 登记行逐字一致）；状态前置条件条件更新保护并发 |
| R43 ◆ 库存数量变动（回补路径） | 服务端·商品模块分包（库存台账回补契约）＋交易模块调用 | 退货完结事务内按订单项成交数量逐规格回增 `available_qty`；条件更新保护并发（K5）；变动留痕（谁／何时／何因＝退货完结，关联退货单号）；商品下架不影响回补（D6 推论） |
| R44 收支记录写入（支出路径） | 服务端·报表模块分包（台账写入契约）＋交易模块调用 | 退货完结事务内写一条支出记录（`record_type`＝`EXPENSE`、`amount`＝退款金额、`related_no`＝退货单号、`occurred_at`＝完结时点）；按退货单号唯一约束防重；只读追加不编辑不删除（D8） |
| R45 收支台账查询 | 管理端·订单收支台账页＋服务端·报表模块分包（流水查询） | 筛选＝时间范围＋记录类型（全部／收入／支出／冲正）＋关联单号；流水列表（类型／金额元两位小数／关联单号／发生时间）倒序分页；收入合计与支出合计两行；空态与无权限拦截；只读无导出 |

范围外零实现：退货申请（v0.4.0 已交付）、换货补发、评价与咨询（0.5）、统计报表与导出（0.7）、退货单人工编辑与删除。

## 3. 运行方式

按「代码已按 PRD 实现」口径（模拟）：服务端随交易／商品／报表模块分包部署（单服务形态），管理端（PC Web）以客服人员账号走售后处理审核与完结、以管理者账号走订单收支台账；商城端（移动 Web）买家被动查看售后进度卡片新状态；验收用数据＝一张待审核退货单（v0.4.0 申请生成）及其关联订单、支付单。本演练未产出可运行包，操作路径以本版 PRD 第 4 章各条目交互与流程为准。
