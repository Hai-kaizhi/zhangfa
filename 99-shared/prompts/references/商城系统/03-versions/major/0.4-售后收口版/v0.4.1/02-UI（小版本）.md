# 好物商城 v0.4.1 · UI 生图脚本（小版本）

> 本文档是 v0.4.1 售后完结版的 UI 生图脚本：生图提示词由 GPT 在对话中分析资料后自己撰写，本文档只提供资料清单与分步话术；风格锚定整段沿用项目层脚本（唯一来源在 `01-project-docs/04B-ui/04B-UI（项目）.md` 附 A），本版不出现任何新色值；覆盖只圈本版认领条目（R42、R45 操作面；R43、R44 为机制条目无界面）触及的界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质予以保留。

新建一个 GPT 对话，一次性把「必给」资料粘贴给 GPT，然后按第 1 步开始。

## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

> 我要为「好物商城」v0.4.1 售后完结版生成 UI 设计图。请先通读我提供的全部资料，然后**只做一件事：撰写第一张图——管理端（PC 横屏 16:9，左侧导航＋内容区布局）「退货审核」详情页的生图提示词。先只输出提示词，不要生成图片。**
>
> 撰写提示词时必须遵循以下风格锚定（不得偏离，与项目层脚本一致）：
> - **色板（精确 hex，为本项目品牌色唯一来源）**：主色 `#DA3A2B`（暖正红，用于主行动按钮、强调、选中态）；营销强调色 `#FF6A00`（仅用于秒杀/促销标签，本版界面不使用）；成功 `#2FA65A`、警告 `#E8A33D`、危险 `#D85555`；中性色阶：文字主 `#1F2329`、次级 `#4E5969`、辅助 `#86909C`、分隔 `#C9CDD4`、页面底 `#F2F3F5`、卡片 `#FFFFFF`。整体白底为主、主色点缀，克制清爽。
> - **字体与组件形态**：系统默认无衬线中文字体；卡片式布局、圆角 8px、轻投影；管理端为左侧导航（仅体现客服与管理者可见的授权菜单）＋右侧内容区。
> - **通用禁止**：界面文字全部为简体中文；不得出现"平台、商家入驻、多商户、分账"等字样或概念（本产品为单一卖方自营）；不得出现英文界面文案、第三方品牌标识、支付渠道以外的金融元素；人像与插画仅作占位不出现真实品牌。
> - **核心界面必须元素（逐条画出）**：左侧导航「售后处理」高亮；退货单详情卡——退货单号（`RET` 前缀）、关联订单号、订单实付金额、退货原因全文、凭证图片大图区（2 张占位）；买家信息行；状态标签「待审核」（警告色）；操作区——「通过」主色按钮＋「拒绝」危险色按钮＋审核理由多行输入框（提示语「请填写 5~100 字审核理由，拒绝时必填且买家可见」）。
> - **称谓纪律**：状态名严格按我提供的术语表中文原文（本页状态仅可出现「待审核」）；内部人员按角色名（客服人员）。
> - **本版附加禁止**：不得出现退货申请表单（已随 v0.4.0 交付）、统计报表与导出按钮、库存或台账数字的编辑入口；不得出现「退款金额输入框」（退款金额取订单实付、系统自动）。
>
> 提示词结构要求：先一段总述（风格与布局意图），再分区块描述（从左到右、从上到下），最后列出色彩与文字约束。输出后停下来等我确认。

## 2. 第二步：生成并迭代核心界面

确认提示词无误后，发送：

> 请用这张「退货审核」详情页提示词生成图片（PC 横屏管理端）。

迭代方法（验收三问）：①信息点是否全——退货单号、订单信息、原因、凭证、状态标签、通过／拒绝与理由输入逐条在图上；②风格是否同源——色板、圆角、卡片形态与项目层主页基准一致；③纪律是否守住——无英文文案、无范围外元素。对不满意的局部直接描述改哪里，让 GPT 修改提示词后重新生成。**满意的那一版即本版基准，并与项目层脚本生成的主页基准并检一次**（防跨版本风格漂移）。色彩如需微调，改项目层脚本附 A 色值表并同步其第一步话术中的 hex，本脚本随之更新。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 本版核心界面（退货审核详情页）风格已定（以上一张满意图为基准）。请基于资料规划本版其余 UI 图片，**先输出完整清单（说明总数与每张的作用），经我确认后再逐张输出提示词**。规划必须满足以下覆盖要求：
>
> - **覆盖范围＝本版认领条目 R42、R45 的操作面；R43（库存回补路径）与 R44（收支记录写入支出路径）为机制条目、无人工触发面——无界面、不生成图**。必须覆盖的界面：
>   - **管理端（PC 横屏 16:9，左侧导航＋内容区）**：
>     1. 售后处理·待审核退货单列表（退货单号／订单号／买家／申请时间／原因摘要，状态「待审核」标签）。
>     2. 审核详情·拒绝理由校验态（理由不足 5 字时危险色提示「请填写 5~100 字审核理由」，提交不发起）。
>     3. 售后处理·待退货列表（状态「待退货」标签）＋行内「确认收到退货，执行退款完结」按钮。
>     4. 渠道退款失败异常态（提示「渠道退款未成功，可重试」，退货单保持「待退货」）。
>     5. 订单收支台账查询页——筛选区（时间范围／记录类型：全部·收入·支出·冲正／关联单号）＋流水列表（类型／金额元／关联单号／发生时间）＋收入合计与支出合计两行。
>     6. 订单收支台账空态（「暂无符合条件的收支记录」）。
>     7. 按角色授权对照态——管理者视角左侧导航可见「订单收支台账」、客服视角不可见（体现按角色仅见授权菜单）。
>   - **商城端（手机竖屏 9:19.5）**——买家被动呈现面：
>     8. 售后进度卡片·待退货态（状态标签「待退货」警告色＋寄回指引「请尽快寄回」＋回寄地址）。
>     9. 售后进度卡片·退款完成态（状态标签「退款完成」成功色＋到账提示「退款已原路退回，到账以支付渠道为准」）。
>     10. 售后进度卡片·已拒绝态（状态标签「已拒绝」辅助色＋审核理由原文展示区）。
> - **信息点逐条转译**：状态标签颜色语义（待审核／待退货＝警告色、退款完成＝成功色、已拒绝＝辅助色）、拒绝理由买家可见、退款金额不可编辑、台账金额为人民币元两位小数，都要体现在对应图中；生图文字是幻觉，界面文案以上述 PRD 锚定为准。
> - **本版附加禁止**：商城端图不得出现管理端元素与操作按钮；管理端图不得出现退货申请表单、统计报表、导出按钮、库存编辑入口；状态字样严格限术语表原文（待审核、待退货、退款完成、已拒绝；订单状态「售后中」仅出现在管理端订单上下文）；不得出现评价、咨询、会员等级等后续版本元素。
> - 通用禁止与称谓纪律同第一张图。风格、色板、组件形态一律向已定基准看齐。
>
> 清单确认后再逐张输出提示词，每张输出后停下等我确认。

## 4. 第四步：批量生成

清单确认后，发送：

> 按清单顺序逐张生成图片，每张生成后停顿，等我记录后再继续下一张。

单张迭代方法：同第 2 步，逐张局部修正；整批完成后如出现风格漂移，回引本版基准图（退货审核详情页）让 GPT 校正后重生成该张。

## 5. 收尾：回填归档

全部图片满意后，把每张图的信息回填到本文档附 B（图／界面与端／主要偏差／色彩微调记录）；如做了色彩微调，须同步**项目层脚本附 A**（唯一来源）与本版话术中的 hex，保持「文档色值＝品牌色唯一来源」。本版新增界面的要素不回写项目层脚本（风格变更才回写项目层）。

## 附注 其他生图模型的差异

使用即梦等无对话记忆的生图模型时：把第 1 步话术连同资料摘要、风格锚定全文一并放入提示词前置段落；每次生成单张图时重复附上风格锚定与该图提示词；迭代以「新对话＋完整提示词」方式进行，回填流程相同。
