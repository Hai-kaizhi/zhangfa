# 交付说明：v0.4.0

> 定位：v0.4.0 售后受理版的开发交付说明——承接本版 PRD 认领条目（R41 退货申请），按「代码已按 PRD 实现」口径编写；本项目为模拟示范案例（文档范本演练），无真实代码产物，证据为模拟口径。

## 1. 实现清单（条目｜代码位置｜实现要点）

| 条目 | 代码位置 | 实现要点 |
|---|---|---|
| R41 退货申请·数据 | 服务端·交易模块分包（trade_return 持久化） | 新表 `trade_return`：`return_no`、`order_id`、`reason`、`status`、`cancelled_at`（＋通用 `id`／`created_at`／`updated_at`），落库字段与术语表 v0.4.0 登记行逐字一致；凭证图经 `sys_image_asset`（`biz_type`＝`return`）关联；退货单号按 `RET`＋日期＋6 位当日序列生成 |
| R41 退货申请·服务端 | 服务端·交易模块分包（退货申请服务与接口） | 创建申请校验链：本人订单→状态＝已完成→无未到终态退货单（条件创建防并发）；撤回仅待审核可执行（状态前置条件更新）；创建与撤回均留痕；不做删除 |
| R41 退货申请·商城端 | 商城端（移动 Web）·订单详情页＋申请退货页 | 已完成订单详情「申请退货」入口（不满足条件置灰并提示）；申请页＝原因文本（5~200 字，快捷选项填入）＋凭证九宫格（1~3 张、单张 ≤5MB、jpg／png／webp）＋提交；售后进度卡片（退货单号／状态／申请时间／原因摘要／凭证缩略图／撤回按钮＋二次确认） |

范围外零实现：客服审核、渠道退款、库存回补、台账支出与查询（随 v0.4.1）；管理端界面；订单状态流转。

## 2. 验收锚自检（锚原文｜结果｜证据）

锚原文（逐字引自本版 PRD 第 2 章认领条目表）：「买家在商城端对本人已完成订单提交退货申请（含原因与凭证）后，系统生成待审核的退货单并呈现处理进度；客服审核前买家可撤回，撤回后退货单转已取消且订单保持已完成。」

| # | 锚拆句 | 结果 | 证据（模拟口径） |
|---|---|---|---|
| 1 | 买家在商城端对本人已完成订单提交退货申请（含原因与凭证） | 通过 | 界面叙述：会员「我的订单」打开已完成订单详情（订单号 `ORD20260920000118`，状态「已完成」），点「申请退货」→申请页填写原因「水杯杯盖开裂，与描述不符」、上传 2 张凭证图→点「提交申请」→提示「申请已提交」，返回订单详情出现售后进度卡片。接口叙述：`POST /api/trade/returns`（body：orderId、reason、proofImageIds）→ 201，返回 `returnNo: RET20260920000001`。 |
| 2 | 系统生成待审核的退货单 | 通过 | 日志行（模拟）：`ReturnService create ok returnNo=RET20260920000001 orderId=... status=PENDING_REVIEW operator=cust#1024`；数据叙述：trade_return 落行（status＝`PENDING_REVIEW`，cancelled_at 为空）。 |
| 3 | 并呈现处理进度 | 通过 | 界面叙述：订单详情售后进度卡片显示退货单号、状态标签「待审核」（警告色）、申请时间、原因摘要与凭证缩略图。 |
| 4 | 客服审核前买家可撤回 | 通过 | 界面叙述：进度卡片点「撤回申请」→弹层「撤回后本次申请终止，可重新发起」→「确认撤回」→卡片状态更新。接口叙述：`POST /api/trade/returns/{id}/cancel` → 200。日志行（模拟）：`ReturnService cancel ok returnNo=RET20260920000001 from=PENDING_REVIEW to=CANCELLED`。 |
| 5 | 撤回后退货单转已取消且订单保持已完成 | 通过 | 数据叙述（模拟）：trade_return.status＝`CANCELLED`、cancelled_at 写入；trade_order.status 仍＝`COMPLETED`（未流转）；撤回后订单详情「申请退货」入口恢复可用（可再次发起）。 |

异常与拦截抽验（PRD A1~A7，提示文案逐字）：

| # | 场景 | 结果 | 证据（模拟口径） |
|---|---|---|---|
| A1 | 非本人／非已完成订单触达申请路径 | 通过 | 界面叙述：已取消订单详情无入口；直接调接口返回提示「仅已完成订单可申请退货」。 |
| A2 | 已有未到终态退货单再发起 | 通过 | 界面叙述：入口置灰提示「已有进行中的售后申请」；重复提交接口同样拦截返回该文案。 |
| A3 | 已退款完成订单再发起 | 通过 | 接口叙述（构造模拟数据）：返回「该订单售后已完成，不可重复申请」。 |
| A4 | 原因长度不足 5 字 | 通过 | 界面叙述：输入「坏了」点提交，即时提示「请填写 5~200 字退货原因」，未发起请求。 |
| A5 | 凭证 0 张／超 3 张／单张超 5MB | 通过 | 界面叙述：不选图提交被拦；选第 4 张与 6MB 图即时提示「请上传 1~3 张图片（jpg／png／webp，每张不超过 5MB）」，超限图不入列。 |
| A6 | 提交／撤回请求失败 | 通过 | 界面叙述（断网模拟）：提示「提交失败，请稍后重试」，原因与已选凭证保留。 |
| A7 | 撤回二次确认点「暂不撤回」 | 通过 | 界面叙述：弹层关闭，退货单保持待审核。 |

## 3. 运行方式

按「代码已按 PRD 实现」口径（模拟）：服务端随交易模块分包部署（单服务形态），商城端（移动 Web）发布后，会员登录→我的订单→已完成订单详情→申请退货；验收用数据＝一笔本人已完成订单（含可上传的凭证图片）。本演练未产出可运行包，操作路径以本版 PRD 第 4 章 R41 交互与流程为准。

## 4. 已知限制与待确认

- 本版为文档范本演练，无真实代码与运行产物，全部证据为模拟口径（见引言）。
- 待审核／已取消之外的状态字样（待退货／退款完成／已拒绝）与订单「售后中」流转随 v0.4.1 上线后呈现，本版界面不出现。
- 独立售后记录列表入口随 0.5 个人记录入口聚合，本版仅订单详情进入。
- 审核结论与审核理由字段未在本版建表范围（随 v0.4.1 认领定名登记，术语表已注）。
- 无待确认歧义项：实现过程未发现 PRD 缺口或歧义。
