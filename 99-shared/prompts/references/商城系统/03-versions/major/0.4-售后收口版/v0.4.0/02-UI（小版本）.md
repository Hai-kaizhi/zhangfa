# 好物商城 v0.4.0 · UI 生图脚本（小版本）

> 本文档是 v0.4.0 售后受理版的 UI 生图脚本：生图提示词由 GPT 在对话中分析资料后自己撰写，本文档只提供资料清单与分步话术；风格锚定整段沿用项目层脚本（唯一来源在项目层 `01-project-docs/04B-ui/04B-UI（项目）.md` 附 A），本版不出现任何新色值；覆盖只圈本版认领条目（R41 退货申请）触及的界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质予以保留。

新建一个 GPT 对话，一次性把「必给」资料粘贴给 GPT，然后按第 1 步开始。

## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

> 我要为「好物商城」v0.4.0 售后受理版生成 UI 设计图。请先通读我提供的全部资料，然后**只做一件事：撰写第一张图——商城端（手机竖屏 9:19.5）「申请退货」页的生图提示词。先只输出提示词，不要生成图片。**
>
> 撰写提示词时必须遵循以下风格锚定（不得偏离，与项目层脚本一致）：
> - **色板（精确 hex，为本项目品牌色唯一来源）**：主色 `#DA3A2B`（暖正红，用于主行动按钮、强调、选中态）；营销强调色 `#FF6A00`（仅用于秒杀/促销标签，本版界面不使用）；成功 `#2FA65A`、警告 `#E8A33D`、危险 `#D85555`；中性色阶：文字主 `#1F2329`、次级 `#4E5969`、辅助 `#86909C`、分隔 `#C9CDD4`、页面底 `#F2F3F5`、卡片 `#FFFFFF`。整体白底为主、主色点缀，克制清爽。
> - **字体与组件形态**：系统默认无衬线中文字体；卡片式布局、圆角 8px、轻投影；本页为二级页面，顶部返回导航＋页面标题。
> - **通用禁止**：界面文字全部为简体中文；不得出现"平台、商家入驻、多商户、分账"等字样或概念（本产品为单一卖方自营）；不得出现英文界面文案、第三方品牌标识、支付渠道以外的金融元素；人像与插画仅作占位不出现真实品牌。
> - **核心界面必须元素（逐条画出）**：页面标题「申请退货」；订单信息摘要卡（订单号、已完成状态标记、商品缩略图占位）；「退货原因」区块——常见原因快捷选项（质量不佳／商品与描述不符／少件漏发／不想要了／其他，标签可多选其一高亮）＋原因文本输入区（提示语「请填写 5~200 字退货原因」）；「上传凭证」区块——图片九宫格上传位（已传 2 张示意＋虚线添加位，角标注「1~3 张」）；底部主行动按钮「提交申请」（主色）；辅助说明行「客服审核前可撤回申请」。
> - **称谓纪律**：C 端登录后使用者界面称"会员"，状态名严格按我提供的术语表中文原文（本页状态仅可出现「已完成」）。
> - **本版附加禁止**：不得出现退款金额输入、退货物流单号填写、客服审核操作区、管理端元素；不得出现「待退货、退款完成、已拒绝、售后中」等本版不可达的状态字样；不得出现评价、咨询入口。
>
> 提示词结构要求：先一段总述（风格与布局意图），再分区块描述（从上到下），最后列出色彩与文字约束。输出后停下来等我确认。

## 2. 第二步：生成并迭代核心界面

确认提示词无误后，发送：

> 请用这张「申请退货」提示词生成图片（竖屏手机端）。

迭代方法（验收三问）：①信息点是否全——快捷原因、文本区、九宫格凭证、提交按钮、辅助说明逐条在图上；②风格是否同源——色板、圆角、卡片形态与项目层主页基准一致；③纪律是否守住——无英文文案、无范围外元素。对不满意的局部直接描述改哪里（如「凭证区块改为三列九宫格，保持其余不变」），让 GPT 修改提示词后重新生成。**满意的那一版即本版基准，并与项目层脚本生成的主页基准并检一次**（防跨版本风格漂移）。色彩如需微调，改项目层脚本附 A 色值表并同步其第一步话术中的 hex，本脚本随之更新。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 本版核心界面（申请退货页）风格已定（以上一张满意图为基准）。请基于资料规划本版其余 UI 图片，**先输出完整清单（说明总数与每张的作用），经我确认后再逐张输出提示词**。规划必须满足以下覆盖要求：
>
> - **覆盖范围＝本版认领条目 R41 退货申请（商城端手机竖屏 9:19.5），本版为买家操作面版本、无机制条目（不存在"无界面不生成"的条目）**。必须覆盖的界面：
>   1. **订单详情（已完成）**：商品与订单信息、订单状态「已完成」、可用的「申请退货」入口（主色按钮）。
>   2. **订单详情·售后进度卡片（待审核）**：退货单号、状态标签「待审核」（警告色）、申请时间、原因摘要、凭证缩略图、「撤回申请」次级按钮。
>   3. **撤回二次确认弹层**：文案「撤回后本次申请终止，可重新发起」＋「确认撤回」「暂不撤回」两按钮。
>   4. **售后进度卡片（已取消态）**：状态标签「已取消」（辅助色）、「申请退货」入口恢复可用，体现可再次发起。
>   5. **拦截态——已有进行中售后申请**：「申请退货」入口置灰，提示「已有进行中的售后申请」。
>   6. **拦截态——凭证上传超限**：上传区块提示「请上传 1~3 张图片（jpg／png／webp，每张不超过 5MB）」，超限图片带失败标记。
>   7. **表单校验态——原因长度不足**：原因输入区错误提示「请填写 5~200 字退货原因」（危险色），提交按钮不变。
>   8. **对照态——非已完成订单详情**（如已取消订单）：无「申请退货」入口的订单详情形态。
> - **信息点逐条转译**：字段必填与格式限制、各拦截与校验提示文案、状态标签颜色语义（待审核＝警告色、已取消＝辅助色）都要体现在对应图中；生图文字是幻觉，界面文案以上述 PRD 锚定为准。
> - **本版附加禁止**：不得出现管理端界面与客服审核操作、退款金额、物流单号；状态字样仅限「已完成、待审核、已取消」；不得出现评价、咨询、会员等级等后续版本元素。
> - 通用禁止与称谓纪律同第一张图。风格、色板、组件形态一律向已定基准看齐。
>
> 清单确认后再逐张输出提示词，每张输出后停下等我确认。

## 4. 第四步：批量生成

清单确认后，发送：

> 按清单顺序逐张生成图片，每张生成后停顿，等我记录后再继续下一张。

单张迭代方法：同第 2 步，逐张局部修正；整批完成后如出现风格漂移，回引本版基准图（申请退货页）让 GPT 校正后重生成该张。

## 5. 收尾：回填归档

全部图片满意后，把每张图的信息回填到本文档附 B（图／界面与端／主要偏差／色彩微调记录）；如做了色彩微调，须同步**项目层脚本附 A**（唯一来源）与本版话术中的 hex，保持「文档色值＝品牌色唯一来源」。本版新增界面的要素不回写项目层脚本（风格变更才回写项目层）。

## 附注 其他生图模型的差异

使用即梦等无对话记忆的生图模型时：把第 1 步话术连同资料摘要、风格锚定全文一并放入提示词前置段落；每次生成单张图时重复附上风格锚定与该图提示词；迭代以「新对话＋完整提示词」方式进行，回填流程相同。
