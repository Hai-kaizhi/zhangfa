# 好物商城 v0.3.1 · UI 生图脚本（小版本）

> 本文档是 v0.3.1 的 UI 生图脚本：生图提示词由 GPT 分析资料后自己撰写，本文只给资料清单与话术；风格锚定（色板、令牌、组件形态、通用禁止）整段沿用项目层脚本《UI（项目）》附 A——风格唯一来源在项目层，本版不新增任何色值；覆盖只圈本版认领条目（R38~R40）触及的界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质予以保留。

新建一个 GPT 对话，一次性粘贴"必给"资料，然后按第 1 步开始。

## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

> 我在为「好物商城」v0.3.1（促销下单版）生成 UI 设计图。请先通读我提供的资料（含 v0.2.1 订单确认页与 v0.3.0 促销基准），然后**只做一件事：撰写第一张图——商城端「订单确认页·含选券器」（移动端竖屏 9:19.5）的生图提示词。先只输出提示词，不要生成图片。**
>
> 撰写提示词时必须遵循以下风格锚定（逐字沿用项目层脚本，不得偏离、不得新增色值）：
> - **色板（精确 hex，唯一来源为项目层附 A）**：主色 `#DA3A2B`（主行动按钮、价格强调、选中态）；营销强调色 `#FF6A00`（促销价格与券面额大字、秒杀标签）；成功 `#2FA65A`、警告 `#E8A33D`、危险 `#D85555`；文字主 `#1F2329`、次级 `#4E5969`、辅助 `#86909C`；边框 `#C9CDD4`、页面底 `#F2F3F5`、卡片 `#FFFFFF`。白底为主、主色点缀。
> - **字体与组件形态**：系统默认无衬线中文字体；卡片式布局、圆角 8px、轻投影；商城端移动端布局（沿用 v0.2.1 底部导航与页面骨架）。
> - **通用禁止（整段继承项目层）**：界面文字全部为简体中文；不得出现"平台、商家入驻、多商户、分账"等字样或概念；不得出现英文界面文案、第三方品牌标识、支付渠道以外的金融元素。
> - **本版附加禁止**：不出现退货退款、售后入口（随 0.4）；不出现评价、咨询（随 0.5）；不出现会员等级（随 0.6）；秒杀确认页不得出现选券器（本版秒杀路径不叠加用券）。
> - **订单确认页·含选券器必须元素**：默认收货地址卡（可切换）；条目清单；**优惠券行**（已选券呈现"－券面额〔营销强调色〕"，未选呈现"选择优惠券 ＞"）；**选券器弹层**（可用券卡列表：面额大字〔营销强调色〕、使用门槛、有效期至、单选；不可用券置灰并标注原因——"未满足使用门槛"/"已过期"/"已使用"；无可用时呈现"暂无可用优惠券"）；金额明细（商品合计、券抵扣行、应付）；"提交订单"主按钮。
> - **称谓与状态纪律**：界面用语严格按术语表与 PRD 原文；券状态名逐字为"未使用/已使用/已过期"；金额展示元两位小数。
>
> 提示词结构要求：先一段总述，再从上到下分区块描述，最后列色彩与文字约束。输出后停下等我确认。

## 2. 第二步：生成与迭代核心界面

确认后发送：

> 请用这张订单确认页提示词生成图片（移动端竖屏）。

迭代方法（验收三问）：信息点是否齐全（地址、条目、券行与选券器弹层三置灰原因、明细三行、主按钮）？风格是否与 v0.2.1 订单确认页及 v0.3.0 促销基准一致（并检一次）？界面用语是否与 PRD 逐字一致？满意后即为本版基准。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 基准已定。请基于资料规划 v0.3.1 其余 UI 图片，**先输出完整清单（说明总数与每张的作用），经我确认后再逐张输出提示词**。覆盖要求（只圈本版认领条目 R38~R40，含异常态与空态）：
>
> - **商城端（移动竖屏 9:19.5）**：
>   - 秒杀活动页（R39/R40）：四态——待开始（开始时间预告＋不可购买）、进行中（秒杀价〔营销强调色〕＋剩余库存＋"秒杀购买"主按钮）、已结束、已售罄（置灰）；**必须画出**进行中态与已售罄态两张。
>   - 秒杀价确认页（R40）：单条目（秒杀价大字）、地址卡、金额明细（无券行）、提交按钮；**必须画出**限购拦截反馈"每人限购 1 件"与抢完失败反馈"已抢完"。
>   - 商品详情页秒杀价条（R40 入口）：进行中活动商品详情页顶部呈现秒杀价与"去秒杀"入口（营销强调色）。
>   - 我的优惠券·已使用态（R38 呈现＋v0.3.0 预留补齐）：已使用券卡（置灰、标注使用时间）；取消订单后券回到"未使用"的状态变化说明图（两卡对照）。
>   - 订单详情促销信息（R40）：订单详情金额明细含"券抵扣"行。
> - **机制条目声明**：R38 核销与退回、R39 资格与预扣均为下单/取消事务内机制，无人工界面、不生成图（效果经持券状态、活动库存与订单金额呈现；管理端秒杀列表已随 v0.3.0 交付，sold_qty 变化在既有列表体现，不重复生成）。
> - 除上述外不得出现本版范围外界面（无售后、无评价、无会员、无报表）。
>
> 风格、色板、组件形态、通用禁止与本版附加禁止一律沿用基准与项目层附 A；界面用语逐字沿用术语表与 PRD。

## 4. 第四步：批量生成

清单确认后发送：

> 按清单顺序逐张生成图片，每张生成后停顿，等我记录后再继续下一张。

单张迭代方法同第 2 步；如出现风格漂移，回引基准图校正后重生成该张。

## 5. 收尾：回填归档

全部图片满意后回填附 B（图／界面与端／主要偏差／色彩微调记录）。**色彩如需微调，必须先改项目层脚本附 A（唯一来源）再同步本版话术**，本版不自行定新色值。

## 附注 其他生图模型的差异

使用即梦等无对话记忆的生图模型时：把第 1 步话术连同资料摘要、风格锚定全文一并前置；每张图生成时重复附上风格锚定与该图提示词；迭代以新对话＋完整提示词进行，回填流程相同。
