# 好物商城 v0.3.0 · UI 生图脚本（小版本）

> 本文档是 v0.3.0 的 UI 生图脚本：生图提示词由 GPT 分析资料后自己撰写，本文只给资料清单与话术；风格锚定（色板、令牌、组件形态、通用禁止）整段沿用项目层脚本《UI（项目）》附 A——风格唯一来源在项目层，本版不新增任何色值；覆盖只圈本版认领条目（R32~R37）触及的界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质予以保留。

| 资料 | 位置 | 必给或可选 |
|---|---|---|

新建一个 GPT 对话，一次性粘贴"必给"资料，然后按第 1 步开始。

## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

> 我在为「好物商城」v0.3.0（促销配置版）生成 UI 设计图。请先通读我提供的资料（含 v0.2.1 既有基准），然后**只做一件事：撰写第一张图——管理端「新建秒杀活动」表单页（PC 横屏 16:9，左侧导航＋表单）的生图提示词。先只输出提示词，不要生成图片。**
>
> 撰写提示词时必须遵循以下风格锚定（逐字沿用项目层脚本，不得偏离、不得新增色值）：
> - **色板（精确 hex，唯一来源为项目层附 A）**：主色 `#DA3A2B`（主按钮、选中态）；营销强调色 `#FF6A00`（**仅用于促销相关强调**——秒杀标签与促销价格，本版为其正当使用场景，项目层口径）；成功 `#2FA65A`、警告 `#E8A33D`、危险 `#D85555`；文字主 `#1F2329`、次级 `#4E5969`、辅助 `#86909C`；边框 `#C9CDD4`、页面底 `#F2F3F5`、卡片 `#FFFFFF`。白底为主、主色点缀。
> - **字体与组件形态**：系统默认无衬线中文字体；卡片式布局、圆角 8px、轻投影；管理端 PC 布局（左侧导航仅营销管理相关菜单）。
> - **通用禁止（整段继承项目层）**：界面文字全部为简体中文；不得出现"平台、商家入驻、多商户、分账"等字样或概念；不得出现英文界面文案、第三方品牌标识、支付渠道以外的金融元素。
> - **本版附加禁止**：不出现订单选券抵扣界面与"已使用"券实例（随 0.3.1）；不出现秒杀活动页与秒杀购买按钮（买家侧活动页随 0.3.1）；不出现退货退款、评价、会员等级元素。
> - **新建秒杀活动表单必须元素**：关联商品下拉（仅已上架商品）＋规格选择、秒杀价输入（元，标注"需低于日常售价"）、活动库存输入、每顾客限购（固定 1 件，只读展示）、起止时间选择器、底部"保存"主按钮；行内校验示例（"秒杀价需为正整数且低于日常售价"/"该规格在所选时段已有活动"）。
> - **称谓与状态纪律**：界面用语严格按术语表与 PRD 原文；活动状态名逐字为"待开始/进行中/已结束"；券状态名逐字为"未使用/已使用/已过期"；金额展示元两位小数。
>
> 提示词结构要求：先一段总述，再从上到下分区块描述，最后列色彩与文字约束。输出后停下等我确认。

## 2. 第二步：生成并迭代核心界面

确认后发送：

> 请用这张新建秒杀活动表单提示词生成图片（PC 横屏）。

迭代方法（验收三问）：信息点是否齐全（六要素＋只读限购＋校验反馈）？风格是否与 v0.2.1 管理端基准一致（并检一次）？界面用语是否与 PRD 逐字一致？满意后即为本版基准。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 基准已定。请基于资料规划 v0.3.0 其余 UI 图片，**先输出完整清单（说明总数与每张的作用），经我确认后再逐张输出提示词**。覆盖要求（只圈本版认领条目 R32~R37，含异常态与空态）：
>
> - **管理端（PC 横屏 16:9）**：
>   - 券模板列表页（R32）：列表（券名称、面额/门槛〔元〕、有效期天数、发放量/已发放量、发放状态〔发放中/已停用〕、操作）；**必须画出**空态"暂无券模板，请新建第一个券模板"。
>   - 新建/编辑券模板表单（R32）：五要素＋行内校验（"面额不得超过使用门槛"/"有效期天数需为不小于 1 的整数"）；**必须画出**被持有时面额与门槛只读态（角标"已被持有，面额与门槛不可修改"）。
>   - 删除与停用拦截（R32/R33）：**必须画出**删除被持有模板拦截"该模板已被 N 人持有，不可删除"；停用二次确认弹窗（含"停用后买家不可再领取，已发持有按原有效期走完"说明）。
>   - 秒杀活动列表页（R36）：三态状态标签（待开始＝辅助色、进行中＝营销强调色 `#FF6A00`、已结束＝危险色）＋操作（仅待开始可编辑/删除）；**必须画出**编辑拦截"活动已开始，不可编辑"与空态"暂无秒杀活动，请新建第一个活动"。
> - **商城端（移动竖屏 9:19.5）**：
>   - 领券中心页（R34）：可领券卡列表（券名称、面额〔营销强调色大字〕、使用门槛、有效期说明"领取后 N 天有效"、"领取"按钮）；**必须画出**四类拦截反馈——"该券已停止发放"/"该券已抢完"/"您已领取该券"（按钮变"已领取"置灰）/未登录点击引导登录。
>   - 个人中心·我的优惠券（R35）：状态筛选（未使用/已使用/已过期三标签）＋券卡（面额、门槛、有效期至）；**必须画出**空态"暂无优惠券，去领券中心逛逛"与"已使用"列表空态（标注"下单用券随下一版本开放"）。
> - **机制条目声明**：R37 档期自动执行为调度任务，无人工界面、不生成图（效果经活动状态标签与持券过期状态呈现）。
> - 除上述外不得出现本版范围外界面（无选券下单、无秒杀活动页、无订单/售后/评价）。
>
> 风格、色板、组件形态、通用禁止与本版附加禁止一律沿用基准与项目层附 A；界面用语逐字沿用术语表与 PRD。

## 4. 第四步：批量生成

清单确认后发送：

> 按清单顺序逐张生成图片，每张生成后停顿，等我记录后再继续下一张。

单张迭代方法同第 2 步；如出现风格漂移，回引基准图校正后重生成该张。

## 5. 收尾：回填归档

全部图片满意后回填附 B（图／界面与端／主要偏差／色彩微调记录）。**色彩如需微调，必须先改项目层脚本附 A（唯一来源）再同步本版话术**，本版不自行定新色值。

## 附注 其他生图模型的差异

使用即梦等无对话记忆的生图模型时：把第 1 步话术连同资料摘要、风格锚定全文一并前置；每张图生成时重复附上风格锚定与该图提示词；迭代以新对话＋完整提示词进行，回填流程相同。
