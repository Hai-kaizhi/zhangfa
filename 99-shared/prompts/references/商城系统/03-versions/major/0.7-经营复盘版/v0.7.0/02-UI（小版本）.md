# 好物商城 v0.7.0 · UI 生图脚本（小版本）

> 本文档是 v0.7.0 经营报表版的 UI 生图脚本：生图提示词由 GPT 在对话中分析资料后自己撰写，本文档只提供资料清单与分步话术；风格锚定整段沿用项目层脚本（唯一来源在 `01-project-docs/04B-ui/04B-UI（项目）.md` 附 A），本版不出现任何新色值；覆盖只圈本版认领条目（R63~R66 操作面；派生取数与预聚合为机制部分无界面；本版为纯管理端版本，商城端零界面）；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质予以保留。

| 资料 | 位置 | 必给或可选 |

| PRD（小版本）v0.7.0 | `04-workspace/v0.7.0/01-PRD（小版本）.md` | 必给（界面与信息点唯一来源） |

新建一个 GPT 对话，一次性把「必给」资料粘贴给 GPT，然后按第 1 步开始。

## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

> 我要为「好物商城」v0.7.0 经营报表版生成 UI 设计图。请先通读我提供的全部资料，然后**只做一件事：撰写第一张图——管理端（PC 横屏 16:9，左侧导航＋内容区布局）「商品销售统计」页的生图提示词。先只输出提示词，不要生成图片。**
>
> 撰写提示词时必须遵循以下风格锚定（不得偏离，与项目层脚本一致）：
> - **色板（精确 hex，为本项目品牌色唯一来源）**：主色 `#DA3A2B`（暖正红，用于主行动按钮、趋势高亮、选中态）；营销强调色 `#FF6A00`（仅用于秒杀/促销标签，本版界面不使用）；成功 `#2FA65A`、警告 `#E8A33D`、危险 `#D85555`；中性色阶：文字主 `#1F2329`、次级 `#4E5969`、辅助 `#86909C`、分隔 `#C9CDD4`、页面底 `#F2F3F5`、卡片 `#FFFFFF`。整体白底为主、主色点缀，克制清爽。
> - **字体与组件形态**：系统默认无衬线中文字体；卡片式布局、圆角 8px、轻投影；管理端为左侧导航（仅体现管理者可见的授权菜单，含「统计报表」）＋右侧内容区；图表用简洁柱状／占比条，不使用花哨可视化。
> - **通用禁止**：界面文字全部为简体中文；不得出现"平台、商家入驻、多商户、分账"等字样或概念（本产品为单一卖方自营）；不得出现英文界面文案、第三方品牌标识、支付渠道以外的金融元素；人像与插画仅作占位不出现真实品牌。
> - **核心界面必须元素（逐条画出）**：左侧导航「统计报表」高亮（子项：商品销售统计／订单统计／会员统计）；筛选区——时间窗四档标签（今日／近 7 天／近 30 天／自定义，当月为默认示例）＋分类与品牌下拉＋关键词输入＋「查询」「导出」按钮（导出为主色、管理者专属）；统计表卡——列头「商品／规格｜销量｜毛额（元）｜净额（元）」，五行示例数据（商品名＋规格名占位、两位小数金额），净额列倒序；底部对账条——「净额合计 ¥23,400.00＝台账收入−支出−冲正净额，与台账一致」附成功色对勾标识。
> - **称谓纪律**：订单与顾客状态名严格按我提供的术语表中文原文；内部人员按角色名（管理者／运营人员）。
> - **本版附加禁止**：不得出现经营预测、自定义多维分析、实时大屏元素；不得出现导出格式选择器（固定 xlsx）；不得出现商城端任何元素。
>
> 提示词结构要求：先一段总述（风格与布局意图），再分区块描述（从左到右、从上到下），最后列出色彩与文字约束。输出后停下来等我确认。

## 2. 第二步：生成并迭代核心界面

确认提示词无误后，发送：

> 请用这张「商品销售统计」提示词生成图片（PC 横屏管理端）。

迭代方法（验收三问）：①信息点是否全——筛选区、双列金额、对账条、导出按钮逐条在图上；②风格是否同源——色板、圆角、卡片形态与项目层主页基准一致；③纪律是否守住——无英文文案、无范围外元素。对不满意的局部直接描述改哪里，让 GPT 修改提示词后重新生成。**满意的那一版即本版基准，并与项目层脚本生成的主页基准并检一次**（防跨版本风格漂移）。色彩如需微调，改项目层脚本附 A 色值表并同步其第一步话术中的 hex，本脚本随之更新。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 本版核心界面（商品销售统计页）风格已定（以上一张满意图为基准）。请基于资料规划本版其余 UI 图片，**先输出完整清单（说明总数与每张的作用），经我确认后再逐张输出提示词**。规划必须满足以下覆盖要求：
>
> - **覆盖范围＝本版认领条目 R63~R66 的操作面；机制部分声明——派生取数与预聚合为系统机制无独立界面不生成图；本版为纯管理端版本、商城端零界面不生成任何商城端图**。必须覆盖的界面（均为管理端 PC 横屏 16:9，左侧导航＋内容区布局）：
>   1. 订单统计页——完成指标卡（完成订单量、完成金额）＋状态分布卡（待支付／待发货／已发货／已完成／已取消／售后中六状态单量，状态名严格按术语表）＋按日完成量柱状趋势（近 30 天）。
>   2. 会员统计页——规模卡（当期存量／历史累计／本期新增）＋等级分布卡（各等级人数与占比条）＋复购卡（复购顾客数、复购率）。
>   3. 商品销售统计·规格行下钻态——点击行展开完成订单号列表（只读）。
>   4. 对账差异提示态——对账条呈警告色「存在在途事实差异，核对以单据状态为准」。
>   5. 空态——三类报表各一张或择最必要一张示意（「所选时间窗暂无销售数据」示例）。
>   6. 时间范围校验异常态——起止倒置时危险色提示「请选择正确的时间范围」。
>   7. 导出反馈态——导出成功提示（文件生成并开始下载）＋「最近导出记录」列表（时间、报表类型、范围、操作者）。
>   8. 导出频控拦截态——提示「今日导出次数已达上限（10 次／天），请明日再试」。
>   9. 按角色授权对照态——管理者视角含「导出」按钮与订单统计菜单，运营人员视角无导出按钮且菜单仅商品销售统计与会员统计，客服人员视角无「统计报表」菜单（体现按角色仅见授权菜单）。
> - **信息点逐条转译**：金额均为人民币元两位小数；六状态名与等级名严格按术语表；对账一致用成功色对勾、差异用警告色；各提示与空态文案逐字体现；生图文字是幻觉，界面文案以上述 PRD 锚定为准。
> - **本版附加禁止**：不得出现预测曲线、多维自定义分析器、实时刷新大屏；不得出现导出格式选择；不得出现商城端与买家侧元素。
> - 通用禁止与称谓纪律同第一张图。风格、色板、组件形态一律向已定基准看齐。
>
> 清单确认后再逐张输出提示词，每张输出后停下等我确认。

## 4. 第四步：批量生成

清单确认后，发送：

> 按清单顺序逐张生成图片，每张生成后停顿，等我记录后再继续下一张。

单张迭代方法：同第 2 步，逐张局部修正；整批完成后如出现风格漂移，回引本版基准图（商品销售统计页）让 GPT 校正后重生成该张。

## 5. 收尾：回填归档

全部图片满意后，把每张图的信息回填到本文档附 B（图／界面与端／主要偏差／色彩微调记录）；如做了色彩微调，须同步**项目层脚本附 A**（唯一来源）与本版话术中的 hex，保持「文档色值＝品牌色唯一来源」。本版新增界面的要素不回写项目层脚本（风格变更才回写项目层）。

## 附注 其他生图模型的差异

使用即梦等无对话记忆的生图模型时：把第 1 步话术连同资料摘要、风格锚定全文一并放入提示词前置段落；每次生成单张图时重复附上风格锚定与该图提示词；迭代以「新对话＋完整提示词」方式进行，回填流程相同。
