# 好物商城 v0.1.0 · UI 生图脚本（小版本）

> 本文档是 v0.1.0 的 UI 生图脚本：生图提示词由 GPT 分析资料后自己撰写，本文只给资料清单与话术；风格锚定（色板、令牌、组件形态、通用禁止）整段沿用项目层脚本《UI（项目）》附 A——风格唯一来源在项目层，本版不新增任何色值；覆盖只圈本版认领条目（R1~R7）触及的界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质予以保留。

## 0. 准备：给 GPT 哪些资料

| 资料 | 位置 | 必给或可选 |
|---|---|---|
| PRD（小版本） | `04-workspace/v0.1.0/01-PRD（小版本）.md` | 必给（界面与信息点唯一来源） |
| UI（项目）脚本 | `01-project-docs/04B-ui/04B-UI（项目）.md` | 必给（风格锚定与令牌映射唯一来源） |

新建一个 GPT 对话，一次性粘贴"必给"资料，然后按第 1 步开始。

## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

> 我在为「好物商城」管理端 v0.1.0（权限基座版）生成 UI 设计图。请先通读我提供的资料，然后**只做一件事：撰写第一张图——管理端「账号管理」列表页（PC 横屏 16:9，左侧导航＋顶部筛选＋账号表格）的生图提示词。先只输出提示词，不要生成图片。**
>
> 撰写提示词时必须遵循以下风格锚定（逐字沿用项目层脚本，不得偏离、不得新增色值）：
> - **色板（精确 hex，唯一来源为项目层附 A）**：主色 `#DA3A2B`（主按钮、选中态）；成功 `#2FA65A`、警告 `#E8A33D`、危险 `#D85555`（状态标签与危险操作）；文字主 `#1F2329`、次级 `#4E5969`、辅助 `#86909C`；边框 `#C9CDD4`、页面底 `#F2F3F5`、卡片 `#FFFFFF`。白底为主、主色点缀，克制清爽。
> - **字体与组件形态**：系统默认无衬线中文字体；卡片式布局、圆角 8px、轻投影；管理端为 PC 布局（左侧导航＋内容区）。
> - **通用禁止（整段继承项目层）**：界面文字全部为简体中文；不得出现"平台、商家入驻、多商户、分账"等字样或概念；不得出现英文界面文案、第三方品牌标识、支付渠道以外的金融元素。
> - **本版附加禁止**：本版界面不得出现商品、订单、会员、优惠券、秒杀等业务概念与字样（那些归后续版本）；不得出现移动端界面（本版全部为管理端 PC 页面）。
> - **账号管理页必须元素**：顶部筛选区（账号名输入、角色下拉、状态下拉、查询按钮）、账号表格（账号名、显示名、所持角色标签、状态标签〔正常＝成功色、停用＝危险色〕、最近登录时间、"停用/启用"行内操作）、右上"开通账号"主按钮、分页条；左侧导航仅呈现权限管理相关菜单。
> - **称谓纪律**：界面用语严格按术语表与 PRD 原文（如"管理端账号""角色""停用""启用"），不得同义改写。
>
> 提示词结构要求：先一段总述（风格与布局意图），再分区块描述（从左到右、从上到下），最后列色彩与文字约束。输出后停下等我确认。

## 2. 第二步：生成并迭代核心界面

确认后发送：

> 请用这张账号管理页提示词生成图片（PC 横屏）。

迭代方法（验收三问）：信息点是否齐全（筛选、表格列、状态标签、操作、开通入口）？风格是否与项目层附 A 一致（白底、主色点缀、圆角卡片）？界面用语是否与 PRD 逐字一致？满意后**与项目层脚本已生成的主页基准图并检一次**（防跨版本风格漂移），并检通过即为本版基准。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 账号管理页基准已定。请基于资料规划 v0.1.0 其余 UI 图片，**先输出完整清单（说明总数与每张的作用），经我确认后再逐张输出提示词**。覆盖要求（只圈本版认领条目 R1~R7，含异常态与空态）：
>
> - **登录页**：账号名与凭据输入、登录按钮；**必须画出异常态**——凭据错误提示"账号名或凭据不正确"、锁定提示"账号已锁定，请稍后再试"、停用提示"账号已停用"。
> - **强制重置凭据页**：首次登录引导（新凭据两次输入），**必须画出校验失败反馈**（"新凭据需至少 8 位且同时包含字母与数字"/"两次输入不一致"）。
> - **开通账号表单**：账号名、显示名、初始角色多选、保存按钮；**必须画出**行内校验失败反馈（"账号名已存在"）与保存成功后的一次性初始凭据完整展示态（标注"仅此一次展示"）。
> - **账号停用确认弹窗**：展示账号名、显示名、所持角色、当前状态；**必须画出**停用后被拒态（"账号已停用"跳登录页）与自停拦截提示（"不能停用当前登录的账号"）。
> - **角色管理页**：角色列表（角色名、说明、能力点数量、引用账号数）；**必须画出**能力点勾选树编辑态（按模块分组两级树）与删除被引用角色的拦截提示（"该角色已被 N 个账号使用，不可删除"）。
> - **个人设置页**：显示名修改与凭据重置两个分区；**必须画出**"旧凭据不正确"拦截反馈。
> - **空态必须画出**：账号列表空态（"暂无账号，点击开通账号创建第一个账号"）、角色列表空态（"暂无角色，请新建第一个角色"）。
> - **机制条目声明**：权限校验机制本身无界面、不生成图；除上述界面外不得出现本版范围外界面（无商品、无订单、无移动端）。
>
> 风格、色板、组件形态、通用禁止与本版附加禁止一律沿用第一张图基准与项目层附 A；界面用语逐字沿用术语表与 PRD。

## 4. 第四步：批量生成

清单确认后发送：

> 按清单顺序逐张生成图片，每张生成后停顿，等我记录后再继续下一张。

单张迭代方法同第 2 步；如出现风格漂移，回引账号管理页基准图校正后重生成该张。

## 5. 收尾：回填归档

全部图片满意后回填附 B（图／界面与端／主要偏差／色彩微调记录）。**色彩如需微调，必须先改项目层脚本附 A（唯一来源）再同步本版话术**，本版不自行定新色值。

## 附注 其他生图模型的差异

使用即梦等无对话记忆的生图模型时：把第 1 步话术连同资料摘要、风格锚定全文一并前置；每张图生成时重复附上风格锚定与该图提示词；迭代以新对话＋完整提示词进行，回填流程相同。
