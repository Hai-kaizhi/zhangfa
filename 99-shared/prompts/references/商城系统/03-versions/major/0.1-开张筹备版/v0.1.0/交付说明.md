# 交付说明：v0.1.0 权限基座版

> 本版开发交付说明：承接小版本 PRD 认领条目 R1~R7 的实现清单、验收锚自检、运行方式与已知限制。**本文档为文档范本演练**：本版不产出真实代码文件，实现清单与自检证据均按「代码已按 PRD 实现」的模拟口径编写（证据为模拟界面／接口／日志叙述），供流程范本参考；上游为模拟案例材料，模拟性质予以保留。

## 1. 实现清单（条目｜代码位置｜实现要点）

| 条目 | 代码位置（模拟口径） | 实现要点 |
|---|---|---|
| R1 账号开通 | server 端 `com.haowu.auth` 账号服务；管理端 `apps/admin-web` 权限管理＞账号管理＞开通表单 | 唯一性校验（account_name 唯一索引兜底）；系统生成一次性初始凭据（≥8 位含字母数字）仅完整展示一次；must_reset_credential 置是；开通留痕 |
| R2 账号查询 | server 端账号查询接口；管理端账号列表页 | 账号名模糊／角色／状态组合筛选；分页默认 20 条；状态标签配色（正常＝成功色、停用＝危险色）；凭据不出参 |
| R3 ◆ 账号停用与启用 | server 端账号状态处置；管理端列表行操作＋确认弹窗 | 二次确认展示账号名／显示名／所持角色；停用即时失效（令牌受众校验＋服务端状态兜底）；自停拦截；处置留痕 |
| R4 角色增删改查 | server 端角色服务；管理端角色管理页 | 角色名唯一；能力点勾选树（本版仅权限模块组）；被引用角色删除拦截（引用计数）；能力点编码 `<模块>:<对象>:<动作>` |
| R5 ◆ 角色授权与账号分派 | server 端授权服务；管理端角色编辑＋账号角色编辑 | 多角色能力点并集即时重算；变更即时生效（不要求重登）；自锁拦截（保留权限管理能力校验）；变更留痕 |
| R6 管理端登录与登出 | server 端认证（JWT 管理端受众）；管理端登录页 | 统一失败提示不暴露账号存在性；连续失败 5 次锁 15 分钟；停用账号登录即拒；令牌 24 小时；首次登录跳强制重置 |
| R7 自身资料与凭据重置 | server 端个人设置接口；管理端个人设置页 | 显示名修改即时生效；凭据重置验旧凭据＋两次一致＋强度校验；重置后当前令牌不作废；不提供角色变更入口 |
| 数据层 | 建表 auth_account／auth_role／auth_account_role（落库字段逐字按术语表 v0.1.0 权限域登记行） | 审计三字段齐备；auth_account_role 唯一索引（account_id＋role_id）防重 |

## 2. 验收锚自检（锚原文｜结果｜证据）

（04 黑盒验收按 PRD 第 2 章验收锚逐条执行；以下证据为模拟界面／接口／日志叙述。）

| 锚原文 | 结果 | 证据 |
|---|---|---|
| R1：管理者开通账号并指定初始角色后，被开通人能以该账号登录管理端，且首次登录被强制重置凭据 | 通过 | 模拟界面：开通表单保存成功弹出一次性凭据页（顶部标注"仅此一次展示，请妥善交付"）；模拟日志 `AUTH-OP action=account:create operator=管理员甲 target=账号 op001 roles=[运营角色]`；以 op001＋初始凭据登录，被跳转"强制重置凭据"页，设置新凭据两次一致后进入管理端 |
| R2：管理者按账号名、角色或状态检索，能找到目标账号并查看其角色与状态 | 通过 | 模拟接口：`GET 管理端/auth/accounts?accountName=op&status=NORMAL` 返回列表含 op001（显示名、所持角色＝运营角色、状态＝正常、最近登录时间）；组合筛选角色＝运营角色＋状态＝停用时结果为空，界面显示空态"暂无符合条件的账号" |
| R3：管理者停用账号后该账号登录与操作即时失效，启用后可重新登录，处置动作留痕可查 | 通过 | 模拟界面：停用二次确认弹窗展示 op001 及所持角色，确认后状态转"停用"；模拟接口：被停用会话随即调用任一功能接口返回"账号已停用"并跳登录页；模拟日志 `AUTH-OP action=account:disable operator=管理员甲 target=op001 at=2026-09-20`；启用后 op001 可重新登录 |
| R4：管理者新建角色并配置能力点后保存成功，被账号引用的角色不可删除 | 通过 | 模拟界面：新建"运营角色"（勾选能力点 auth:account:none 预留位外的本版权限能力点）保存成功，列表可见；删除被 op001 引用的"运营角色"时拦截提示"该角色已被 1 个账号使用，不可删除"；新建未引用的测试角色可删除成功 |
| R5：管理者调整角色能力点或账号所持角色后，对应账号的管理端菜单与操作面即时按新权限刷新，变更留痕 | 通过 | 模拟操作：给"运营角色"增删能力点保存后，另一浏览器会话（op001 在线、未重登）刷新页面即见菜单变化；模拟日志 `AUTH-OP action=role:grant operator=管理员甲 target=运营角色 delta=[+auth:role:read]`；编辑 op001 角色为[运营角色,客服角色]后其操作面按并集刷新 |
| R6：内部人员以账号凭据登录后获得与所持角色匹配的管理端界面，登出后访问受保护页面需重新登录 | 通过 | 模拟界面：登录成功进入管理端，菜单仅含所持角色能力点对应项；登出后直接访问账号管理地址被跳转登录页；异常态实测——错误凭据提示"账号名或凭据不正确"（连续 5 次后第 6 次即使凭据正确也提示"账号已锁定，请稍后再试"），停用账号登录提示"账号已停用" |
| R7：任意内部角色登录后可自行修改显示名与登录凭据，操作不涉及自身角色变更 | 通过 | 模拟界面：个人设置页仅"显示名"与"凭据重置"两个分区，无任何角色相关控件；修改显示名保存后右上角即时更新；旧凭据输错时拦截"旧凭据不正确"，正确重置后提示"凭据已重置"且当前会话保持登录 |

自检结论：7/7 通过，无修复遗留。

## 3. 运行方式

（模拟口径）按技术文档部署形态：单机 Docker Compose 编排（管理端静态资源、后端单体服务、MySQL、Nginx）；构建时选各技术当前稳定版；初始化执行 auth_ 三表迁移脚本并创建首个管理者账号（引导流程：首个账号经初始化脚本建立并强制首次登录重置）。日常运行经 Nginx 80/443 访问管理端。**范本演练说明：以上为运行方式口径描述，本版无真实可执行产物。**
