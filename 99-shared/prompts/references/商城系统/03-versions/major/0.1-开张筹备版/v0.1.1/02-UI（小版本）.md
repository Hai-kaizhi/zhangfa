# 好物商城 v0.1.1 · UI 生图脚本（小版本）

> 本文档是 v0.1.1 的 UI 生图脚本：生图提示词由 GPT 分析资料后自己撰写，本文只给资料清单与话术；风格锚定（色板、令牌、组件形态、通用禁止）整段沿用项目层脚本《UI（项目）》附 A——风格唯一来源在项目层，本版不新增任何色值；覆盖只圈本版认领条目（R8~R14）触及的界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质予以保留。

新建一个 GPT 对话，一次性粘贴"必给"资料，然后按第 1 步开始。

## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

> 我在为「好物商城」管理端 v0.1.1（商品货架版）生成 UI 设计图。请先通读我提供的资料，然后**只做一件事：撰写第一张图——管理端「商品建档与编辑」页（PC 横屏 16:9，左侧导航＋商品编辑表单）的生图提示词。先只输出提示词，不要生成图片。**
>
> 撰写提示词时必须遵循以下风格锚定（逐字沿用项目层脚本，不得偏离、不得新增色值）：
> - **色板（精确 hex，唯一来源为项目层附 A）**：主色 `#DA3A2B`（主按钮、选中态）；成功 `#2FA65A`、警告 `#E8A33D`、危险 `#D85555`（状态标签与危险操作）；文字主 `#1F2329`、次级 `#4E5969`、辅助 `#86909C`；边框 `#C9CDD4`、页面底 `#F2F3F5`、卡片 `#FFFFFF`。白底为主、主色点缀，克制清爽。
> - **字体与组件形态**：系统默认无衬线中文字体；卡片式布局、圆角 8px、轻投影；管理端为 PC 布局（左侧导航＋内容区）。
> - **通用禁止（整段继承项目层）**：界面文字全部为简体中文；不得出现"平台、商家入驻、多商户、分账"等字样或概念；不得出现英文界面文案、第三方品牌标识、支付渠道以外的金融元素。
> - **本版附加禁止**：不得出现订单、购物车、交易、会员、优惠券、秒杀等字样或概念（归后续版本）；不得出现移动端界面；左侧导航仅呈现商品管理相关菜单（分类管理、品牌管理、商品列表）。
> - **商品建档与编辑页必须元素**：商品名称输入（必填标记）、商品分类下拉（叶子分类）、品牌下拉（可选）、规格（SKU）行编辑区（每行＝规格名＋售价，可增删行）、商品图集上传区（九宫格占位＋上传按钮＋封面标记）、详情图文编辑区、底部"保存草稿"主按钮与"上架"次按钮；状态标签显示"草稿"。
> - **称谓纪律**：界面用语严格按术语表与 PRD 原文（如"商品""规格（SKU）""草稿""已上架""已下架""商品分类""品牌""图片资源"不得同义改写）。
>
> 提示词结构要求：先一段总述（风格与布局意图），再分区块描述（从左到右、从上到下），最后列色彩与文字约束。输出后停下等我确认。

## 2. 第二步：生成并迭代核心界面

确认后发送：

> 请用这张商品建档与编辑页提示词生成图片（PC 横屏）。

迭代方法（验收三问）：信息点是否齐全（表单分区、SKU 行、图集、双按钮、状态标签）？风格是否与项目层附 A 一致（白底、主色点缀、圆角卡片）？界面用语是否与 PRD 逐字一致？满意后**与项目层脚本已生成的主页基准图并检一次**（防跨版本风格漂移），并检通过即为本版基准。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 商品建档与编辑页基准已定。请基于资料规划 v0.1.1 其余 UI 图片，**先输出完整清单（说明总数与每张的作用），经我确认后再逐张输出提示词**。覆盖要求（只圈本版认领条目 R8~R14，含异常态与空态）：
>
> - **商品列表页**：筛选区（名称模糊、分类、品牌、状态）＋表格（名称、分类、品牌、状态标签〔草稿＝辅助色、已上架＝成功色、已下架＝危险色〕、规格数、上架/下架操作）＋分页；**必须画出空态**（"暂无商品，点击新建商品创建第一个商品"）与筛选无结果态（"暂无符合条件的商品"）。
> - **商品建档校验失败态**：**必须画出**行内校验反馈（"商品名称需为 2~50 字符"/"请至少添加一个规格"/"售价需为正整数（单位分）"）。
> - **上架完备性拦截弹窗**：**必须画出**缺口清单反馈（如"缺少库存台账"）与重复操作提示（"商品已是上架状态"）。
> - **分类管理页**：分类树（父子层级、排序）＋新增/编辑表单（分类名、父分类、排序）；**必须画出**删除被引用分类拦截（"该分类已被 N 个商品使用，不可删除"）与父分类成环拦截（"不能选择自身或后代作为父分类"）。
> - **品牌管理页**：列表（品牌名、介绍、品牌图）＋新增/编辑表单；**必须画出**删除被引用品牌拦截（"该品牌已被 N 个商品使用，不可删除"）。
> - **库存分区**（商品档案内）：按 SKU 行展示可售数量、调整入口；**必须画出**非负整数拦截反馈（"库存数量需为非负整数"）与留痕记录列表（调整前后/操作者/时间/原因）。
> - **图片上传反馈态**：**必须画出**格式拦截（"仅支持 JPG/PNG/WebP 格式"）、大小拦截（"单张不超过 5MB"）、图集超上限（"每个商品最多关联 9 张图片"）。
> - **空态必须画出**：无分类（"暂无分类，请新建第一个分类"）、无品牌（"暂无品牌，请新建第一个品牌"）、无规格时库存分区空态（"请先在档案中添加规格（SKU）"）。
> - **机制条目声明**：库存的锁定/扣减/回补为交易协作机制（随 0.2/0.4），无界面、不生成图；图片 biz_type 关联机制随表单内嵌，无独立界面；除上述外不得出现本版范围外界面（无订单、无营销、无移动端）。
>
> 风格、色板、组件形态、通用禁止与本版附加禁止一律沿用第一张图基准与项目层附 A；界面用语逐字沿用术语表与 PRD。

## 4. 第四步：批量生成

清单确认后发送：

> 按清单顺序逐张生成图片，每张生成后停顿，等我记录后再继续下一张。

单张迭代方法同第 2 步；如出现风格漂移，回引商品建档与编辑页基准图校正后重生成该张。

## 5. 收尾：回填归档

全部图片满意后回填附 B（图／界面与端／主要偏差／色彩微调记录）。**色彩如需微调，必须先改项目层脚本附 A（唯一来源）再同步本版话术**，本版不自行定新色值。

## 附注 其他生图模型的差异

使用即梦等无对话记忆的生图模型时：把第 1 步话术连同资料摘要、风格锚定全文一并前置；每张图生成时重复附上风格锚定与该图提示词；迭代以新对话＋完整提示词进行，回填流程相同。
