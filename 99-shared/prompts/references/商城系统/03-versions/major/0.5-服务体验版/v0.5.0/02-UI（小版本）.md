# 好物商城 v0.5.0 · UI 生图脚本（小版本）

> 本文档是 v0.5.0 评价帮助版的 UI 生图脚本：生图提示词由 GPT 在对话中分析资料后自己撰写，本文档只提供资料清单与分步话术；风格锚定整段沿用项目层脚本（唯一来源在 `01-project-docs/04B-ui/04B-UI（项目）.md` 附 A），本版不出现任何新色值；覆盖只圈本版认领条目（R46~R50）触及的界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质予以保留。

## 0. 准备：给 GPT 哪些资料

| 资料 | 位置 | 必给或可选 |
|---|---|---|
| PRD（小版本）v0.5.0 | `04-workspace/v0.5.0/01-PRD（小版本）.md` | 必给（界面与信息点唯一来源） |
| UI（项目）脚本 | `01-project-docs/04B-ui/04B-UI（项目）.md` | 必给（风格锚定唯一来源） |

新建一个 GPT 对话，一次性把「必给」资料粘贴给 GPT，然后按第 1 步开始。

## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

> 我要为「好物商城」v0.5.0 评价帮助版生成 UI 设计图。请先通读我提供的全部资料，然后**只做一件事：撰写第一张图——商城端（手机竖屏 9:19.5）「写评价」页的生图提示词。先只输出提示词，不要生成图片。**
>
> 撰写提示词时必须遵循以下风格锚定（不得偏离，与项目层脚本一致）：
> - **色板（精确 hex，为本项目品牌色唯一来源）**：主色 `#DA3A2B`（暖正红，用于主行动按钮、选中星标、强调）；营销强调色 `#FF6A00`（仅用于秒杀/促销标签，本版界面不使用）；成功 `#2FA65A`、警告 `#E8A33D`、危险 `#D85555`；中性色阶：文字主 `#1F2329`、次级 `#4E5969`、辅助 `#86909C`、分隔 `#C9CDD4`、页面底 `#F2F3F5`、卡片 `#FFFFFF`。整体白底为主、主色点缀，克制清爽。
> - **字体与组件形态**：系统默认无衬线中文字体；卡片式布局、圆角 8px、轻投影；二级页面顶部返回导航＋页面标题。
> - **通用禁止**：界面文字全部为简体中文；不得出现"平台、商家入驻、多商户、分账"等字样或概念（本产品为单一卖方自营）；不得出现英文界面文案、第三方品牌标识、支付渠道以外的金融元素；人像与插画仅作占位不出现真实品牌。
> - **核心界面必须元素（逐条画出）**：页面标题「写评价」；商品摘要卡（商品缩略图占位、名称、规格快照）；「评分」区块——1~5 星星标（选中的星用主色，未选灰阶）；「评价内容」多行文本输入区（提示语「请填写 10~500 字评价内容」）；「添加图片」区块——九宫格上传位（虚线添加格＋角标「最多 3 张」）；底部主行动按钮「发布评价」（主色）；辅助说明行「评价提交后公开展示」。
> - **称谓纪律**：C 端登录后使用者界面称"会员"；状态名严格按我提供的术语表中文原文。
> - **本版附加禁止**：不得出现咨询入口与工单、个人资料与注销、会员等级等元素（随 v0.5.1／0.6）；不得出现评价审核中的状态字样（本版提交后直接公开展示）。
>
> 提示词结构要求：先一段总述（风格与布局意图），再分区块描述（从上到下），最后列出色彩与文字约束。输出后停下来等我确认。

## 2. 第二步：生成并迭代核心界面

确认提示词无误后，发送：

> 请用这张「写评价」提示词生成图片（竖屏手机端）。

迭代方法（验收三问）：①信息点是否全——商品摘要、星级、内容输入、图片上传、发布按钮逐条在图上；②风格是否同源——色板、圆角、卡片形态与项目层主页基准一致；③纪律是否守住——无英文文案、无范围外元素。对不满意的局部直接描述改哪里，让 GPT 修改提示词后重新生成。**满意的那一版即本版基准，并与项目层脚本生成的主页基准并检一次**（防跨版本风格漂移）。色彩如需微调，改项目层脚本附 A 色值表并同步其第一步话术中的 hex，本脚本随之更新。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 本版核心界面（写评价页）风格已定（以上一张满意图为基准）。请基于资料规划本版其余 UI 图片，**先输出完整清单（说明总数与每张的作用），经我确认后再逐张输出提示词**。规划必须满足以下覆盖要求：
>
> - **覆盖范围＝本版认领条目 R46~R50 的操作面；本批全部为操作面条目，无机制条目（不存在"无界面不生成"的条目）**。必须覆盖的界面：
>   - **商城端（手机竖屏 9:19.5）**：
>     1. 订单详情（已完成）——订单项「写评价」入口与「已评价」标记的对照形态。
>     2. 写评价页·校验异常态——未选评分或内容不足时的危险色提示（「请选择 1~5 星评分」／「请填写 10~500 字评价内容」）。
>     3. 商品详情页·评价区——评分分布汇总（各星占比）＋评价列表（评分星、内容、图片缩略、时间，时间倒序）。
>     4. 商品详情页·评价区空态（「暂无评价，买过后快来评价吧」）。
>     5. 帮助中心页——分类导航＋已发布文章列表＋顶部搜索框。
>     6. 帮助中心·检索空态（「暂无相关帮助内容，换个关键词试试」）。
>     7. 帮助文章详情页（标题、所属分类、正文）。
>   - **管理端（PC 横屏 16:9，左侧导航＋内容区布局）**：
>     8. 帮助文章列表（标题、分类、发布状态、更新时间；新建按钮）。
>     9. 帮助文章编辑页（标题、分类选择、正文、发布开关／保存草稿按钮）。
>     10. 文章分类管理页（分类树、排序、下属文章数；删除被引用分类的拦截提示「该分类下有文章，请先转移后再删除」）。
>     11. 评价管理页（按商品／订单筛选＋评价列表含已隐藏标记）。
>     12. 评价隐藏二次确认弹层（「隐藏后买家不可见，操作留痕」＋确认／取消按钮）。
>     13. 按角色授权对照态——运营人员视角左侧导航可见「帮助中心」「评价管理」，客服视角不可见（体现按角色仅见授权菜单）。
> - **信息点逐条转译**：星标选中态用主色、异常提示用危险色、发布状态用成功／辅助色、已隐藏标记用辅助色；各拦截与校验提示文案、空态文案都要体现在对应图中；生图文字是幻觉，界面文案以上述 PRD 锚定为准。
> - **本版附加禁止**：商城端图不得出现管理端元素；不得出现咨询工单、常见问题引导、个人资料与注销、会员等级等随 v0.5.1／0.6 交付的元素；不得出现「审核中」等本版不存在的状态字样。
> - 通用禁止与称谓纪律同第一张图。风格、色板、组件形态一律向已定基准看齐。
>
> 清单确认后再逐张输出提示词，每张输出后停下等我确认。

## 4. 第四步：批量生成

清单确认后，发送：

> 按清单顺序逐张生成图片，每张生成后停顿，等我记录后再继续下一张。

单张迭代方法：同第 2 步，逐张局部修正；整批完成后如出现风格漂移，回引本版基准图（写评价页）让 GPT 校正后重生成该张。

## 5. 收尾：回填归档

全部图片满意后，把每张图的信息回填到本文档附 B（图／界面与端／主要偏差／色彩微调记录）；如做了色彩微调，须同步**项目层脚本附 A**（唯一来源）与本版话术中的 hex，保持「文档色值＝品牌色唯一来源」。本版新增界面的要素不回写项目层脚本（风格变更才回写项目层）。

## 附注 其他生图模型的差异

使用即梦等无对话记忆的生图模型时：把第 1 步话术连同资料摘要、风格锚定全文一并放入提示词前置段落；每次生成单张图时重复附上风格锚定与该图提示词；迭代以「新对话＋完整提示词」方式进行，回填流程相同。
