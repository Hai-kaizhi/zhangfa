# 交付说明：v0.5.0

> 定位：v0.5.0 评价帮助版的开发交付说明——承接本版 PRD 认领条目（R46 ◆ 评价创建、R47 评价查询与管理、R48 帮助文章增删改查、R49 文章分类维护、R50 帮助中心检索查阅），按「代码已按 PRD 实现」口径编写；本项目为模拟示范案例（文档范本演练），无真实代码产物，证据为模拟口径。

## 1. 实现清单（条目｜代码位置｜实现要点）

| 条目 | 代码位置 | 实现要点 |
|---|---|---|
| R46 ◆ 评价创建 | 服务端·商品模块分包（评价服务）＋商城端·订单详情与写评价页 | 新表 `prod_review`：`order_item_id`（唯一约束，一次成交一条）、`score`（1~5）、`content`、`is_hidden`，落库字段与术语表 v0.5.0 登记行逐字一致；三层防重（入口／提交校验／唯一约束）；评价图片经 `sys_image_asset`（`biz_type`＝`review`）关联；创建后商品详情页即时呈现 |
| R47 评价查询与管理 | 商城端·商品详情页评价区＋管理端·评价管理页＋服务端·商品模块分包 | 买家侧仅未隐藏评价（时间倒序、每页 20 条、评分分布汇总）；运营侧按商品／订单维度查询（含已隐藏带标记）；隐藏置 `is_hidden` 并留痕、买家侧即时过滤 |
| R48 帮助文章增删改查 | 服务端·内容模块分包（帮助中心）＋管理端·帮助中心管理页 | 新表 `cms_help_article`：`title`、`category_id`、`content`、`published`；草稿／发布／下线标记切换与留痕；仅已发布对买家可见；软删除限未发布或已下线文章 |
| R49 文章分类维护 | 服务端·内容模块分包＋管理端·分类管理页 | 新表 `cms_help_category`：`category_name`、`parent_id`、`sort_order`（全部复用既有名）；分类树维护；被文章引用不可删（软删除语义） |
| R50 帮助中心检索查阅 | 商城端·帮助中心页＋服务端·内容模块分包（检索查询） | 分类导航＋关键词对 `title`／`content` 模糊匹配；仅已发布；空分类不占位；空态提示 |

范围外零实现：咨询工单与常见问题引导、个人中心自助（资料凭据、记录入口聚合、注销）随 v0.5.1；评价先审后显与注销冷静期（暂缓清单）；会员等级（0.6）、统计报表（0.7）。

## 2. 验收锚自检（锚原文｜结果｜证据）

锚原文（逐字引自本版 PRD 第 2 章认领条目表）：

| # | 锚原文 | 结果 | 证据（模拟口径） |
|---|---|---|---|
| 1 | R46：「买家对本人已完成订单的订单项提交评价（评分与内容）后创建成功并在商品详情页公开展示，同一订单项至多一条评价」 | 通过 | 界面叙述：会员在已完成订单详情对订单项（保温杯·白色 500ml）点「写评价」，选 4 星、填内容、传 1 张图，提交提示「评价发布成功」，订单项入口转「已评价」，商品详情页评价区即时出现该条（4 星、内容、图片、时间）。接口叙述：`POST /api/product/reviews`（body：orderItemId、score=4、content、imageIds）→ 201 返回 reviewId。数据叙述（模拟）：prod_review 落行（order_item_id 唯一）。日志行（模拟）：`ReviewCreate ok reviewId=9001 orderItem=... score=4`。防重验证：同订单项再次提交返回「该商品已评价」，并发双提交仅一条落库（唯一约束日志：`dup review insert rejected order_item_id=...`）。 |
| 2 | R47：「买家可在商品详情页查看该商品的评价列表；运营人员按商品／订单维度查询评价，违规评价可隐藏并留痕，隐藏后商城端不可见」 | 通过 | 界面叙述：商品详情页评价区显示评分分布（5 星 60%／4 星 30%…）与列表（时间倒序）；管理端评价管理按商品「保温杯」筛选出 6 条，对一条违规评价点「隐藏」→二次确认→标记「已隐藏」；刷新商品详情页该条不再出现。接口叙述：`POST /api/product/reviews/{id}/hide` → 200。日志行（模拟）：`ReviewHide ok reviewId=9003 operator=opt#3 trace=留痕`。 |
| 3 | R48：「运营人员可新建、编辑、发布与下线帮助文章，仅已发布文章对买家可见」 | 通过 | 界面叙述：运营新建《如何申请退货》挂分类「售后」，保存草稿→列表状态「草稿」→发布→买家帮助中心可见；下线后买家侧即时不显现、列表状态「已下线」。接口叙述：`POST /api/cms/help-articles`→201、`PUT …/{id}/publish`→200、`PUT …/{id}/unpublish`→200。日志行（模拟）：`HelpArticle publish ok id=101 by=opt#3`。删除拦截验证：对已发布文章点删除提示「请先下线再删除」。 |
| 4 | R49：「运营人员可维护帮助分类树，被文章引用的分类不可删除」 | 通过 | 界面叙述：分类管理页新增「配送说明」于「购物指南」之下、调整排序即时保存；对被 1 篇文章引用的「售后」分类点删除，提示「该分类下有文章，请先转移后再删除」；删除无引用的「旧分类」成功（软删除留痕）。日志行（模拟）：`HelpCategory soft-delete ok id=9 trace=留痕`、`HelpCategory delete rejected id=2 reason=被文章引用`。 |
| 5 | R50：「买家按分类或关键词检索并查阅已发布帮助文章」 | 通过 | 界面叙述：帮助中心按分类「售后」浏览到已发布《如何申请退货》；关键词「退货」命中标题与正文含该词的已发布文章列表；点击进入详情（标题、分类、正文）。接口叙述：`GET /api/cms/help-center?keyword=退货` → 200（3 条，草稿与已下线不出现）。空态验证：关键词「发票」无命中显示「暂无相关帮助内容，换个关键词试试」。 |

## 3. 运行方式

按「代码已按 PRD 实现」口径（模拟）：服务端随商品／内容模块分包部署（单服务形态）；商城端（移动 Web）以会员身份走「我的订单→已完成订单→写评价」「帮助中心检索查阅」；管理端（PC Web）以运营人员身份走「帮助中心管理」「评价管理」。验收用数据＝一笔本人已完成订单（含可上传图片）、若干已发布帮助文章与分类。本演练未产出可运行包，操作路径以本版 PRD 第 4 章各条目交互与流程为准。

## 4. 已知限制与待确认

- 本版为文档范本演练，无真实代码与运行产物，全部证据为模拟口径（见引言）。
- 评价隐藏为单向操作（恢复待业务确认，不影响验收锚——锚仅要求可隐藏且不可见）。
- 帮助文章正文为纯文本段落（富文本能力边界留版本级，04C-内容）。
- 常见问题引导对帮助中心高频问题的取数展示随 v0.5.1 咨询入口交付，本版仅提供检索查阅。
- 无待确认歧义项：实现过程未发现 PRD 缺口或歧义。
