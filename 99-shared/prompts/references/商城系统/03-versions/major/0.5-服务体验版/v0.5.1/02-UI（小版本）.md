# 好物商城 v0.5.1 · UI 生图脚本（小版本）

> 本文档是 v0.5.1 咨询自助版的 UI 生图脚本：生图提示词由 GPT 在对话中分析资料后自己撰写，本文档只提供资料清单与分步话术；风格锚定整段沿用项目层脚本（唯一来源在 `01-project-docs/04B-ui/04B-UI（项目）.md` 附 A），本版不出现任何新色值；覆盖只圈本版认领条目（R51~R58 操作面；工单完结判定自动任务为机制部分无界面）触及的界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质予以保留。

新建一个 GPT 对话，一次性把「必给」资料粘贴给 GPT，然后按第 1 步开始。

## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

> 我要为「好物商城」v0.5.1 咨询自助版生成 UI 设计图。请先通读我提供的全部资料，然后**只做一件事：撰写第一张图——管理端（PC 横屏 16:9，左侧导航＋内容区布局）「工单处理」页的生图提示词。先只输出提示词，不要生成图片。**
>
> 撰写提示词时必须遵循以下风格锚定（不得偏离，与项目层脚本一致）：
> - **色板（精确 hex，为本项目品牌色唯一来源）**：主色 `#DA3A2B`（暖正红，用于主行动按钮、强调、选中态）；营销强调色 `#FF6A00`（仅用于秒杀/促销标签，本版界面不使用）；成功 `#2FA65A`、警告 `#E8A33D`、危险 `#D85555`；中性色阶：文字主 `#1F2329`、次级 `#4E5969`、辅助 `#86909C`、分隔 `#C9CDD4`、页面底 `#F2F3F5`、卡片 `#FFFFFF`。整体白底为主、主色点缀，克制清爽。
> - **字体与组件形态**：系统默认无衬线中文字体；卡片式布局、圆角 8px、轻投影；管理端为左侧导航（仅体现客服人员可见的授权菜单）＋右侧内容区。
> - **通用禁止**：界面文字全部为简体中文；不得出现"平台、商家入驻、多商户、分账"等字样或概念（本产品为单一卖方自营）；不得出现英文界面文案、第三方品牌标识、支付渠道以外的金融元素；人像与插画仅作占位不出现真实品牌。
> - **核心界面必须元素（逐条画出）**：左侧导航「咨询处理」高亮；工单头卡——工单号（`TIC` 前缀）、状态标签「处理中」（警告色）、顾客信息行（昵称、手机号）、可选关联订单号（只读跳转样式）；往来答复时间线（买家气泡居左浅底、客服气泡居右主色浅底，各含时间戳）；底部答复输入区（多行文本，提示语「请填写 10~1000 字答复」）＋「提交答复」主色按钮；辅助说明行「买家静默 72 小时后自动完结」。
> - **称谓纪律**：状态名严格按我提供的术语表中文原文（本页仅可出现「处理中」）；内部人员按角色名（客服人员）。
> - **本版附加禁止**：不得出现即时聊天式的会话界面元素（输入区为工单答复表单样式）；不得出现机器人自动答复、内部备注区；不得出现评价、帮助中心管理页、会员等级、统计报表等元素。
>
> 提示词结构要求：先一段总述（风格与布局意图），再分区块描述（从左到右、从上到下），最后列出色彩与文字约束。输出后停下来等我确认。

## 2. 第二步：生成并迭代核心界面

确认提示词无误后，发送：

> 请用这张「工单处理」提示词生成图片（PC 横屏管理端）。

迭代方法（验收三问）：①信息点是否全——工单头、状态标签、往来时间线、答复输入、自动完结说明逐条在图上；②风格是否同源——色板、圆角、卡片形态与项目层主页基准一致；③纪律是否守住——无英文文案、无范围外元素。对不满意的局部直接描述改哪里，让 GPT 修改提示词后重新生成。**满意的那一版即本版基准，并与项目层脚本生成的主页基准并检一次**（防跨版本风格漂移）。色彩如需微调，改项目层脚本附 A 色值表并同步其第一步话术中的 hex，本脚本随之更新。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 本版核心界面（工单处理页）风格已定（以上一张满意图为基准）。请基于资料规划本版其余 UI 图片，**先输出完整清单（说明总数与每张的作用），经我确认后再逐张输出提示词**。规划必须满足以下覆盖要求：
>
> - **覆盖范围＝本版认领条目 R51~R58 的操作面；机制部分声明——R55 的完结判定（静默 72 小时自动完结的定时任务）与 R54 的高频问题取数机制无独立界面、不生成图（前者无人工触发面，后者呈现在引导页内）**。必须覆盖的界面：
>   - **商城端（手机竖屏 9:19.5）**：
>     1. 咨询入口·高频问题引导页（高频问题列表＋「没有解决？创建工单」按钮＋「查看全部帮助」入口）。
>     2. 创建工单页（咨询内容多行输入＋可选关联本人订单选择器＋提交按钮）。
>     3. 创建工单·字数校验异常态（危险色提示「请填写 10~500 字咨询内容」）。
>     4. 我的咨询列表（工单号＋状态标签＋内容摘要＋时间，倒序；含「待响应」标签形态）。
>     5. 我的咨询·空态（「暂无咨询记录，遇到问题点上方入口发起咨询」）。
>     6. 工单详情·买家侧（往来答复时间线＋追问输入框；「已完结」状态标签＋追问重开提示）。
>     7. 个人中心聚合页（订单与售后记录、优惠券持有、我的咨询三入口，我的咨询带未读红点；既有个人资料、收货地址、账号与安全入口）。
>     8. 个人资料编辑页（头像上传、昵称输入、保存按钮；昵称校验提示态「昵称 2~20 字」）。
>     9. 换绑手机号流程页（原手机号短信验证→新手机号短信验证两步；验证码错误提示「验证码错误或已过期，请重新获取」）。
>     10. 注销申请页（风险提示列表＋「确认注销」危险色按钮＋二次确认弹层）。
>     11. 注销被阻止态（提示「请先处理完结进行中的订单与售后」＋订单与售后去向入口）。
>   - **管理端（PC 横屏 16:9，左侧导航＋内容区布局）**：
>     12. 咨询处理·检索列表（状态／顾客／关联单号筛选＋工单列表＋「待响应」置顶标识）。
>     13. 检索空态（「暂无符合条件的工单」）。
>     14. 工单处理页·待响应首答态（状态标签「待响应」、往来区仅买家咨询内容、答复输入区）。
>     15. 按角色授权对照态——客服人员视角左侧导航可见「咨询处理」，运营人员视角不可见（体现按角色仅见授权菜单）。
> - **信息点逐条转译**：状态标签颜色语义（待响应＝警告色、处理中＝警告色、已完结＝成功色）；答复与追问的气泡方向区分买家与客服；各拦截与校验提示文案、空态文案都要体现在对应图中；生图文字是幻觉，界面文案以上述 PRD 锚定为准。
> - **本版附加禁止**：商城端图不得出现管理端元素；不得出现评价相关界面与帮助中心管理页（v0.5.0 已交付不重复）；不得出现会员等级、统计报表、注销冷静期等本版外概念；工单状态字样严格限「待响应、处理中、已完结」。
> - 通用禁止与称谓纪律同第一张图。风格、色板、组件形态一律向已定基准看齐。
>
> 清单确认后再逐张输出提示词，每张输出后停下等我确认。

## 4. 第四步：批量生成

清单确认后，发送：

> 按清单顺序逐张生成图片，每张生成后停顿，等我记录后再继续下一张。

单张迭代方法：同第 2 步，逐张局部修正；整批完成后如出现风格漂移，回引本版基准图（工单处理页）让 GPT 校正后重生成该张。

## 5. 收尾：回填归档

全部图片满意后，把每张图的信息回填到本文档附 B（图／界面与端／主要偏差／色彩微调记录）；如做了色彩微调，须同步**项目层脚本附 A**（唯一来源）与本版话术中的 hex，保持「文档色值＝品牌色唯一来源」。本版新增界面的要素不回写项目层脚本（风格变更才回写项目层）。

## 附注 其他生图模型的差异

使用即梦等无对话记忆的生图模型时：把第 1 步话术连同资料摘要、风格锚定全文一并放入提示词前置段落；每次生成单张图时重复附上风格锚定与该图提示词；迭代以「新对话＋完整提示词」方式进行，回填流程相同。
