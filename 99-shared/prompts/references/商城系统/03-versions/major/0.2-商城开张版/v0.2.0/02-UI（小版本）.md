# 好物商城 v0.2.0 · UI 生图脚本（小版本）

> 本文档是 v0.2.0 的 UI 生图脚本：生图提示词由 GPT 分析资料后自己撰写，本文只给资料清单与话术；风格锚定（色板、令牌、组件形态、通用禁止）整段沿用项目层脚本《UI（项目）》附 A——风格唯一来源在项目层，本版不新增任何色值；覆盖只圈本版认领条目（R15~R20）触及的界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质予以保留。

## 0. 准备：给 GPT 哪些资料

| 资料 | 位置 | 必给或可选 |
|---|---|---|
| PRD（小版本） | `04-workspace/v0.2.0/01-PRD（小版本）.md` | 必给（界面与信息点唯一来源） |
| UI（项目）脚本 | `01-project-docs/04B-ui/04B-UI（项目）.md` | 必给（风格锚定与令牌映射唯一来源） |

新建一个 GPT 对话，一次性粘贴"必给"资料，然后按第 1 步开始。

## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

> 我在为「好物商城」v0.2.0（商城地基版）生成 UI 设计图，本版首次出现商城端移动界面。请先通读我提供的资料，然后**只做一件事：撰写第一张图——商城端「首页」（移动端竖屏 9:19.5）的生图提示词。先只输出提示词，不要生成图片。**
>
> 撰写提示词时必须遵循以下风格锚定（逐字沿用项目层脚本，不得偏离、不得新增色值）：
> - **色板（精确 hex，唯一来源为项目层附 A）**：主色 `#DA3A2B`（主行动按钮、价格强调、选中态）；营销强调色 `#FF6A00`（仅用于秒杀/促销标签——本版无促销，不出现）；成功 `#2FA65A`、警告 `#E8A33D`、危险 `#D85555`；文字主 `#1F2329`、次级 `#4E5969`、辅助 `#86909C`；边框 `#C9CDD4`、页面底 `#F2F3F5`、卡片 `#FFFFFF`。整体白底为主、主色点缀，克制清爽。
> - **字体与组件形态**：系统默认无衬线中文字体；卡片式布局、圆角 8px、轻投影；商城端为移动端布局（底部标签栏导航：本版仅「首页」「分类」两个标签）。
> - **通用禁止（整段继承项目层）**：界面文字全部为简体中文；不得出现"平台、商家入驻、多商户、分账"等字样或概念；不得出现英文界面文案、第三方品牌标识、支付渠道以外的金融元素。
> - **本版附加禁止**：不出现购物车、下单、支付、订单、优惠券、秒杀等入口或字样（随 0.2.1/0.3）；不出现会员中心、评价、咨询入口（随后续版本）；不出现 PC 管理端界面（首图）。
> - **首页必须元素**：顶部搜索框、内容位呈现区（广告横幅〔BANNER〕轮播、推荐位〔RECOMMEND〕商品卡网格、专题入口〔TOPIC〕入口条）、分类快捷入口、商品瀑布流卡片（图、名称、价格〔元两位小数〕）；底部标签栏「首页／分类」。
> - **称谓纪律**：界面用语严格按术语表与 PRD 原文（如"内容位""商品分类""已上架"），价格展示为元。
>
> 提示词结构要求：先一段总述（风格与布局意图），再从上到下分区块描述，最后列色彩与文字约束。输出后停下等我确认。

## 2. 第二步：生成并迭代核心界面

确认后发送：

> 请用这张首页提示词生成图片（移动端竖屏）。

迭代方法（验收三问）：信息点是否齐全（搜索框、三类内容位区、分类入口、瀑布流、底部两标签）？风格是否与项目层附 A 一致？界面用语是否与 PRD 逐字一致？满意后**与项目层脚本已生成的主页基准图并检一次**（本项目层基准即商城端首页——本版为该基准的首个实际版本，并检确认跨版本同源），通过即为本版基准。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 首页基准已定。请基于资料规划 v0.2.0 其余 UI 图片，**先输出完整清单（说明总数与每张的作用），经我确认后再逐张输出提示词**。覆盖要求（只圈本版认领条目 R15~R20，含异常态与空态）：
>
> - **商城端（移动竖屏 9:19.5）**：
>   - 登录页（R15）：手机号输入＋获取验证码按钮（60 秒倒计时态）＋验证码输入；**必须画出异常态**——"请输入正确的手机号"/"验证码不正确"/"验证码已过期，请重新获取"/"今日发送次数已达上限"。
>   - 分类浏览页（R17）：叶子分类列表＋商品列表（仅已上架）；**必须画出空态**"该分类暂无在售商品"。
>   - 搜索结果页（R17）：结果列表；**必须画出空态**"没有找到相关商品，换个关键词试试"。
>   - 商品详情页（R17）：图集、名称、价格（元）、规格选择（仅查看态，无加购按钮）、图文详情；**必须画出**已下架提示态"商品已下架"。
>   - 地址簿列表与编辑表单（R16）：列表含默认标记；表单（联系人/手机号/地区三级选择/详址/设为默认）；**必须画出**空态"暂无收货地址，请新增"、超上限拦截"最多保存 20 条收货地址"、删除二次确认。
>   - 首页失效位隐藏效果（R19）：**必须画出**内容位被下线/商品下架后首页无该位且不留空白的效果（与完整首页对照）。
> - **管理端（PC 横屏 16:9）**：
>   - 内容位列表页（R18）：类型/标题/关联商品/在线标记/档期/排序＋新建按钮；左侧导航仅内容管理。
>   - 内容位编辑表单（R18）：类型三选一、标题、关联商品下拉、素材图上传、档期、排序；**必须画出**上线校验缺口清单拦截（"关联商品未上架"/"素材图未上传"）与行内校验（"标题文案需为 1~20 字符"）。
>   - 内容位空态（R18）："暂无内容位，请新建第一个内容位"。
> - **机制条目声明**：R20 档期自动执行为调度任务，无人工界面、不生成图（其效果体现在内容位列表的在线标记变化）。
> - 除上述外不得出现本版范围外界面（无购物车/订单/支付/营销/会员/咨询）。
>
> 风格、色板、组件形态、通用禁止与本版附加禁止一律沿用第一张图基准与项目层附 A；界面用语逐字沿用术语表与 PRD。

## 4. 第四步：批量生成

清单确认后发送：

> 按清单顺序逐张生成图片，每张生成后停顿，等我记录后再继续下一张。

单张迭代方法同第 2 步；如出现风格漂移，回引首页基准图校正后重生成该张。

## 5. 收尾：回填归档

全部图片满意后回填附 B（图／界面与端／主要偏差／色彩微调记录）。**色彩如需微调，必须先改项目层脚本附 A（唯一来源）再同步本版话术**，本版不自行定新色值。

## 附注 其他生图模型的差异

使用即梦等无对话记忆的生图模型时：把第 1 步话术连同资料摘要、风格锚定全文一并前置；每张图生成时重复附上风格锚定与该图提示词；迭代以新对话＋完整提示词进行，回填流程相同。
