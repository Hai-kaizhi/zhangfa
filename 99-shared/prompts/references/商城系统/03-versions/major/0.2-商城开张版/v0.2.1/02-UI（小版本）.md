# 好物商城 v0.2.1 · UI 生图脚本（小版本）

> 本文档是 v0.2.1 的 UI 生图脚本：生图提示词由 GPT 分析资料后自己撰写，本文只给资料清单与话术；风格锚定（色板、令牌、组件形态、通用禁止）整段沿用项目层脚本《UI（项目）》附 A——风格唯一来源在项目层，本版不新增任何色值；覆盖只圈本版认领条目（R21~R31）触及的界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质予以保留。

新建一个 GPT 对话，一次性粘贴"必给"资料，然后按第 1 步开始。

## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

> 我在为「好物商城」v0.2.1（成交闭环版）生成 UI 设计图。请先通读我提供的资料（含 v0.2.0 的商城端基准），然后**只做一件事：撰写第一张图——商城端「购物车」页（移动端竖屏 9:19.5）的生图提示词。先只输出提示词，不要生成图片。**
>
> 撰写提示词时必须遵循以下风格锚定（逐字沿用项目层脚本，不得偏离、不得新增色值）：
> - **色板（精确 hex，唯一来源为项目层附 A）**：主色 `#DA3A2B`（主行动按钮、价格强调、选中态）；成功 `#2FA65A`、警告 `#E8A33D`、危险 `#D85555`；文字主 `#1F2329`、次级 `#4E5969`、辅助 `#86909C`；边框 `#C9CDD4`、页面底 `#F2F3F5`、卡片 `#FFFFFF`。白底为主、主色点缀，克制清爽。
> - **字体与组件形态**：系统默认无衬线中文字体；卡片式布局、圆角 8px、轻投影；商城端移动端布局，底部标签栏在 v0.2.0 基础上新增「购物车」标签（现为首页／分类／购物车三项）。
> - **通用禁止（整段继承项目层）**：界面文字全部为简体中文；不得出现"平台、商家入驻、多商户、分账"等字样或概念；不得出现英文界面文案、第三方品牌标识、支付渠道以外的金融元素。
> - **本版附加禁止**：不出现优惠券、秒杀、满减等营销元素（随 0.3）；不出现退货退款、售后入口与"售后中"状态字样（随 0.4）；不出现评价、咨询入口（随 0.5）；不出现会员等级权益（随 0.6）。
> - **购物车页必须元素**：条目卡片（商品图、名称、规格名、单价〔元〕、数量步进器、勾选框、移除入口）；失效条目置灰态（含"已失效，不可结算"标记）；底部结算栏（已选件数、合计金额〔元〕、红色结算主按钮）；空购物车空态；顶部标题"购物车"。
> - **称谓与状态纪律**：界面用语严格按术语表与 PRD 原文；订单状态名逐字为"待支付/待发货/已发货/已完成/已取消"（"售后中"不得出现）；价格展示为元两位小数。
>
> 提示词结构要求：先一段总述，再从上到下分区块描述，最后列色彩与文字约束。输出后停下等我确认。

## 2. 第二步：生成并迭代核心界面

确认后发送：

> 请用这张购物车页提示词生成图片（移动端竖屏）。

迭代方法（验收三问）：信息点是否齐全（条目要素、失效置灰、结算栏合计、空态）？风格是否与 v0.2.0 商城端基准一致（同源并检一次）？界面用语是否与 PRD 逐字一致？满意后即为本版基准。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 购物车基准已定。请基于资料规划 v0.2.1 其余 UI 图片，**先输出完整清单（说明总数与每张的作用），经我确认后再逐张输出提示词**。覆盖要求（只圈本版认领条目 R21~R31，含异常态与空态）：
>
> - **商城端（移动竖屏 9:19.5）**：
>   - 商品详情页变化态（R21）：在 v0.2.0 详情页基础上呈现规格选择＋"加入购物车"主按钮与"立即购买"次按钮。
>   - 订单确认页（R22）：默认收货地址自动选中卡（可切换，标注"默认"）、条目清单、金额明细（小计与合计，无优惠项）、"提交订单"主按钮；**必须画出**无地址拦截态"请先添加收货地址"（引导去地址簿）与可售不足失败态"「规格名」可售不足，仅剩 N 件"。
>   - 支付页（R29）：订单金额、渠道收银台占位（不含第三方品牌标识）、支付处理中态；**必须画出**返回后"订单待支付，剩余 XX:XX"倒计时提示。
>   - 我的订单列表页（R24）：状态筛选标签（五态）＋订单卡（订单号、状态标签、金额、条目摘要、按状态操作按钮〔去支付/取消订单/确认收货/再次查看〕）；**必须画出**空态"暂无相关订单"。
>   - 订单详情页（R24/R25/R26）：状态时间线（下单→支付→发货→完成）、条目快照清单、收货信息、物流跟踪区（承运方＋物流单号＋跟踪入口）、按状态主操作；**必须画出**确认收货二次确认弹窗与取消订单二次确认弹窗（含"取消后不可恢复"提示）。
>   - 购物车空态与失效条目（R21）：空态"购物车是空的，去逛逛"；失效条目置灰不可勾选。
> - **管理端（PC 横屏 16:9）**：
>   - 订单管理列表页（R24）：筛选（状态/订单号/顾客）＋表格（订单号、顾客、金额、状态标签、下单时间、操作）；左侧导航仅订单管理；**必须画出**待发货空态"暂无待发货订单"。
>   - 发货登记弹窗（R28）：承运方下拉＋物流单号输入；**必须画出**行内校验"物流单号需为 8~30 位字母数字"。
>   - 订单详情页（管理端）（R24）：条目快照、收货信息、支付信息（支付单号、渠道、状态）。
> - **机制条目声明**：R23 库存变动、R27 订单自动流转、R30 支付回调确认、R31 收入写入为协作与调度机制，无人工界面、不生成图（效果经订单状态与倒计时呈现）。
> - 除上述外不得出现本版范围外界面（无营销、无售后退货、无评价、无报表）。
>
> 风格、色板、组件形态、通用禁止与本版附加禁止一律沿用购物车基准与项目层附 A；界面用语逐字沿用术语表与 PRD。

## 4. 第四步：批量生成

清单确认后发送：

> 按清单顺序逐张生成图片，每张生成后停顿，等我记录后再继续下一张。

单张迭代方法同第 2 步；如出现风格漂移，回引购物车基准图校正后重生成该张。

## 5. 收尾：回填归档

全部图片满意后回填附 B（图／界面与端／主要偏差／色彩微调记录）。**色彩如需微调，必须先改项目层脚本附 A（唯一来源）再同步本版话术**，本版不自行定新色值。

## 附注 其他生图模型的差异

使用即梦等无对话记忆的生图模型时：把第 1 步话术连同资料摘要、风格锚定全文一并前置；每张图生成时重复附上风格锚定与该图提示词；迭代以新对话＋完整提示词进行，回填流程相同。
