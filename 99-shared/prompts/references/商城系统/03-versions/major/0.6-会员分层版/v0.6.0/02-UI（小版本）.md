# 好物商城 v0.6.0 · UI 生图脚本（小版本）

> 本文档是 v0.6.0 等级分层版的 UI 生图脚本：生图提示词由 GPT 在对话中分析资料后自己撰写，本文档只提供资料清单与分步话术；风格锚定整段沿用项目层脚本（唯一来源在 `01-project-docs/04B-ui/04B-UI（项目）.md` 附 A），本版不出现任何新色值；覆盖只圈本版认领条目（R59~R61 操作面；定期与事件触发的增量重算为机制部分无界面）触及的界面；主流程＝GPT 同一对话＋GPT-image。上游为模拟案例材料，模拟性质予以保留。

新建一个 GPT 对话，一次性把「必给」资料粘贴给 GPT，然后按第 1 步开始。

## 1. 第一步话术：让 GPT 产出本版核心界面的生图提示词

> 我要为「好物商城」v0.6.0 等级分层版生成 UI 设计图。请先通读我提供的全部资料，然后**只做一件事：撰写第一张图——管理端（PC 横屏 16:9，左侧导航＋内容区布局）「顾客详情·分层画像」页的生图提示词。先只输出提示词，不要生成图片。**
>
> 撰写提示词时必须遵循以下风格锚定（不得偏离，与项目层脚本一致）：
> - **色板（精确 hex，为本项目品牌色唯一来源）**：主色 `#DA3A2B`（暖正红，用于主行动按钮、等级徽标强调、选中态）；营销强调色 `#FF6A00`（仅用于秒杀/促销标签，本版界面不使用）；成功 `#2FA65A`、警告 `#E8A33D`、危险 `#D85555`；中性色阶：文字主 `#1F2329`、次级 `#4E5969`、辅助 `#86909C`、分隔 `#C9CDD4`、页面底 `#F2F3F5`、卡片 `#FFFFFF`。整体白底为主、主色点缀，克制清爽。
> - **字体与组件形态**：系统默认无衬线中文字体；卡片式布局、圆角 8px、轻投影；管理端为左侧导航（仅体现运营／客服／管理者可见的授权菜单）＋右侧内容区。
> - **通用禁止**：界面文字全部为简体中文；不得出现"平台、商家入驻、多商户、分账"等字样或概念（本产品为单一卖方自营）；不得出现英文界面文案、第三方品牌标识、支付渠道以外的金融元素；人像与插画仅作占位不出现真实品牌。
> - **核心界面必须元素（逐条画出）**：左侧导航「顾客管理」高亮；顾客头卡——昵称、脱敏手机号（138****1234 样式）、账号状态标签「正常」（成功色）、注册时间；等级卡——当前等级徽标「黄金会员」（主色描边徽标样式）、权益说明两行、「距下一等级」进度条（当前累计实付与下一门槛差额文案）；交易沉淀摘要卡——累计实付（元，两位小数）、完成订单数、最近下单时间；页面为只读详情（无编辑按钮）。
> - **称谓纪律**：状态名严格按我提供的术语表中文原文（顾客账号状态仅可出现「正常」；本版不出现「冻结」操作——冻结治理随下一版）；内部人员按角色名。
> - **本版附加禁止**：不得出现冻结／恢复按钮与处置入口（随 v0.6.1）；不得出现会员等级编辑表单（属会员等级管理页）；不得出现积分、任务、签到等成长体系元素；不得出现统计报表与导出。
>
> 提示词结构要求：先一段总述（风格与布局意图），再分区块描述（从左到右、从上到下），最后列出色彩与文字约束。输出后停下来等我确认。

## 2. 第二步：生成并迭代核心界面

确认提示词无误后，发送：

> 请用这张「顾客详情·分层画像」提示词生成图片（PC 横屏管理端）。

迭代方法（验收三问）：①信息点是否全——顾客头卡、等级徽标与进度、权益说明、交易摘要逐条在图上；②风格是否同源——色板、圆角、卡片形态与项目层主页基准一致；③纪律是否守住——无英文文案、无范围外元素。对不满意的局部直接描述改哪里，让 GPT 修改提示词后重新生成。**满意的那一版即本版基准，并与项目层脚本生成的主页基准并检一次**（防跨版本风格漂移）。色彩如需微调，改项目层脚本附 A 色值表并同步其第一步话术中的 hex，本脚本随之更新。

## 3. 第三步话术：规划本版其余图片并逐张撰写提示词

> 本版核心界面（顾客详情·分层画像）风格已定（以上一张满意图为基准）。请基于资料规划本版其余 UI 图片，**先输出完整清单（说明总数与每张的作用），经我确认后再逐张输出提示词**。规划必须满足以下覆盖要求：
>
> - **覆盖范围＝本版认领条目 R59~R61 的操作面；机制部分声明——R60 的定期任务与交易完成事件触发的增量重算无独立界面、不生成图（运营手动「全量重算」入口有界面，呈现在会员等级管理页）**。必须覆盖的界面：
>   - **管理端（PC 横屏 16:9，左侧导航＋内容区布局）**：
>     1. 会员等级管理页——模板列表（等级名、门槛〔元展示〕、权益说明、排序、归属人数）＋「新建等级」「全量重算」按钮。
>     2. 等级新建／编辑页——等级名、门槛金额、权益说明、排序表单＋保存按钮。
>     3. 等级编辑校验异常态——名称重复或门槛非法时的危险色提示（「等级名 2~20 字且不可重复」／「门槛为不小于 0 的整数金额（分），且各等级门槛不可相同」）。
>     4. 等级删除拦截态——被归属引用提示「该等级已有顾客归属，请先调整门槛重算转移后再删除」；默认级保护提示「默认等级不可删除，门槛须保持为 0」。
>     5. 全量重算反馈态——「重算处理中」提示与完成后结果摘要（更新归属人数、留痕条数）。
>     6. 顾客检索列表——手机号／昵称／等级组合筛选＋列表（昵称、脱敏手机号、等级名、状态、注册时间）。
>     7. 顾客检索空态（「暂无符合条件的顾客」）。
>     8. 顾客详情·默认等级态画像（等级徽标「普通会员」、权益说明、距下一等级进度）。
>     9. 按角色授权对照态——运营视角可见「会员等级」「顾客管理」，客服与管理者视角仅见「顾客管理」（只读，无「新建等级」按钮；体现按角色仅见授权菜单）。
>   - **商城端（手机竖屏 9:19.5）**：
>     10. 会员中心·等级与权益卡——当前等级徽标、权益说明、「距下一等级」进度条（买家被动呈现面）。
>     11. 会员中心·默认等级态（「普通会员」徽标与升级引导文案）。
> - **信息点逐条转译**：等级徽标用主色系差异化（普通＝辅助色描边、白银／黄金＝主色描边渐次强调）；门槛与金额展示为人民币元（两位小数）；各拦截与校验提示文案、空态文案都要体现在对应图中；生图文字是幻觉，界面文案以上述 PRD 锚定为准。
> - **本版附加禁止**：管理端图不得出现冻结／恢复处置入口；商城端图不得出现积分、任务、签到、自动发券等元素（权益为呈现型说明）；不得出现「冻结」状态字样（顾客状态仅呈现「正常」）。
> - 通用禁止与称谓纪律同第一张图。风格、色板、组件形态一律向已定基准看齐。
>
> 清单确认后再逐张输出提示词，每张输出后停下等我确认。

## 4. 第四步：批量生成

清单确认后，发送：

> 按清单顺序逐张生成图片，每张生成后停顿，等我记录后再继续下一张。

单张迭代方法：同第 2 步，逐张局部修正；整批完成后如出现风格漂移，回引本版基准图（顾客详情·分层画像）让 GPT 校正后重生成该张。

## 5. 收尾：回填归档

全部图片满意后，把每张图的信息回填到本文档附 B（图／界面与端／主要偏差／色彩微调记录）；如做了色彩微调，须同步**项目层脚本附 A**（唯一来源）与本版话术中的 hex，保持「文档色值＝品牌色唯一来源」。本版新增界面的要素不回写项目层脚本（风格变更才回写项目层）。

## 附注 其他生图模型的差异

使用即梦等无对话记忆的生图模型时：把第 1 步话术连同资料摘要、风格锚定全文一并放入提示词前置段落；每次生成单张图时重复附上风格锚定与该图提示词；迭代以「新对话＋完整提示词」方式进行，回填流程相同。
