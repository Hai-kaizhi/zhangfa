# 原始需求

> 说明：示范项目「商城系统」立项输入，形态参考开源电商项目 mall，按模拟案例处理。

**做什么产品**：一套自营的零售电商系统，分“前台商城＋后台管理”两半：买家在手机上下单买货，我们的团队在网页后台管商品、订单、会员、营销和内容。店和货都是自己的。

**给谁用**
- 买家（C 端）：手机上逛商城的普通人——看推荐、搜索、挑规格、下单、付款、查物流、评价、申请售后。
- 我们的团队（B 端）：运营上架商品、排推荐位、发优惠券、做秒杀；订单与客服接单发货、处理退货与咨询；管理者看报表、管账号权限。各岗位只见自己那一摊。

**解决什么问题**：买家这边，货不好找、下单流程绕、订单和售后没人管；我们这边，商品资料散落各处，订单靠人盯，促销没抓手，经营情况说不清。

**核心场景与业务闭环**：运营维护商品（分类、品牌、规格、库存）上架 → 买家从首页推荐、搜索或分类进详情 → 选规格、加购物车、提交订单、在线支付 → 后台接单发货，买家跟踪物流 → 确认收货、评价；有问题发起退货退款，客服审核处理 → 交易沉淀为会员，运营用优惠券、秒杀、推荐位和会员等级促活复购 → 用统计报表复盘商品、订单与会员情况，反过来指导选品与活动。

**范围与偏好**
- 端：两个端必须有——买家侧手机商城（优先）、内部 PC 网页后台，共用一套数据。
- 商城必备：首页门户与商品推荐、商品搜索、商品展示、购物车、订单流程与支付、会员中心、客户服务与帮助中心。
- 后台必备：商品管理、订单管理（含退货处理）、会员管理、促销管理、运营与内容管理（推荐位、广告、专题）、权限管理、统计报表、基础财务。
- 明确不做：多商家入驻（只做自营、单一卖方）；直播带货与社交裂变；跨境电商与线下门店；财务只记订单收支，不做结算分账。
- 偏好：先把买卖跑通、后台管得住，不求花哨。
