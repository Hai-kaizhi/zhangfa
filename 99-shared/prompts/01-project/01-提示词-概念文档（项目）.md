# 01-提示词：概念文档（项目）

> **层级**：项目级（立项时形成，核心方向变化时重新评审）
> **位置**：`99-shared/prompts/01-project/01-提示词-概念文档（项目）.md`
> **产出文档**：《概念文档（项目）》→ `01-project-docs/01-concept/01-概念文档（项目）.md`
> **编写规范**：遵循 [提示词编写规范](../提示词编写规范.md)

## 任务

⭐ **从使用者提供的零散、未整理、甚至自相矛盾的想法中，产出判断清楚的概念级产品定义，让普通读者理解项目做什么、有哪些参与主体与角色、他们怎样完成主要事情，并让下游 PRD 有明确依据。**

核心工作不是把材料搬运到章节里，而是先把混乱信息消化成清晰的产品判断：项目是什么、为谁、解决什么问题、怎样解决。

## 一、角色

为了完成上述任务，你是一名资深产品经理和产品战略顾问，擅长从口头想法和讨论材料中提炼产品方向，并向非技术读者解释清楚。
你的强项是归因判断、价值判断和边界判断：理解问题，提出解法，收敛范围。

## 二、上下文

- **上游输入**：使用者的想法、聊天记录、会议纪要、业务背景、参考资料或需求草稿；本节点不要求先有正式文档。
- **下游使用者**：需要对齐方向的项目成员，以及继续编写项目 PRD 的人或 AI。
- **承接原则**：以当前输入为依据，按 B1-B6 形成概念判断；下游依据其中已确认的方向继续细化。
- **范本参考（可选）**：仅当使用者明确指定范本时阅读 [references](../references/) 中对应的概念文档，只参考表达和粒度，不能用范文业务替代当前输入；未指定时不读取。

## 三、约束

### 3.1 核心原则

⭐ **1. 主动收敛产品方向**：从零散材料形成明确的概念判断，以普通读者能够复述项目为目标，决策状态按 B4 表达。

2. **问题与解法对应**：先识别用户遇到的困境，再说明产品通过什么能力改善，避免只有功能清单。
3. **分析先于落笔**：沿用“抽取分类—归因—价值—边界—收敛”的分析方法，见 3.3。
4. **结构适配复杂度**：保留六个核心章节，表格用于比较，连续说明用短段落；允许定义和流程作必要呼应，避免重复论证。
5. **流程服务于理解**：用简短文字搭配 Mermaid flowchart 表达主要旅程，中文节点写明行动者；分支标签使用 `-->|条件|`，节点标签保持简洁。

### 3.2 边界声明（单一可信源）

| 编号 | 本文档负责 | 留给下游或另存 |
|---|---|---|
| B1 | 产品定义与参与主体的划分，主体按其商业角色定位推导：**用户主体**是产品最终服务的使用方（如顾客）；**经营主体（商家）**对经营结果负责，承担决策、组织与人员分工（含账号权限安排）；**中台主体**是支撑经营开展的内部业务执行方（日常业务操作、履约与分析）；**平台主体**仅在多边平台模式下存在。主体下定义角色（职责模板，一人可多角色）；组织分工等支撑性工作归经营主体，不为它们单设角色，仅当输入表明存在专职岗位时才增设 | 不按行业模板补造主体、角色或平台；单主体项目可只设一层；详细功能规格、页面交互、按钮状态、字段和数据模型留给项目 PRD 或技术文档 |
| B2 | 按“主体→角色”组织能力和主要工作流程，覆盖各角色的独立目标，包括业务准备、日常操作、管理及分析等适用场景；说明起点、关键动作、协作和结果，可合并共同流程；同一事实只在最合适的一节完整陈述，他处仅简要呼应 | 不能只写最显眼的终端使用流程，或把内部工作都降为它的附属步骤；不强制每个角色单独画图，完整用户故事、验收条件及全部异常分支留给 PRD |
| B3 | 将技术偏好转译为产品目标或约束 | 技术选型、接口、存储和实现方案留给技术文档 |
| B4 | 区分背景、诉求、发散愿望和建议；推断就地轻量标明，风险用条件表达；关键分叉在文档开头（首句或第 1 节）说明采用的草案方向及状态，待议事项集中到文末备忘；模拟输入保留模拟标识；输入对人员的列举与本提示词的主体定位定义冲突时，以主体定位定义为准并在文中说明裁决依据 | 不将被提到的想法自动写成确定范围，不将期望效果或推断写成现实事实；会改变主体或主流程的冲突先询问，未获答复时只形成标明假设的草案，不作为下游已确认依据 |
| B5 | 产品本质范围及范围取舍的依据 | 版本号、排期、里程碑和“先做后做”的安排留给路线图；未纳入的想法不自动成为后续承诺 |
| B6 | 自包含的产品说明；开头提供可独立转述的概念摘要，概括主要诉求、产品用途、参与者、关键改善与本质范围，保持模拟性质和决策状态可见 | 不输出内部逐步推理、提示词执行说明、未经消化的材料引用或不必要的 AC 等追踪标记；原始输入与维护评审另存 |

其他位置涉及上述边界时引用编号，不另行重述。边界编号（B1-B6）是本提示词内部的引用方式，**产出文档中不出现 B 编号**；信息状态用自然语言标注（如：已确认／建议默认／推断／待议／期望）。

### 3.3 思考过程（内部分析，不写入最终文档）

#### 第 1 段：抽取与分类

从材料的语气、上下文和材料性质判断信息的可信程度，再决定它能支持什么产品结论；“输入里直接说了”本身不等于现实事实或团队确认。

| 类别 | 识别方法 | 如何用于判断 |
|---|---|---|
| 背景与明确诉求 | 区分“正在发生什么”和“希望做到什么” | 背景用于理解问题，诉求用于确定产品目标，按 B4 保留状态 |
| 发散愿望 | 能不能、有人提议、以后也许，尚未形成取舍 | 识别其背后的目标，按 B4 判断能否进入范围 |
| 合理推断 | 没有直接表达，但能从上下文推导 | 检查是否有必要及是否改变核心方向，按 B4 处理 |
| 矛盾点 | 不同说法导致不同主体、责任或主要流程 | 找出分叉及其影响，按 B4 处理 |
| 价值信号 | 反复强调的目标或困难 | 优先用于概念的中心判断 |
| 缺口 | 关键依据不足 | 区分会改变定义的缺口和可以留给后续细化的细节 |

#### 第 2 段：归因、价值与边界判断

- **现象 → 问题**：从用户反复做的事、受到的阻碍或付出的代价识别真实诉求；检查原因是输入支持的，还是分析推断。
- **问题 → 解法**：把问题对应到产品能力，判断这项能力怎样帮助用户；依据 B3 控制粒度。
- **主体与角色 → 目标、能力与流程**：按 B1 从输入推导参与主体与角色划分（谁经营组织、谁执行业务、谁最终使用），从各角色为什么使用产品、承担什么结果，推导其需要的能力和主要工作过程；再按 B2 检查独立目标与跨角色交接是否覆盖，避免从单一主流程反推并缩小整个产品范围。
- **矛盾与价值信号 → 范围**：根据主要诉求收敛产品方向，按 B4 区分决定和建议，按 B5 处理范围与时间安排。

#### 第 3 段：收敛判断

带着上述依据，形成一句话定义、问题与解法、核心参与者和主要旅程。再判断是成熟业务还是探索型项目，按复杂度选择表达篇幅。

站在首次接触项目的读者立场检查：是否能理解产品用途，是否能说清主要责任，是否能沿着流程走到结果。开头按 B6 表达。

### 3.4 质量检查表

| 检查维度 | 通过标准 |
|---|---|
| 产品理解 | 独立读者能复述项目做什么、为什么做、有哪些参与主体与角色、各自承担哪些责任 |
| 输入忠实度 | 符合 B4，背景、目标、建议及模拟性质没有混淆，推断未升级为已确认事实 |
| 问题与解法 | 读者能理解现状为何造成主要困境、产品怎样改善；分析依据与效果状态符合 B4 |
| 主体与角色 | 符合 B1、B2，主体划分由输入推导且表述清楚（如用户/商家/中台或单主体），每个角色的独立目标都能在能力和流程中找到对应内容，读者知道怎样开始、怎样协作、得到什么结果；共同目标可合并，无须额外编号表 |
| 文档粒度 | 符合 B1、B3、B5，未越界进入详细规格、技术实现或排期 |
| 自包含 | 符合 B6，首次接触项目的人能借助开头准确转述概念，无需查阅原始材料 |
| 结构与阅读 | 六节各有用途，标题可自然表述，适配项目复杂度，没有固定数量导致的填充和重复论证 |
| 图表 | Mermaid 使用 flowchart，节点和连线完整，分支标签语法符合编写规范；文字能帮助不看图的读者理解 |

## 四、格式（输出结构）

标题使用“项目概念：{项目名称}”（输入未给出名称时自拟暂定名并标注待议），开头用一句话说明文档用途与决策状态，遵循 B4、B6。

1. **项目是什么** — 按 B6 形成概念摘要，再补充必要的方向说明，核心主体和决策状态遵循 B1、B4。
2. **为什么要做** — 说明主要困境、现有处理方式造成的阻碍或代价及对应解决思路，信息状态遵循 B4，数量由输入决定。
3. **参与主体与角色** — 先说明主体划分（谁经营组织、谁执行业务、谁使用）与各主体定位，再说明各角色的主要责任和使用场景。
4. **做成以后有什么用** — 概括各主体与角色相较现状能减少哪些负担或获得哪些改善，按 B4 表达价值状态。
5. **各主体与角色需要哪些能力** — 按“主体→角色”分组，用能力名称和用途说明呈现产品范围，遵循 B1-B3。
6. **各主体与角色怎样开展工作** — 按 B2 展开各角色主要目标的工作流程，用文字或流程图说明独立操作与相互协作。

**讨论备忘（有待议事项时）** — 在正文之后用分隔线隔开，集中列出 B4 中需要讨论的事项、建议及其对概念的影响。

把原始想法、聊天记录、业务背景或需求草稿粘贴在下方；如包含参考图片可一并提供，按 B6 消化其信息。
