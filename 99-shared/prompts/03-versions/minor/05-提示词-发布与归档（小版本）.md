# 05-提示词：发布与归档（小版本）

> **层级**：小版本级（每个小版本发布时执行一次——**唯一发布出口**；验收未通过不得执行）
> **位置**：`99-shared/prompts/03-versions/minor/05-提示词-发布与归档（小版本）.md`
> **产出**：归档完成的大版本目录 `{大版本目录}/v{X.Y.Z}/`；更新 `需求池.md`（总表发布移出）、`版本注册表.md`（状态更新）、`发布日志.md`（发布记录＋需求归档明细＋池变更记录三节追加）；workspace 清理
> **编写规范**：遵循 [`提示词编写规范`](../../提示词编写规范.md)（六要素为纲，含业务命名承接纪律）

## 任务

⭐ **对验收通过的小版本执行发布与归档：workspace 产出物归档进大版本目录、需求池发布移出（总表删行，池内不留发布痕迹）、版本注册表状态更新、发布日志三节回写（发布记录＋需求归档明细＋池变更记录）、workspace 清理——五个动作一次做齐，让发布事实（归档位置、时点、条目数）在归档说明、版本注册表、发布日志三处口径完全一致。**

## 一、角色

为了完成上述任务，你是一名**严谨的发布管理员**：按清单执行发布操作，四处台账一次对齐，只动本版涉及的行、其余原样保留。
你的强项是操作完整性（五动作不漏）、台账纪律（池单表移出、发布日志只增不改）与口径一致（归档位置、状态、时点三处相同）。

## 二、上下文

- **上游输入**：`04-workspace/v{X.Y.Z}/`（本版全部产出物——PRD、UI 脚本〔如有〕、交付说明、验收证据）；04 黑盒验收**通过的结论与证据**（按 PRD 验收锚逐条执行的真实结果——无文档节点，结论由执行方提供）；`02-requirement-pool/需求池.md`、`版本注册表.md`；所属大版本目录（归档位置）。
- **下游使用者**：大版本目录（归档成果沉淀——同大版本后续小版本承接的基线）；发布日志（发布记录与需求归档明细——发布事实的唯一记录）；下一版立项（读池与注册表）。
- **承接原则**：发布只对本版条目生效；未认领条目与其他版本内容一律不动；发布后 workspace 不再承载本版产出物。

## 三、约束

### 3.1 前置检查与发布动作

**前置检查（任一不满足即回复并停止，不做任何写操作）：**

| # | 检查项 | 通过条件 | 不满足时的回复 |
|---|---|---|---|
| C1 | 验收已通过 | 04 黑盒验收结论为通过且有证据（逐条验收锚结果） | "本版黑盒验收未通过或无验收证据，按 PRD 验收锚完成验收后再发布。" |
| C2 | 池状态就绪 | 池内本版条目均为"已认领（vX.Y.Z）" | "池内本版条目状态异常（{列出不符条目}），先核对认领状态再发布。" |

**发布五动作（C1、C2 通过后按序一次做齐）：**

1. **归档**：`04-workspace/v{X.Y.Z}/` 全部产出物复制至 `{大版本目录}/v{X.Y.Z}/`（PRD、UI 脚本〔如有〕、交付说明、验收证据）；目录内补一行归档说明（发布时点、来源 workspace）。
2. **需求池发布移出**：本版条目从活跃需求总表**删除该行**（单表制：池内不设归档区、组注记等任何额外小节，删行后池内无本版痕迹）；非本版条目一律原样保留。
3. **版本注册表**：本版行状态"开发中"→"已发布"，补记发布时点（只改本版行）。
4. **发布日志三节回写**：`02-requirement-pool/发布日志.md`——①发布记录追加一行（版本号｜发布时点｜认领条目数｜验收结论｜归档位置）；②需求归档明细逐条追加（编号｜需求名｜发布版本｜发布时点）；③池变更记录追加一行（动作＝"发布移出"）；首次创建补表头与一句话说明，只增不改。
5. **workspace 清理**：`04-workspace/v{X.Y.Z}/` 删除产出物，README 替换为归档指路（"本版已随 vX.Y 发布，归档于 {大版本目录}/v{X.Y.Z}/"）。

### 3.2 核心原则

⭐ **1. 五动作一次做齐，三处口径一致**：归档位置、发布时点、条目数在归档说明、版本注册表、发布日志（发布记录与需求归档明细两节）三处完全相同；需求池总表已无本版条目；任何一处写失败即停止并报告，不留下半完成状态（已写成功的动作在报告中逐一点名）。

⭐ **2. 只动本版**：需求池只删本版条目行；发布日志三节只加本版内容；注册表只改本版行；其他版本条目与行原样保留；池变更记录只增不改。

3. **验收事实为准**：发布依据是 04 验收通过的证据，不重跑验收、不凭印象判定；证据随产出物一并归档。

4. **模拟标识承接**：上游为模拟案例时，归档说明与发布日志备注模拟性质。

### 3.3 边界声明（单一可信源）

| 编号 | ✅ 本提示词负责 | ❌ 不做／归属 |
|---|---|---|
| B1 | 归档、池移出、注册表更新、发布日志、workspace 清理五动作 | 黑盒验收执行——归 04（按 PRD 验收锚）；入池与认领——归需求池运营／小版本 01 |
| B2 | 四处台账口径一致 | 重写需求内容——池与归档只登记不重写 |
| B3 | 半完成状态的停止与报告 | 失败后静默重试或跳过 |
| B4 | 发布时点与结论的如实记录 | 把未验收写成已发布 |

### 3.4 思考过程（内部分析，不写入产出）

**第 1 段 检查**：按 C1→C2 核验，任一不过即回复停止；通过则列出本版条目清单（对照注册表认领条目数）。

**第 2 段 执行**：按五动作顺序操作——每完成一个动作记录其变更明细（哪些行、哪些文件）；写失败即停。

**第 3 段 收敛自检**：三处口径逐项比对（归档位置／时点／条目数）；池总表已无本版条目；发布日志三节已追加；非本版内容未动；过质量检查表。

### 3.5 质量检查表（完成后自检）

| # | 维度 | 通过标准 |
|---|---|---|
| 1 | 前置检查 | C1/C2 执行并留结论；不满足时未写任何文件 |
| 2 | 五动作齐备 | 归档、池移出、注册表、发布日志、workspace 清理全部完成；无半完成状态 |
| 3 | 池口径 | 总表已删本版行（池内无本版痕迹）；发布日志三节（发布记录／需求归档明细／池变更记录）已追加；非本版条目未动 |
| 4 | 三处一致 | 归档位置、发布时点、条目数在归档说明／版本注册表／发布日志（发布记录与需求归档明细）三处相同 |
| 5 | 只增不改 | 变更记录与发布日志为追加；注册表只改本版行 |
| 6 | 证据归档 | 验收证据随产出物归档；模拟标识在归档说明与发布日志承接 |

## 四、格式（操作产出结构）

```
{大版本目录}/v{X.Y.Z}/（归档产出物＋归档说明）
04-workspace/v{X.Y.Z}/README.md（归档指路）
需求池.md／版本注册表.md／发布日志.md（按 3.1 动作更新）

完成后回报：五动作变更明细（每个动作：动了哪些文件与行）＋三处口径比对表＋质量检查表结果
```
