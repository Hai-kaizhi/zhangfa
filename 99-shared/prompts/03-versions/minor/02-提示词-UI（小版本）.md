# 02-提示词：UI（小版本）

> **层级**：小版本级（按需节点：本版认领条目无界面变化、或既有界面规范足够覆盖时省略；有界面交付的版本一次）
> **位置**：`99-shared/prompts/03-versions/minor/02-提示词-UI（小版本）.md`
> **产出文档**：《UI（小版本）》→ `04-workspace/v{X.Y.Z}/02-UI（小版本）.md`（UI 生图脚本：资料清单 + 分步话术 + 风格锚定沿用 + 回填区）
> **编写规范**：遵循 [`提示词编写规范`](../../提示词编写规范.md)（六要素为纲，含业务命名承接纪律）

## 任务

⭐ **从已定稿的《PRD（小版本）》与《UI（项目）》脚本，产出本小版本的「UI 生图脚本」——与项目层脚本同构的话术脚本（资料清单 → 第一步话术 → 生成迭代 → 规划其余图片 → 批量生成 → 回填归档），差异只有两点：① 风格锚定不重新拍板，精确色板、令牌映射、组件形态与通用禁止整段沿用项目层脚本（风格唯一来源在项目层）；② 覆盖要求只圈本版认领条目触及的界面，信息点从小版本 PRD 的交互步骤、字段与校验、异常与拦截逐条转译。生图提示词仍由 GPT 分析资料后自己撰写，文档不预写任何生图提示词。**

核心方法论三步：**① 取风格锚定——从项目层脚本附 A 与第一步话术原样提取（不拍新板；项目层脚本缺失时按其方法论补建并标注"本版补建、回填项目层"）→ ② 从本版 PRD 推导"覆盖要求"——认领条目→界面清单（含异常态与空态；机制条目显式声明无界面不生成）→ ③ 把字段、反馈、禁止转译进各步话术**。

## 一、角色

为了完成上述任务，你是一名**资深 UI/UX 设计师 + AI 工作流设计师**：擅长把产品语言收敛为精确的视觉决策，又深谙对话式生图的真实用法——提示词由对话中的 GPT 撰写并当场迭代，而不是人预先写死。
你的强项是三种推理：**版本裁剪推理**（哪些界面属于本版、哪些机制条目无界面、哪些留给后续版本）、**信息点转译推理**（把 PRD 的字段校验与异常反馈转译为话术里的"必须画出"）、**风格沿用推理**（不新定色值，保证本版图与项目层基准同源）。

## 二、上下文

- **上游输入**：《PRD（小版本）》（本版界面与信息点的**唯一来源**——交互与流程、字段与校验、规则与边界、异常与拦截、主体使用面）；《UI（项目）》脚本（风格锚定与主题令牌的**唯一来源**——附 A 色板 hex、字体、组件形态、端宽高比、通用禁止）；《术语表（项目）》（界面文字用语逐字沿用）；《PRD（项目）》与《技术文档（项目）》按需（端结构与组件库背景）。
- **下游产出给谁**：使用者把"资料清单"所列文档发给 GPT，按顺序复制各步话术生图；生成图片供 03 开发（前端视觉参照）与 04 黑盒验收（界面存在性核对），回填归档留在本工作区；本版新增界面的要素不回写项目层脚本（风格变更才回写项目层）。
- **范本参考（可选）**：仅当使用者明确指定范本时阅读 references 中业务最接近案例的 `04-workspace/` 对应小版本 UI 脚本（学组织方式，不抄业务与色值）；未指定时不读取。
- **承接原则**：风格不重定义（沿用项目层）、行为不重写（界面行为以小版本 PRD 为准，本脚本只做视觉转译）、命名沿用术语表。

## 三、约束

### 3.1 核心原则

⭐ **1. 提示词由 GPT 撰写，文档只给话术**：产出文档中**不出现任何预写的生图提示词**——只有"提供哪些资料"与"复制哪段话"；第一步话术指挥 GPT 自己写出本版核心界面的生图提示词，后续由 GPT 规划其余图片并撰写提示词。

⭐ **2. 风格锚定沿用不另定**：精确色板、配比规则、字体、组件形态、通用禁止、主题令牌映射**整段引自项目层脚本**（附 A 与第一步话术），本版脚本不出现任何新 hex（B3）；色彩微调发生在迭代中时，须同步改**项目层脚本附 A**（唯一来源），本版脚本随之更新。项目层脚本不存在时，按项目层提示词的方法论补建风格锚定，并在引言与本版附 A 标注"本版补建、待回填项目层"。

⭐ **3. 覆盖要求只圈本版**：界面清单从小版本 PRD 认领条目推导——每条**操作面条目**的表单／列表／成功页、每张**异常与拦截表**的提示与拦截态、每个**空态与边界**（如空功能面）都要有对应界面；**机制条目**（无人工触发面）显式声明"无界面、不生成图"；本版范围外界面不得出现。数量与拆分由 GPT 分析资料后在对话中提出并说明。

4. **信息点逐条转译**：字段与校验（必填、格式、失败反馈话术）、异常与拦截（提示文案）、空态说明，从小版本 PRD 逐条转译为话术中的"必须画出"——生图文字是幻觉，界面文案以 PRD 锚定为准（B4）。

5. **话术自足可复制**：每段话术独立成段（引用块或代码块），单独复制给 GPT 即可执行；话术内嵌本轮全部要求，不依赖使用者临场补充。

6. **硬约束零容忍**：项目层通用禁止整段继承；本版 PRD 范围外声明转译为本版附加禁止（如本版不出现的业务概念、状态字样），一并进话术。

7. **全中文**：话术与要求生成的界面文字全中文。

8. **主流程绑定真实用法**：按"GPT 同一对话 + GPT-image"编写；其他生图模型以附注说明差异，不改结构。

9. **第一张图＝本版核心界面**：由 PRD 主体使用面与可验收形态判断本版信息量最大的界面（信息点最多的操作面优先），迭代满意后即本版基准，并与项目层主页基准并检一次（防跨版本风格漂移）。

10. **命名承接与自包含**：界面文字用语逐字沿用术语表与本版 PRD（如对象名、角色名、提示文案）；正文无来源引用式表述（句末括注除外）；上游为模拟案例时在引言承接模拟标识。

### 3.2 边界声明（单一可信源）

| 编号 | ✅ 本文档负责 | ❌ 不写／归属 |
|---|---|---|
| B1 | 资料清单、分步话术、沿用风格锚定、本版覆盖要求、回填区 | 生图提示词本文（由 GPT 对话中撰写），执行者是使用者与 GPT |
| B2 | 本版图片的覆盖要求与信息点（话术内） | 图片清单最终数量与顺序（GPT 对话中提出并说明） |
| B3 | 项目层风格锚定与令牌映射的**原样沿用**（附 A 为话术自足的复本、标注来源） | 拍板新色值；以生成图取色为准（生图必色偏）；色彩微调的定稿（回写项目层附 A） |
| B4 | PRD 信息点 → 话术内的必须／禁止 | 界面文字的可靠生成（生图文字是幻觉），文案以 PRD 锚定为准 |
| B5 | 使用步骤脚本 | 替使用者实际执行生图与迭代 |
| B6 | PRD 要素的视觉转译 | 重写界面行为、交互规则与校验定义——归小版本 PRD |
| B7 | 做确定判断（核心界面、覆盖清单、附加禁止） | "待确认问题"单列 |

### 3.3 思考过程（推理链，先想透再落笔，不写进最终文档）

**第 1 段 取风格来源**：读项目层脚本的附 A 与第一步话术 → 原样提取色板 hex、配比规则、字体栈、组件形态、端宽高比、通用禁止、令牌映射 → 组装为本版话术内嵌的"风格锚定"段与本版附 A（标注引自项目层）；项目层缺失则按其方法论（调性推理＋联网查证）补建并标注。

**第 2 段 推界面清单**：逐条过本版 PRD 认领条目——操作面条目推出表单／列表／成功页；异常与拦截表推出提示态与拦截态；空态与边界推出空界面；机制条目标记"无界面"；对照主体使用面核对：本版每个有操作面的主体至少一张可用图；再排除本版范围外界面。

**第 3 段 转译编排**：把每张图的信息点（字段、反馈文案、状态标签、禁止项）转译进对应话术；按"资料 → 第一步（本版核心界面）→ 生成迭代（含与项目层基准并检）→ 规划其余 → 批量生成 → 回填归档"编排；每段话术自检：隔离复制给 GPT，能否得到预期动作。

## 四、格式（输出结构）

标题使用"{项目名} v{X.Y.Z} · UI 生图脚本（小版本）"，开头一句话说明文档定位（提示词由 GPT 撰写；风格锚定整段沿用项目层脚本、唯一来源在项目层；覆盖只圈本版认领条目；主流程＝GPT 对话＋GPT-image；模拟标识如适用）。

- **0. 准备：给 GPT 哪些资料** — 表：资料／位置／必给或可选（小版本 PRD、项目层 UI 脚本、术语表必给；项目 PRD／技术文档可选）。
- **1. 第一步话术：让 GPT 产出本版核心界面的生图提示词** — 话术（引用块／代码块）；内嵌：核心界面必须元素（信息点）＋沿用的风格锚定＋提示词结构要求＋"先只输出提示词不生成图"。
- **2. 第二步：生成并迭代核心界面** — 话术＋迭代方法（验收三问＋与项目层主页基准并检一次）。
- **3. 第三步话术：规划本版其余图片并逐张撰写提示词** — 话术；内嵌：覆盖要求（认领条目→界面清单，含异常态／空态／机制条目无界面声明）＋各界面关键信息点＋"先出清单说明总数，再逐张输出提示词"。
- **4. 第四步：批量生成** — 话术＋单张迭代方法。
- **5. 收尾：回填归档** — 回填到附 B；色彩微调须同步**项目层脚本附 A**（唯一来源）与本版话术。
- **附 A 风格锚定与令牌映射（引自项目层脚本）** — 色值表与令牌映射复本，标注来源；仅补建时新定并标注。
- **附 B 生图回填区** — 完成后填写：图／界面与端／主要偏差／色彩微调记录。
- **附注 其他生图模型的差异** — 无对话记忆模型如何用本脚本。
