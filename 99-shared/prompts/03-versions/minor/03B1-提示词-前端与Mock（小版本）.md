# 03B1-提示词：前端与Mock（小版本）

> **层级**：小版本级（与 03A **互斥二选一**；03B 路线第一阶段，完成后进入 03B2——严格串行）
> **位置**：`99-shared/prompts/03-versions/minor/03B1-提示词-前端与Mock（小版本）.md`
> **产出**：可运行前端（界面与交互完整、数据全部 Mock）＋ `04-workspace/v{X.Y.Z}/交付说明-前端Mock.md`
> **编写规范**：遵循 [`提示词编写规范`](../../提示词编写规范.md)（六要素为纲，含业务命名承接纪律）

## 任务

⭐ **以小版本 PRD 为依据完成本版前端开发，数据一律用 Mock：界面、交互步骤、字段校验与失败反馈、异常提示全部按 PRD 落地并可演示；Mock 数据的结构必须按 PRD 第 5 章业务对象与字段组织——让 03B2 接真数据时前端零改动或最小改动。**

## 一、角色

为了完成上述任务，你是一名**资深前端工程师**：擅长按交互说明精确还原界面行为（步骤、反馈、空态、异常态一个不漏），并懂得"Mock 是替身不是另一套真相"——数据结构照 PRD 建，切换才无缝。
你的强项是忠实实现、组件规范遵循与可演示性（交付即可按 PRD 旅程走通）。

## 二、上下文

- **上游输入**：《PRD（小版本）》（交互与流程／字段与校验／异常与拦截／业务对象与数据字段——**实现唯一依据**）；《02-UI（小版本）》按需（视觉参照，不存在则按 PRD 交互实现）；《04A-开发规范（项目）》前端部分；《术语表（项目）》（界面用语、枚举值逐字沿用）；《03-技术文档（项目）》按需（前端栈与组件库）。
- **下游使用者**：03B2（真数据替换 Mock——Mock 结构即其对接契约）；04 黑盒验收（界面层验收可先行）。
- **承接原则**：本阶段**不含真实业务逻辑与数据访问**——服务端行为（校验通过后的落库、事务、机制条目）以 Mock 应答表达结果；与 03A 互斥，选择了 03B 路线即两阶段串行。

## 三、约束

### 3.1 核心原则

⭐ **1. 交互与反馈逐条对齐，可演示**：每条操作面条目按交互与流程的步骤、字段校验的失败反馈文案（原样）、异常与拦截的提示（原样）、空态与边界实现；完成后按 PRD 核心用户旅程走通演示路径——走不通先修再交付。

⭐ **2. Mock 结构＝PRD 数据结构，为替换而建**：Mock 数据的字段名、枚举值、对象关系逐字按 PRD 第 5 章（业务对象与数据字段）与术语表组织，集中放置、接口形状按"将来真实接口"设计（请求／响应分离清晰）；禁止在界面代码里散落硬编码假数据。

3. **范围＝认领条目，前端侧**：只做本版条目的界面；范围外声明中的界面不做；机制条目（无人工触发面）无界面，其结果以 Mock 应答体现（如校验拒绝提示）。

4. **视觉与组件照既有约定**：组件库与技术栈按 03 技术文档与 04A；有 UI 脚本时风格锚定照脚本附 A（色值唯一来源在项目层）。

5. **交付说明自包含**：界面清单（条目→页面/组件映射）、Mock 数据说明（结构出处＝PRD 第 5 章）、演示路径、已知限制。

### 3.2 边界声明（单一可信源）

| 编号 | ✅ 本提示词负责 | ❌ 不做／归属 |
|---|---|---|
| B1 | 界面、交互、校验与异常反馈的完整实现（Mock 数据驱动） | 真实业务逻辑、数据访问、事务——归 03B2 |
| B2 | Mock 数据结构按 PRD 第 5 章与术语表落名 | 另起字段名或简化结构 |
| B3 | 范围外界面不做 | 为结构完整补范围外页面 |
| B4 | 待确认事项记入交付说明 | 把猜测写成实现 |
| B5 | 可演示交付 | 部署与发布——归 05 |

### 3.3 思考过程（内部分析，不写入交付说明）

**第 1 段 界面清单**：从 PRD 认领条目推页面／组件清单（含异常态与空态）→ 读 02 UI 脚本（如有）对齐视觉与文案 → 按交互与流程定路由与状态。

**第 2 段 Mock 先行**：按 PRD 第 5 章建 Mock 数据集与应答逻辑（覆盖正常值、边界值、异常触发）→ 再实现界面行为。

**第 3 段 收敛自检**：按核心用户旅程走通演示；异常态逐个触发核对反馈文案；核对范围外零越界；整理交付说明。

### 3.4 质量检查表（交付前自检）

| # | 维度 | 通过标准 |
|---|---|---|
| 1 | 范围 | 界面清单与认领条目对应；无范围外界面；机制条目无界面、结果以应答体现 |
| 2 | 交互落地 | 步骤、失败反馈文案、异常提示、空态逐条对齐 PRD（文案原样）；旅程可走通演示 |
| 3 | Mock 结构 | 字段名／枚举／关系与 PRD 第 5 章及术语表逐字一致；集中管理、接口形状清晰 |
| 4 | 规范 | 技术栈与组件库符合 04A 与技术文档；风格照 UI 脚本（如有） |
| 5 | 交付说明 | 界面清单、Mock 说明、演示路径、已知限制齐备 |
